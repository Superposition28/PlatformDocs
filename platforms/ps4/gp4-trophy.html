1. Identification & Scope

Every PlayStation 4 application ships a standardized sce_sys/ directory (mirrored into both PKG entries and the mounted PFS uroot/sce_sys/ tree). Two key binary platform formats live inside this directory alongside param.sfo and shell artwork:

  • trophy00.trp (Big-Endian): Directly inherits Sony's PlayStation 3 TRP container format (magic 0xDCA24D00 at offset 0x00, 64-byte big-endian header, 64-byte big-endian file entries). On PS4, TRP files typically use format version 2 or 3 and store encrypted trophy XML schemas (TROPCONF.ESFM, TROP.ESFM, TROP_00.ESFM) alongside plain PNG artwork (ICON0.PNG, TROP000.PNG).
  • playgo-chunk.dat (Little-Endian): Orbis-native binary manifest starting with 70 6C 67 6F ("plgo"). It encodes progressive install chunks, merged chunk extents (mchunks), language masks, and scenario activation lists generated from a .gp4 publishing project (<psproject fmt="gp4">).

2. Binary Layout Tables

trophy00.trp Header (64 bytes / 0x40 at offset 0x00, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be Magic TRP archive signature 0xDCA24D00 (DC A2 4D 00).
0x04 4 u32be Version Archive version (1, 2, or 3; PS4 uses v2/v3).
0x08 8 u64be FileSize Total size of the .trp file in bytes.
0x10 4 u32be EntryCount Number of 64-byte file entries starting at offset 0x40.
0x14 4 u32be EntrySize Byte size of each entry record (0x40 = 64 bytes).
0x18 4 u32be DevFlag 0 = retail package, 1 = development/debug trophy archive.
0x1C 20 u8[20] Sha1Digest SHA-1 checksum of the entire TRP file (computed with this 20-byte field zeroed; present in v2/v3).
0x30 16 u8[16] Padding Zero-filled reserved padding.
trophy00.trp File Entry Record (64 bytes / 0x40 each, Big-Endian, starting at 0x40)
Offset Size Type Field Description
0x00 32 char[32] Name NUL-padded ASCII filename (e.g., TROPCONF.ESFM, TROP.ESFM, ICON0.PNG, TROP000.PNG).
0x20 8 u64be Offset Absolute byte offset to the member payload.
0x28 8 u64be Size Payload size in bytes.
0x30 4 u32be Flags Entry attributes (0 = unencrypted PNG/SFM; non-zero e.g. 0x00000001 / 0x00000003 = encrypted .ESFM).
0x34 12 u8[12] Padding Zero-filled padding.
playgo-chunk.dat Header Core Fields (Little-Endian, at offset 0x00)
Offset Size Type Field Description
0x00 4 u8[4] magic Constant ASCII bytes "plgo" (70 6C 67 6F).
0x04 2 u16le version_major PlayGo binary format major version (commonly 0x0001 or 0x0002).
0x06 2 u16le version_minor PlayGo binary format minor version (0x0000).
0x08 2 u16le image_count Number of package/disc images covered (typically 1).
0x0A 2 u16le chunk_count Total number of defined PlayGo chunks.
0x0C 2 u16le mchunk_count Total number of merged chunk (mchunk) physical extents.
0x0E 2 u16le scenario_count Number of PlayGo installation scenarios.
0x10 4 u32le file_size Total size of playgo-chunk.dat in bytes.
0x14 2 u16le default_scenario_id Default scenario index used when no explicit user choice applies.
0x16 2 u16le attrib PlayGo attribute flags bitmask.
0x18 4 u32le sdk_version Publishing SDK version (packed Orbis SDK version integer).
0x1C 2 u16le disc_count Optical disc count (1 for single-disc/digital packages).
0x1E 2 u16le layer_bmp Disc layer bitmap.
0x20 32 u8[32] reserved Zero-filled reserved bytes (0x20..0x3F).
0x40 48 char[48] content_id 36-character PSN Content ID string plus zero padding (0x40..0x6F).
0x70+ var {u32le, u32le}[] section_descriptors Header offset/size descriptor pairs pointing to chunk_attrs, chunk_mchunks, chunk_labels, mchunk_attrs, scenario_attrs, scenario_chunks, and scenario_labels (exact slot layout depends on version_major).

3. Flags, Enums & Decoding Formulas

PlayGo Scenario Types & Chunk Attributes
Structure Field / Value Meaning
scenario_attr.type 1 (Single-Player / Default) Standard launch scenario specifying initial chunks required before booting.
scenario_attr.type 2 (Multi-Player / Mode-Select) Alternate user-selectable initial scenario (e.g., multiplayer-first install).
chunk_attr.req_locus 2 / 3 Required storage locus (e.g., local HDD/SSD vs. optical/streamable).
trp_entry.Flags 0x00000000 Unencrypted archive member (standard for ICON0.PNG, TROP*.PNG, or v1 .SFM).
trp_entry.Flags 0x00000001 / 0x00000003 Encrypted/signed .ESFM trophy definition XML in PS4 retail TRP archives.

TRP SHA-1 Verification Formula:

// For trophy00.trp Version >= 2:
expected_sha1 = trp_bytes[0x1C : 0x30]
temp = copy(trp_bytes)
temp[0x1C : 0x30] = 20 zero bytes
actual_sha1 = SHA1(temp)
assert actual_sha1 == expected_sha1

GP4 Authoring Manifest Relationship: During build time, Publishing Tools read a .gp4 XML project (<psproject fmt="gp4" version="1000">) containing <volume>, <files>, <rootdir>, and <scenarios>, compiling those rules into playgo-chunk.dat, the PFS filesystem tree, and the final .pkg.

4. Edge Cases & Loader/Parser Rules

  • TRP Entry Alignment & EntrySize Checks: Although standard PS4 TRPs set EntrySize == 0x40, parsers should validate EntrySize >= 0x40 and advance entry cursors by EntrySize rather than a hardcoded constant.
  • .SFM vs. .ESFM Inside TRP: Unencrypted development/v1 TRPs contain plain XML files (TROPCONF.SFM, TROP.SFM), whereas retail PS4 TRPs carry AES-128-CBC encrypted .ESFM members with non-zero Flags. PNG icons inside the same TRP remain plaintext and can be extracted without decryption keys.
  • PlayGo Chunk Ordering & Language Masks: In playgo-chunk.dat, chunk 0 holds the initial mandatory boot files (eboot.bin, sce_sys/, core runtime PRXs). Each chunk carries a 64-bit language mask allowing localized assets to be filtered by system language during progressive download.
  • PKG vs. Mounted PFS Mirroring: Files inside sce_sys/ appear both as CNT entry records in the outer .pkg (for pre-install XMB inspection before mounting PFS) and inside the inner PFS uroot/sce_sys/ directory. Parsers reading an unpacked game directory should prefer sce_sys/ directly, while .pkg inspectors can read CNT entries 0x1000..0x1400+ without mounting PFS.

5. Step-by-Step Pseudocode

function ParseOrbisTrp(trp_bytes):
    if len(trp_bytes) < 0x40:
        error("Truncated TRP header")
    if read_u32be(trp_bytes, 0x00) != 0xDCA24D00:
        error("Invalid TRP magic")

    version     = read_u32be(trp_bytes, 0x04)
    file_size   = read_u64be(trp_bytes, 0x08)
    entry_count = read_u32be(trp_bytes, 0x10)
    entry_size  = read_u32be(trp_bytes, 0x14)

    if entry_size < 0x40 or 0x40 + entry_count * entry_size > len(trp_bytes):
        error("TRP entry table out of bounds")

    if version >= 2:
        stored_sha1 = trp_bytes[0x1C : 0x30]
        check_buf = bytearray(trp_bytes)
        check_buf[0x1C : 0x30] = b"\x00" * 20
        sha1_valid = (SHA1(check_buf) == stored_sha1)
    else:
        sha1_valid = null

    members = []
    for i in 0 .. entry_count - 1:
        off = 0x40 + i * entry_size
        name   = decode_ascii(trp_bytes[off : off + 0x20]).split("\x00", 1)[0]
        m_off  = read_u64be(trp_bytes, off + 0x20)
        m_size = read_u64be(trp_bytes, off + 0x28)
        flags  = read_u32be(trp_bytes, off + 0x30)
        if m_off + m_size > len(trp_bytes):
            error("TRP member out of bounds: " + name)
        members.append({ name: name, offset: m_off, size: m_size, flags: flags })

    return { version: version, sha1_valid: sha1_valid, members: members }

function ParsePlayGoHeader(plgo_bytes):
    if len(plgo_bytes) < 0x70:
        error("Truncated playgo-chunk.dat")
    if plgo_bytes[0x00 : 0x04] != b"plgo":
        error("Invalid PLGO magic")

    return {
        version_major:       read_u16le(plgo_bytes, 0x04),
        version_minor:       read_u16le(plgo_bytes, 0x06),
        image_count:         read_u16le(plgo_bytes, 0x08),
        chunk_count:         read_u16le(plgo_bytes, 0x0A),
        mchunk_count:        read_u16le(plgo_bytes, 0x0C),
        scenario_count:      read_u16le(plgo_bytes, 0x0E),
        file_size:           read_u32le(plgo_bytes, 0x10),
        default_scenario_id: read_u16le(plgo_bytes, 0x14),
        attrib:              read_u16le(plgo_bytes, 0x16),
        sdk_version:         read_u32le(plgo_bytes, 0x18),
        disc_count:          read_u16le(plgo_bytes, 0x1C),
        layer_bmp:           read_u16le(plgo_bytes, 0x1E),
        content_id:          decode_ascii(plgo_bytes[0x40 : 0x70]).split("\x00", 1)[0],
    }

6. Provenance & Confidence

Confirmed: TRP Header/Entries & sce_sys/ Layout Revision-Dependent: PlayGo v1 vs. v2 Table Slots Crypto-Gated: .ESFM Decryption Key
  • Confirmed Specification: The big-endian 64-byte TRP header (0xDCA24D00), 64-byte entry layout, SHA-1 validation rule, core playgo-chunk.dat header (0x00..0x6F), and standard sce_sys/ filenames/PKG entry IDs are confirmed across Orbis SDK and open-source PlayStation 4 packaging utilities.
  • SDK-Revision-Dependent: Header offset/size descriptor slots beyond 0x70 in playgo-chunk.dat evolved between early version_major == 1 and later version_major == 2 releases (adding inner mchunk tables and extended chunk counts).
  • Crypto-Gated Fields: Decrypting .ESFM XML files inside retail PS4 trophy00.trp archives requires platform trophy encryption keys not distributed here.

Security & Key Exclusion Notice: Do NOT embed Sony ESFM trophy decryption keys or pronunciation signature private keys in clean-room tooling. Plain PNG assets (ICON0.PNG, TROP*.PNG) inside TRP archives can be inspected safely without cryptographic material.
