1. Identification & Scope

PS4 .pkg files are identified at offset 0x0000 by the 4-byte magic 7F 43 4E 54 (\x7FCNT), distinguishing them from PS3 \x7FPKG (0x7F504B47) packages. Internally, a PS4 .pkg is split into two nested structural domains with opposite byte orders:

  • Outer CNT Container (Big-Endian): Holds the 0x1000-byte CNT header (including SHA-256 digests, PFS geometry at 0x400, and RSA-2048 header signature), followed by the CNT Entry Table (pkg_entry_count × 32-byte big-endian records) and entry payloads (param.sfo, icon0.png, playgo-chunk.dat, license files, key tables, and digests).
  • Inner PFS Image (Little-Endian): Located at pfs_image_offset (declared at CNT header 0x408). The PFS image begins with a little-endian Superblock (version = 1, magic = 20130315 / 0x01332A0B), followed by dynamic inodes (dinode) and a hierarchical directory tree rooted at uroot containing sce_sys/ and application files.

Hybrid Endianness Rule: CNT header and entry table integers MUST be decoded as big-endian (u16be / u32be / u64be). Once seeking to pfs_image_offset, all PFS superblock fields, inode pointers, and directory records MUST be decoded as little-endian (u16le / u32le / u64le).

is_encrypted = (entry.flags1 & 0x80000000) != 0

padded_size  = (entry.size + 15) & ~15              // AES-128 block alignment

4. Edge Cases & Loader/Parser Rules

  • Encrypted vs. Unencrypted CNT Entries: System metadata entries (param.sfo, icon0.png, playgo-chunk.dat) often appear unencrypted or encrypted under the package's entry key table (id == 0x0010), whereas DRM/license entries (0x0400..0x0409) are encrypted using RSA-wrapped entry keys and passcode-derived keys. Always check bit 31 (0x80000000) of flags1 before reading raw bytes.
  • PFS Image Inside PKG vs. Raw Directory: Inside a .pkg, the PFS image at pfs_image_offset is typically encrypted with EKpfs (XTS-AES-128) and signed (PFS.mode & 0x05). Orbis OS mounts the PFS image transparently as a read-only block filesystem after verifying the superblock and HMAC/SHA-256 block hashes, exposing uroot/sce_sys/ and uroot/eboot.bin as a normal VFS directory.
  • Directory Block Boundary Rule: A PFS dirent never crosses a blocks_size boundary. If the remaining space in the current block is smaller than the next entry, the preceding entry's entsize is stretched to consume the rest of the block, and the next entry begins at offset 0 of the next block.
  • Indirect Block Pointers: Standard dinodeD32 / dinodeS32 records hold 12 direct block pointers and 5 indirect block pointers (single/double indirect) to address files larger than 12 * blocks_size.

5. Step-by-Step Pseudocode

function ParsePs4PkgAndPfsHeader(pkg_bytes):
    if len(pkg_bytes) < 0x1000:
        error("Truncated CNT PKG header")

    // 1. Read Big-Endian CNT Header
    if read_u32be(pkg_bytes, 0x000) != 0x7F434E54:
        error("Invalid PS4 PKG magic (expected \\x7FCNT)")

    entry_count  = read_u32be(pkg_bytes, 0x010)
    table_offset = read_u32be(pkg_bytes, 0x018)
    content_id   = decode_ascii(pkg_bytes[0x040 : 0x064]).rstrip("\x00")
    content_type = read_u32be(pkg_bytes, 0x074)
    pfs_offset   = read_u64be(pkg_bytes, 0x408)
    pfs_size     = read_u64be(pkg_bytes, 0x410)

    if table_offset + entry_count * 0x20 > len(pkg_bytes):
        error("CNT Entry Table out of bounds")

    // 2. Parse Big-Endian CNT Entry Table
    entries = []
    names_entry = null
    for i in 0 .. entry_count - 1:
        off = table_offset + i * 0x20
        e = {
            id:              read_u32be(pkg_bytes, off + 0x00),
            filename_offset: read_u32be(pkg_bytes, off + 0x04),
            flags1:          read_u32be(pkg_bytes, off + 0x08),
            flags2:          read_u32be(pkg_bytes, off + 0x0C),
            offset:          read_u32be(pkg_bytes, off + 0x10),
            size:            read_u32be(pkg_bytes, off + 0x14),
        }
        if e.offset + e.size > len(pkg_bytes):
            error("CNT entry payload out of bounds")
        if e.id == 0x0200:
            names_entry = e
        entries.append(e)

    // 3. Inspect Embedded Little-Endian PFS Superblock (when unencrypted/decrypted)
    if pfs_offset + 0x50 > len(pkg_bytes):
        error("PFS image offset out of bounds")

    pfs_version = read_u64le(pkg_bytes, pfs_offset + 0x00)
    pfs_magic   = read_u64le(pkg_bytes, pfs_offset + 0x08)
    if pfs_magic == 20130315:
        pfs_mode        = read_u16le(pkg_bytes, pfs_offset + 0x1C)
        blocks_size     = read_u32le(pkg_bytes, pfs_offset + 0x20)
        ndinode         = read_u64le(pkg_bytes, pfs_offset + 0x30)
        superroot_ino   = read_u64le(pkg_bytes, pfs_offset + 0x48)
        pfs_status      = "Plaintext/Decrypted PFS Superblock"
    else:
        pfs_status      = "Encrypted PFS Image (EKpfs required)"

    return {
        content_id: content_id,
        content_type: content_type,
        cnt_entries: entries,
        pfs_status: pfs_status
    }

6. Provenance & Confidence

Confirmed: CNT Header, Entry Table & PFS Superblock Revision-Dependent: EKC / Content Flag Bits Crypto-Gated: EKpfs, Entry Keys & Retail Passcodes
  • Confirmed Specification: The big-endian CNT header offsets (0x000..0x477), 32-byte CNT entry records, standard entry IDs (0x0001..0x1400+), and the little-endian PFS superblock (magic = 20130315) and dirent format are consistently verified across Orbis OS package builders and open-source PFS readers.
  • Crypto-Gated Components: Retail .pkg entry key decryption (entry 0x0010), EKpfs derivation (entry 0x0020), and package passcodes require authorized keys or passcode inputs and cannot be bypassed from header metadata alone.

Security & Key Exclusion Notice: Do NOT embed retail Sony RSA keys, AES key schedules, or package passcodes. An independent parser should extract unencrypted CNT entries directly and surface a clear authentication/decryption boundary for encrypted entries or encrypted PFS blocks.
