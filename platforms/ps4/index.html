Platform Architecture & Execution Pipeline

Unlike the Cell Broadband Engine on PlayStation 3, the PlayStation 4 standardizes user-mode code on 64-bit x86-64 (EM_X86_64) inside a modified FreeBSD ELF64 ABI. Executables (eboot.bin) and dynamic libraries (.prx / .sprx) are wrapped in the Orbis SELF container (0x1D3D154F), which adds segment encryption/signing descriptors and process entitlement blocks verified by the Secure Asset Management Unit (SAMU) before mapping ELF64 segments into virtual memory.

  • Application Packaging (.pkg / PFS): Digital releases, patches, and add-on content are distributed in big-endian CNT .pkg archives (\x7FCNT). Metadata entries (such as param.sfo, icons, PlayGo chunk tables, and license records) reside directly in the PKG entry table, while the main application tree lives inside an embedded little-endian PFS (PlayStation File System) image.
  • Progressive Installation (PlayGo): Large titles split their PFS payload into addressable chunk ranges described by playgo-chunk.dat (plgo) and playgo-manifest.xml so the system shell can launch an application once initial chunks are installed.
  • System Metadata & Trophies (sce_sys/): Every mounted Orbis application exposes a standardized sce_sys/ directory holding param.sfo, shell art, playgo-chunk.dat, and trophy/trophy00.trp.

Hybrid Endianness Caveat: While the x86-64 CPU, Orbis ELF64/SELF, param.sfo, playgo-chunk.dat, and PFS superblocks/inodes are little-endian, Sony carried forward big-endian outer container headers for PS4 CNT .pkg packages and trophy00.trp trophy archives. Parsers must switch byte order at the container boundary.
