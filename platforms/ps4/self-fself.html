Orbis SELF / FSELF & Embedded ELF64-x86_64

PLAYSTATION 4 · EXECUTABLE & SHARED MODULE CONTAINER

Signed, optionally encrypted, and optionally zlib-compressed wrapper around 64-bit x86-64 Orbis ELF executables (eboot.bin) and relocatable dynamic modules (.prx / .sprx). FSELF ("Fake SELF") images keep the same binary envelope with encryption/signing bypassed for development or decrypted inspection.

eboot.bin, *.prx, *.sprx, *.self, *.elf (unwrapped)
Magic Bytes
SELF: 4F 15 3D 1D (u32le 0x1D3D154F); Embedded ELF64: 7F 45 4C 46 (\x7FELF)
Endianness
Little-endian throughout (SELF header, segment entries, ELF64 headers, PT_SCE_* structures)
Platform/OS Scope
PlayStation 4 (Orbis OS, FreeBSD-derived kernel, AMD64 x86-64)
Role/MIME
Primary application executable and dynamic library container (application/x-orbis-self)

1. Identification & Scope

Orbis OS does not execute raw ELF files directly from retail media or packages. Instead, every main executable (eboot.bin) and dynamic module (.prx / .sprx) is packaged inside an Orbis SELF envelope identified by the 32-bit little-endian magic 0x1D3D154F (byte sequence 4F 15 3D 1D). This magic is distinct from PlayStation 3's big-endian SCE\0 (0x53434500) SELF header.

  • Pure Little-Endian Hierarchy: Unlike PS4 .pkg (CNT) or trophy00.trp archives whose outer headers are big-endian, Orbis SELF headers, segment entry descriptors, embedded ELF64-x86_64 headers, program headers, and PT_SCE_DYNLIBDATA tables are uniformly little-endian.
  • SELF vs. FSELF: Retail SELFs carry encrypted AES-128-CTR/CBC segment payloads, SHA-256 block digests, and RSA-2048 signatures validated by the SAMU co-processor. Development or unwrapped FSELF images use the exact same 0x1D3D154F header and 32-byte segment table, but leave loadable segments unencrypted (and optionally zlib-deflated) with unverified/dummy signature metadata.
  • Unwrapped ELF64-x86_64: Embedded directly after the SELF segment table is a standard 64-byte ELF64 header (7F 45 4C 46, EI_CLASS=2, EI_DATA=1, e_machine=0x003E) followed by 56-byte Elf64_Phdr entries including Orbis-specific PT_SCE_* segments.

0x0E 2 u16le MetaSize Size in bytes of the cryptographic metadata block (segment keys, HMACs, RSA signature).
0x10 8 u64le FileSize Declared SELF image size in bytes (excluding optional trailing version/footer blocks on some builds).
0x18 2 u16le NumEntries Number of 32-byte segment entries starting immediately at offset 0x20.
0x1A 2 u16le Flags Global SELF flags (commonly 0x0002 in Orbis SELFs).
0x1C 4 u32le Reserved Zero padding (0x00000000).

Offset Size Type Field Description
0x00 8 u64le Flags Packed bitfield: encryption/compression/signing flags, block size exponent (bits 12..15), and linked ELF Phdr index (bits 20..31).
0x08 8 u64le Offset Absolute byte offset from the start of the SELF file to this entry's payload or block-digest table.
0x10 8 u64le CompressedSize Stored byte size in the SELF file (on disk).
0x18 8 u64le UncompressedSize Logical/decompressed byte size (matches Elf64_Phdr.p_filesz for data segments).

Offset Size Type Field Description

0x34 2 u16le e_ehsize Size of ELF64 header (64).

0x38 2 u16le e_phnum Number of Elf64_Phdr entries.

0x3C 2 u16le e_shnum Number of Section Headers (often 0 in stripped SELFs).

Embedded ELF64 Program Header (Elf64_Phdr, 56 bytes / 0x38 each)
Offset Size Type Field Description
0x00 4 u32le p_type Segment type (PT_LOAD, PT_DYNAMIC, PT_INTERP, or PT_SCE_*).
0x04 4 u32le p_flags Permission flags (PF_X=1, PF_W=2, PF_R=4, plus SCE-specific upper bits).
0x08 8 u64le p_offset Segment offset in the reconstructed ELF file.
0x10 8 u64le p_vaddr Target virtual address (typically 0 for non-mapped PT_SCE_DYNLIBDATA).
0x18 8 u64le p_paddr Physical/load address (mirrors p_vaddr or 0).
0x20 8 u64le p_filesz Byte size of segment data stored in the ELF / SELF segment entry.
0x28 8 u64le p_memsz Byte size allocated in virtual memory (p_memsz - p_filesz is zero-filled BSS).
0x30 8 u64le p_align Segment alignment (typically 0x4000 = 16 KiB page alignment on Orbis, or 0x1000).

3. Flags, Enums & Decoding Formulas

Orbis SELF Segment Entry Flags (u64le Flags at entry +0x00)
Mask / Bits Shift Name Meaning
0x0000000000000001 Bit 0 SF_ORDERED Segment data is sequentially ordered.
0x0000000000000002 Bit 1 SF_ENCRYPTED Segment payload is encrypted (AES-128-CTR/CBC under metadata segment key). Cleared in FSELF.
0x0000000000000004 Bit 2 SF_SIGNED Segment is covered by cryptographic signature/digest verification.
0x0000000000000008 Bit 3 SF_DEFLATED Segment payload is zlib-compressed (RFC 1950/1951); inflate when CompressedSize < UncompressedSize.
0x0000000000000800 Bit 11 SF_BLOCKS Segment is segmented into fixed-size blocks and carries an associated ELF Phdr index.
0x000000000000F000 Bits 12..15 SF_BLOCK_SIZE Block size exponent exp = (Flags >> 12) & 0xF; block size = 1 << (12 + exp) bytes (e.g., exp=2 → 0x4000 = 16 KiB).
0x0000000000010000 Bit 16 SF_DIGESTS Entry holds SHA-256 block digest table rather than raw ELF segment payload.
0x0000000000020000 Bit 17 SF_EXTENTS Entry holds block extent descriptor records for its linked segment.
0x00000000FFF00000 Bits 20..31 SF_SEGMENT_ID SegmentId = (Flags >> 20) & 0xFFF; indexes Elf64_Phdr[SegmentId].
Orbis ELF64 Object Types (e_type) & Program Header Types (p_type)
Value Category Symbol Description
0xFE00 e_type ET_SCE_EXEC Orbis non-ASLR executable image.
0xFE04 e_type ET_SCE_RELAEXEC Orbis relocatable executable image.
0xFE10 e_type ET_SCE_DYNEXEC Orbis ASLR/position-independent main executable (eboot.bin).
0xFE18 e_type ET_SCE_DYNAMIC Orbis dynamic shared library module (.prx / .sprx).
0x60000000 p_type PT_SCE_RELA SCE relocation segment.
0x61000000 p_type PT_SCE_DYNLIBDATA Dynamic linking data (NID strings, symbol/hash tables, JMPREL/RELA, module/library imports and exports).
0x61000001 p_type PT_SCE_PROCPARAM Process parameter block (sceProcessParam: SDK version, libc heap/ASLR configuration).
0x61000002 p_type PT_SCE_MODULE_PARAM PRX/SPRX module parameter block (sceModuleParam: SDK version and module metadata).
0x61000010 p_type PT_SCE_RELRO Read-only-after-relocation segment (mapped RW during dynamic linking, then protected RO).
0x6FFFFF00 p_type PT_SCE_COMMENT SCE toolchain/linker build comment data.
0x6FFFFF01 p_type PT_SCE_VERSION SCE module/SDK version descriptor list.

NID Dynamic Linking Formula: Orbis dynamic linking identifies imported and exported functions/variables using NIDs (Name Identifiers) rather than raw symbol strings. An export or import name in PT_SCE_DYNLIBDATA's string table (DT_SCE_STRTAB) is formatted as:

nid_string = Base64Url_NoPad(first_8_bytes(SHA1(symbol_name || platform_nid_salt)))
full_entry = nid_string + "#" + LibraryId_Base64 + "#" + ModuleId_Base64

Note that the 8-byte digest is interpreted as a 64-bit integer and encoded into 11 URL-safe Base64 characters (alphabet A-Z a-z 0-9 + - or - _ depending on encoder variant, without = padding).

4. Edge Cases & Loader/Parser Rules

  • Segment Entry Deduplication (Data vs. Digest/Extent Entries): A SELF's NumEntries table often contains more entries than e_phnum. For each encrypted/blocked ELF Phdr, there is typically a digest/block-metadata entry (SF_DIGESTS or SF_EXTENTS set) alongside the actual data entry (SF_BLOCKS set and SF_DIGESTS == 0 and SF_EXTENTS == 0). Both share the same SegmentId = (Flags >> 20) & 0xFFF. Parsers reconstructing the unwrapped ELF must select only the payload entry (ignoring digest/extent entries) and write its decompressed/decrypted bytes to Elf64_Phdr[SegmentId].p_offset.
  • Non-Mapped PT_SCE_DYNLIBDATA: Unlike standard SysV ELF where .dynamic, .dynsym, and .dynstr reside inside a PT_LOAD segment, Orbis places dynamic linking metadata inside PT_SCE_DYNLIBDATA (0x61000000), which commonly has p_vaddr == 0 and p_memsz == 0 while carrying a non-zero p_offset and p_filesz. The kernel/runtime dynamic linker (ld-elf / libkernel) reads this segment via file/descriptor rather than mapping it into the application's executable address space.
  • FSELF vs. Retail Encrypted SELF: If SF_ENCRYPTED (bit 1) is set, the raw bytes at entry.Offset are AES-128-CTR/CBC ciphertext and cannot be parsed or inflated without SAMU hardware decryption or externally decrypted keys. If SF_ENCRYPTED == 0 (FSELF or decrypted SELF), check SF_DEFLATED (bit 3): if set, inflate with zlib from entry.Offset (CompressedSize) to UncompressedSize bytes; otherwise copy UncompressedSize bytes directly.
  • Generalized Orbis ELF64 Loader Mapping: After unwrapping segments, a compliant loader iterates over Elf64_Phdr entries:
    1. Validate e_machine == 0x003E, e_phentsize == 56, and bounds against file size.
    2. For every PT_LOAD segment, map p_memsz bytes at base_addr + p_vaddr (16 KiB page aligned on Orbis), copy p_filesz bytes from p_offset, and zero-fill [p_filesz .. p_memsz) (BSS).
    3. Resolve dynamic dependencies from PT_DYNAMIC (DT_NEEDED / DT_SCE_* tags pointing into PT_SCE_DYNLIBDATA) and apply R_X86_64_* relocations from DT_SCE_RELA / DT_SCE_JMPREL.
    4. Apply final memory protections (RX/RW/RO), including marking PT_SCE_RELRO read-only after relocations complete, then transfer control to base_addr + e_entry (for executables) or module entry.
  • Trailing Signature / Padding: Retail SELFs may contain extra signature or padding bytes after the last segment's Offset + CompressedSize; do not assume FileSize equals the actual disk file length without bounds-checking each entry independently.

5. Step-by-Step Pseudocode

function ParseAndUnwrapOrbisSelf(file_bytes):
    if len(file_bytes) < 0x20:
        error("Truncated Orbis SELF header")

    magic       = read_u32le(file_bytes, 0x00)
    if magic != 0x1D3D154F:
        error("Invalid Orbis SELF magic")

    endian      = read_u8(file_bytes, 0x06)
    header_size = read_u16le(file_bytes, 0x0C)
    meta_size   = read_u16le(file_bytes, 0x0E)
    file_size   = read_u64le(file_bytes, 0x10)
    num_entries = read_u16le(file_bytes, 0x18)

    table_end = 0x20 + num_entries * 0x20
    if table_end + 0x40 > len(file_bytes):
        error("SELF segment table or ELF64 header out of bounds")

    // 1. Parse SELF segment entries
    self_entries = []
    for i in 0 .. num_entries - 1:
        off = 0x20 + i * 0x20
        entry = {
            flags:             read_u64le(file_bytes, off + 0x00),
            offset:            read_u64le(file_bytes, off + 0x08),
            compressed_size:   read_u64le(file_bytes, off + 0x10),
            uncompressed_size: read_u64le(file_bytes, off + 0x18),
        }
        if entry.offset + entry.compressed_size > len(file_bytes):
            error("SELF entry payload out of bounds")
        self_entries.append(entry)

    // 2. Parse embedded ELF64-x86_64 header immediately after segment table
    elf_off = table_end
    if file_bytes[elf_off : elf_off + 4] != b"\x7FELF":
        error("Missing embedded ELF64 header")
    if read_u8(file_bytes, elf_off + 4) != 2 or read_u16le(file_bytes, elf_off + 0x12) != 0x003E:
        error("Expected 64-bit x86-64 ELF")

    e_phoff     = read_u64le(file_bytes, elf_off + 0x20)
    e_phentsize = read_u16le(file_bytes, elf_off + 0x36)
    e_phnum     = read_u16le(file_bytes, elf_off + 0x38)
    if e_phentsize != 56:
        error("Unexpected Elf64_Phdr size")

    // 3. Read Elf64_Phdr table and determine reconstructed ELF output size
    phdrs = []
    max_elf_end = elf_off + e_phoff + e_phnum * 56
    out_min_size = e_phoff + e_phnum * 56
    for p in 0 .. e_phnum - 1:
        po = elf_off + e_phoff + p * 56
        if po + 56 > len(file_bytes):
            error("Program header out of bounds")
        ph = {
            p_type:   read_u32le(file_bytes, po + 0x00),
            p_flags:  read_u32le(file_bytes, po + 0x04),
            p_offset: read_u64le(file_bytes, po + 0x08),
            p_vaddr:  read_u64le(file_bytes, po + 0x10),
            p_filesz: read_u64le(file_bytes, po + 0x20),
            p_memsz:  read_u64le(file_bytes, po + 0x28),
        }
        phdrs.append(ph)
        out_min_size = max(out_min_size, ph.p_offset + ph.p_filesz)

    // 4. Allocate output ELF buffer and copy ELF header + Phdrs
    elf_out = bytearray(out_min_size)
    hdr_len = e_phoff + e_phnum * 56
    elf_out[0 : hdr_len] = file_bytes[elf_off : elf_off + hdr_len]
    // Clear stripped section header fields if no section headers are carried
    write_u64le(elf_out, 0x28, 0) // e_shoff
    write_u16le(elf_out, 0x3C, 0) // e_shnum
    write_u16le(elf_out, 0x3E, 0) // e_shstrndx

    // 5. Unwrap data segments linked to Elf64_Phdr indices
    for entry in self_entries:
        is_blocks  = (entry.flags & 0x800) != 0
        is_meta    = (entry.flags & 0x30000) != 0 // SF_DIGESTS | SF_EXTENTS
        if not is_blocks or is_meta:
            continue

        seg_id = (entry.flags >> 20) & 0xFFF
        if seg_id >= len(phdrs):
            error("SELF SegmentId out of Elf64_Phdr range")

        if (entry.flags & 0x02) != 0:
            error("Segment is retail-encrypted (SF_ENCRYPTED); SAMU key required")

        raw = file_bytes[entry.offset : entry.offset + entry.compressed_size]
        if (entry.flags & 0x08) != 0:
            payload = zlib_decompress(raw, expected_size=entry.uncompressed_size)
        else:
            payload = raw[0 : entry.uncompressed_size]

        dst_off = phdrs[seg_id].p_offset
        elf_out[dst_off : dst_off + len(payload)] = payload

    return elf_out

6. Provenance & Confidence

Confirmed: SELF Header, Segment Table & ELF64 Revision-Dependent: Extended Info / NPDRM Fields Crypto-Gated: SAMU Segment Key Material
  • Confirmed Specification: The 32-byte Orbis SELF common header (0x1D3D154F), 32-byte segment entry format, SF_* flag bits, embedded ELF64-x86_64 layout, and PT_SCE_DYNLIBDATA / PT_SCE_PROCPARAM / PT_SCE_MODULE_PARAM / PT_SCE_RELRO program header types are consistently verified across Orbis SDK toolchains and open-source PS4 loaders/builders.
  • SDK-Revision-Dependent: Certain upper bits in Flags, KeyType values, and optional NPDRM / extended info fields vary across Orbis firmware/SDK generations (e.g., 1.xx vs. 4.xx+ vs. 9.xx+).
  • Crypto-Gated Fields: Retail RSA-2048 signatures, segment AES-128-CTR keys, HMAC-SHA-256 digests, and SAMU key seeds inside MetaSize cannot be unwrapped offline without hardware-derived keys.

Security & Key Exclusion Notice: No retail Sony private keys, SAMU key seeds, or proprietary NID salts are included in this specification. Tools parsing retail SELFs without hardware decryption must abort cleanly when SF_ENCRYPTED (bit 1) is set.
