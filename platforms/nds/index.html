Nintendo DS (NTR / TWL)

Platform Architecture & Inherited Formats · Dual-ARM Handheld

The Nintendo DS (hardware code NTR, later extended by Nintendo DSi TWL) is a dual-processor ARM handheld built around an ARM946E-S main CPU and an ARM7TDMI sub-processor booting from Slot-1 Nitro Game Cards. Applications link against the Nintendo Nitro SDK and inherit standardized cartridge headers, NitroFS file tables, ARM overlay descriptors, UTF-16LE localized title banners, and Nitro archive/audio/compression containers.

Main CPU
ARM946E-S (ARMv5TEJ, 67.028 MHz in NTR mode; up to 134.056 MHz in TWL mode), 8 KiB I-cache, 4 KiB D-cache, 32 KiB ITCM, 16 KiB DTCM.
Sub CPU
ARM7TDMI (ARMv4T, 33.514 MHz), 64 KiB dedicated WRAM; handles audio mixing, SPI flash/touchscreen/RTC, Wi-Fi, and IPC.
Main Memory
4 MiB Main RAM at 0x02000000–0x023FFFFF (expanded to 16 MiB at 0x02000000–0x02FFFFFF on DSi TWL), plus 32 KiB shared WRAM.
Boot Media
Slot-1 Nitro Card (ROM + SPI save memory), authenticated via header CRC-16, Nintendo Logo CRC-16, and Blowfish KEY1 Secure Area.
Endianness
Strictly little-endian across both ARM cores and all Nitro SDK binary containers.

Nitro Card & Dual-CPU Boot Architecture

At power-on, internal ARM9 and ARM7 boot ROMs initialize hardware and read the cartridge header at ROM offset 0x0000. Unlike memory-mapped GBA Game Paks, Slot-1 Nitro Cards are accessed sequentially over an 8-byte command bus controlled by REG_ROMCTRL (0x040001A4). The firmware validates the compressed Nintendo logo bitmap and header checksums, loads the static ARM9 and ARM7 binaries into their respective target RAM addresses, decrypts the 16 KiB Secure Area (0x4000–0x7FFF) if present, and jumps to the two CPU entry points.

Because Main RAM is 4 MiB on retail NTR hardware, larger binaries split code into dynamically paged overlays indexed by y9.bin and y7.bin and stored inside the NitroFS File Allocation Table (FAT). Data assets are addressed either by 16-bit FAT file IDs or hierarchical directory paths in the File Name Table (FNT), and routinely packaged using Nitro SDK container and BIOS compression primitives.

Generalized Loader & Memory Constraints

Standard NTR loaders enforce strict address boundaries when placing static binaries and overlays:

  • ARM9 Main RAM Window: Static ARM9 binaries and overlays load into 0x02000000–0x023BFE00 (leaving upper Main RAM reserved for shared IPC structures, SDK heaps, and system buffers).
  • ARM7 Target Regions: Static ARM7 binaries load either into Main RAM (typically near 0x02380000) or into ARM7-side WRAM spanning up to 96 KiB (0x037F8000–0x037FFFFF for 32 KiB shared WRAM when mapped to ARM7, plus 0x03800000–0x0380FFFF for 64 KiB dedicated ARM7 WRAM).
  • DSi Extended Binaries: Hybrid (unit_code = 0x02) and DSi-exclusive (unit_code = 0x03) images add secondary ARM9i and ARM7i segments configured via header offsets 0x01C0–0x01DF.
