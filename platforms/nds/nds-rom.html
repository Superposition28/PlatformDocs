Nintendo DS Cartridge ROM (.nds / .srl) & NitroFS

Platform Binary Specification · Boot Image & Filesystem

The Nintendo DS cartridge image stores the boot header, ARM9 and ARM7 static executables, overlay tables, icon/title banner, and the NitroFS File Allocation Table (FAT) and File Name Table (FNT). Both retail dumps and Nitro SDK Shared ROM (.srl) build outputs share this layout.

Canonical Filenames
*.nds (retail/dumped cartridge image), *.srl (Nitro SDK Shared ROM output)
Magic Bytes
No fixed 4-byte file signature; verified structurally via compressed Nintendo Logo at 0x00C0 (Logo CRC-16 0xCF56 at 0x015C) and Header CRC-16 at 0x015E
Endianness
Little-endian (u16le, u32le)

Nintendo DS (NTR) Slot-1 cartridges; extended 4 KiB header on Nintendo DSi (TWL) hybrid/exclusive cartridges
Role/MIME

1. Identification & Scope

Unlike container formats with a leading FourCC magic word, a Nintendo DS ROM begins immediately at 0x0000 with an ASCII game title. Parsers identify a valid .nds / .srl image by validating structural invariants across the first 0x200 bytes:

  • Header Checksum: Computing CRC-16/MODBUS over bytes 0x0000–0x015D must match the u16le value at 0x015E.
  • Nintendo Logo & Logo CRC: Bytes 0x00C0–0x015B (156 bytes) contain the 1-bit Huffman/LZ-packed Nintendo logo bitmap beginning with 24 FF AE 51 69 9A A2 21; its CRC-16/MODBUS must equal the u16le at 0x015C (0xCF56 on official builds).
  • Segment Bounds: ARM9, ARM7, FNT, FAT, overlay tables, and banner offsets/sizes must fall within the total ROM length (and for NTR images, arm9_rom_offset >= 0x4000).

All multi-byte integers in the header, FAT, and FNT are stored in little-endian byte order.

3. Flags, Enums & Decoding Formulas

CRC-16/MODBUS Checksum

All NDS header and banner checksums use reflected CRC-16/MODBUS (polynomial 0xA001, initial value 0xFFFF, no final XOR):

crc = 0xFFFF
for byte in data:
    crc ^= byte
    for _ in range(8):
        if crc & 1:
            crc = (crc >> 1) ^ 0xA001
        else:
            crc >>= 1

FNT Directory & File ID Decoding

  • Directory Index Conversion: Directory IDs range from 0xF000 (root) up to 0xF000 + total_dir_count - 1. The 0-based index into the FNT main directory table is dir_index = dir_id & 0x0FFF, located at byte offset fnt_offset + (dir_index * 8).
  • Sequential File ID Assignment: File entries inside a directory sub-table do not store an explicit file ID. Instead, initialize file_id = dir_record.first_file_id when entering a directory sub-table, assign file_id to each file entry (0x01 <= type_len <= 0x7F), and increment file_id += 1.
  • FAT Size Derivation: For any valid file_id, file_size = fat[file_id].end_offset - fat[file_id].start_offset. Note that overlay files referenced by y9.bin / y7.bin occupy low FAT indices (often starting at 0) and may have no FNT name entry.

Device Capacity

The nominal ROM capacity in bytes is 131072 << device_capacity (e.g., 0x07 = 16 MiB, 0x09 = 64 MiB). Used content extends only up to ntr_rom_size (0x0080).

4. Edge Cases & Loader/Parser Rules

  • Secure Area Blowfish Encryption (0x4000–0x7FFF): Retail cartridges store the first 0x800 bytes of the Secure Area (0x4000–0x47FF) encrypted with Blowfish KEY1 (derived from game_code and BIOS key tables), with the decrypted first 8 bytes containing the marker "encryObj" (65 6E 63 72 79 4F 62 6A). Decrypted clean dumps and SDK .srl images often hold plaintext or cleared bytes in 0x4000–0x47FF; consequently, secure_area_crc16 at 0x006C reflects a specific state depending on whether the dump was encrypted or decrypted.
  • DSi Extended Header Detection: Only inspect 0x0180–0x0FFF when (unit_code & 0x02) != 0 and header_size >= 0x1000 (or arm9i_rom_offset != 0). Plain NTR ROMs leave 0x0170–0x3FFF zero-filled (or 0xFF-padded after 0x0200).
  • FNT Recursive Tree Bounds: Protect tree traversal against malformed or cyclic directory IDs: verify dir_index < total_dir_count, reject type_len == 0x80 (zero-length directory name), track visited directory IDs to prevent loops, and ensure subtable_offset stays within [total_dir_count * 8, fnt_size).
  • Generalized ARM9/ARM7 Loader Mapping: A clean-room loader reads arm9_size bytes from arm9_rom_offset into arm9_ram_address and arm7_size bytes from arm7_rom_offset into arm7_ram_address, then transfers control to arm9_entry_address and arm7_entry_address. If arm9_rom_offset == 0x4000, bytes 0x4000–0x47FF belong to the Secure Area prefix of the ARM9 binary.

5. Parser Pseudocode

function parse_nds_rom(rom_bytes):
    assert len(rom_bytes) >= 0x200

    # 1. Validate checksums
    expected_hdr_crc = read_u16le(rom_bytes, 0x015E)
    actual_hdr_crc   = crc16_modbus(rom_bytes[0x0000 : 0x015E])
    assert actual_hdr_crc == expected_hdr_crc

    expected_logo_crc = read_u16le(rom_bytes, 0x015C)
    actual_logo_crc   = crc16_modbus(rom_bytes[0x00C0 : 0x015C])
    assert actual_logo_crc == expected_logo_crc

    # 2. Read core header fields
    hdr = {
        title:           trim_null(rom_bytes[0x0000 : 0x000C]),
        game_code:       ascii(rom_bytes[0x000C : 0x0010]),
        maker_code:      ascii(rom_bytes[0x0010 : 0x0012]),
        unit_code:       rom_bytes[0x0012],
        arm9_rom_offset: read_u32le(rom_bytes, 0x0020),
        arm9_entry:      read_u32le(rom_bytes, 0x0024),
        arm9_ram_addr:   read_u32le(rom_bytes, 0x0028),
        arm9_size:       read_u32le(rom_bytes, 0x002C),
        arm7_rom_offset: read_u32le(rom_bytes, 0x0030),
        arm7_entry:      read_u32le(rom_bytes, 0x0034),
        arm7_ram_addr:   read_u32le(rom_bytes, 0x0038),
        arm7_size:       read_u32le(rom_bytes, 0x003C),
        fnt_offset:      read_u32le(rom_bytes, 0x0040),
        fnt_size:        read_u32le(rom_bytes, 0x0044),
        fat_offset:      read_u32le(rom_bytes, 0x0048),
        fat_size:        read_u32le(rom_bytes, 0x004C),
        ov9_offset:      read_u32le(rom_bytes, 0x0050),
        ov9_size:        read_u32le(rom_bytes, 0x0054),
        ov7_offset:      read_u32le(rom_bytes, 0x0058),
        ov7_size:        read_u32le(rom_bytes, 0x005C),
        banner_offset:   read_u32le(rom_bytes, 0x0068),
        header_size:     read_u32le(rom_bytes, 0x0084),
    }

    # 3. Parse FAT (File Allocation Table)
    assert hdr.fat_size % 8 == 0
    file_count = hdr.fat_size // 8
    fat = []
    for i in range(file_count):
        base = hdr.fat_offset + i * 8
        start_off = read_u32le(rom_bytes, base + 0)
        end_off   = read_u32le(rom_bytes, base + 4)
        assert start_off <= end_off <= len(rom_bytes)
        fat.append({ file_id: i, start: start_off, end: end_off })

    # 4. Parse FNT (File Name Table) starting at root (0xF000)
    fnt = rom_bytes[hdr.fnt_offset : hdr.fnt_offset + hdr.fnt_size]
    total_dirs = read_u16le(fnt, 0x06)
    visited = set()
    files = {}

    function walk_dir(dir_id, current_path):
        assert dir_id not in visited
        visited.add(dir_id)
        dir_idx = dir_id & 0x0FFF
        assert dir_idx < total_dirs

        rec_off       = dir_idx * 8
        sub_off       = read_u32le(fnt, rec_off + 0)
        next_file_id  = read_u16le(fnt, rec_off + 4)
        assert sub_off < len(fnt)

        pos = sub_off
        while pos < len(fnt):
            type_len = fnt[pos]
            pos += 1
            if type_len == 0x00:
                break
            name_len = type_len & 0x7F
            assert name_len > 0 and pos + name_len <= len(fnt)
            name = decode_name(fnt[pos : pos + name_len])
            pos += name_len

            if (type_len & 0x80) != 0:
                subdir_id = read_u16le(fnt, pos)
                pos += 2
                walk_dir(subdir_id, current_path + "/" + name)
            else:
                assert next_file_id < file_count
                files[current_path + "/" + name] = fat[next_file_id]
                next_file_id += 1

    walk_dir(0xF000, "")
    return { header: hdr, fat: fat, files: files }

6. Provenance & Confidence

The NTR header (0x0000–0x01FF), CRC-16/MODBUS checksums, FAT entry layout, and FNT directory tree encoding are confirmed against Nintendo DS hardware boot behavior and standard Nitro SDK ROM builders.

Caveats on DSi & Secure Area Fields: Fields in the TWL extended region (0x0180–0x0FFF) are documented at structural summary level for 0x01E0–0x0FFF because individual Modcrypt, SHA-1 HMAC digest regions, and RSA signature offsets vary across DSi system revisions and cartridge/DSiWare types. Similarly, Blowfish KEY1 key tables reside in internal NDS BIOS ROM and are omitted from this specification; parsers inspecting raw retail dumps should check whether 0x4000–0x47FF holds encrypted data or a decrypted "encryObj"/plaintext header.
