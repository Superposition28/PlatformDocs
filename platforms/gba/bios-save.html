GBA BIOS SWI Compression Headers & Cartridge Save Media IDs

Game Boy Advance · System BIOS Streams & Backup Media Identification

The GBA 16 KiB system BIOS provides built-in decompression and filtering routines invoked via Software Interrupts (SWI 0x10–0x18) operating on a standardized 32-bit little-endian stream header. Separately, because the 192-byte cartridge header contains no save-type field, official SDK backup libraries embed word-aligned ASCII identification strings inside the ROM image to declare EEPROM, SRAM/FRAM, or Flash save hardware.

1. Identification & Scope

This specification covers two platform-inherited mechanisms defined by GBA BIOS and Nintendo AGB SDK hardware conventions:

  • BIOS SWI Compression & Filtering Streams (SWI 0x10–0x18): All compressed/filtered streams share a 32-bit little-endian Data Header where bits 4..7 identify the algorithm (1 = LZ77, 2 = Huffman, 3 = Run-Length, 8 = Differential Filter) and bits 8..31 encode the uncompressed output byte length. Note that BitUnPack (SWI 0x10) uses a separate 8-byte parameter struct instead of the 32-bit stream header.
  • Cartridge Save Media Identification Strings: Because the 0x000–0x0BF cartridge header omits save media metadata, official SDK libraries link a 4-byte-aligned ASCII identifier string (suffixed with a 3-digit library version Vnnn) into the ROM image.
  • Endianness Rules: Stream headers and Huffman bitstream words are read as u32le, whereas LZ77 2-byte back-references pack the length nibble in the upper bits of byte 0 and the 12-bit displacement across both bytes in big-endian order.

3. Flags, Enums & Decoding Formulas

GBA BIOS SWI Data Unpacking & Decompression Functions (0x10–0x18)
SWI Number BIOS Function Header Type Nibble Write Unit & Target
0x10 BitUnPack None (r2 info block) 32-bit writes; expands 1/2/4/8-bit units to 1/2/4/8/16/32-bit units.
0x11 LZ77UnCompWram 1 (0x10) 8-bit writes (WRAM only; unsafe for VRAM).
0x12 LZ77UnCompVram 1 (0x10) 16-bit writes (VRAM-safe; disp ≥ 2 required).
0x13 HuffUnComp 2 (0x24 or 0x28) 32-bit writes (WRAM and VRAM safe; packs 4-bit or 8-bit symbols into 32-bit words).
0x14 RLUnCompWram 3 (0x30) 8-bit writes (WRAM only).
0x15 RLUnCompVram 3 (0x30) 16-bit writes (VRAM-safe).
0x16 Diff8bitUnFilterWram 8 (0x81) 8-bit writes; reverses 8-bit horizontal delta encoding (out[i] = out[i-1] + in[i]).
0x17 Diff8bitUnFilterVram 8 (0x81) 16-bit writes; reverses 8-bit delta encoding for VRAM.
0x18 Diff16bitUnFilter 8 (0x82) 16-bit writes; reverses 16-bit horizontal delta encoding (out16[i] = out16[i-1] + in16[i]).

Algorithm Decoding Formulas

  • LZ77 Token (b0, b1): copy_len = ((b0 >> 4) & 0x0F) + 3 (3..18); disp = (((b0 & 0x0F) << 8) | b1) + 1 (1..4096); copies byte-by-byte from out_pos - disp (allowing overlapping RLE-style self-copy when disp < copy_len).
  • Huffman Child Addressing: Given current node at byte offset node_off (relative to stream start) and node byte node_val: child0_off = (node_off & ~1) + ((node_val & 0x3F) * 2) + 2; child1_off = child0_off + 1. If bit 7 of node_val is set, child0_off is a leaf data byte; if bit 6 is set, child1_off is a leaf data byte.
  • 4-bit vs. 8-bit Huffman Packing: When header & 0x0F == 4, decoded 4-bit symbols are packed LSB-first into each 32-bit output word (8 symbols per u32le). When header & 0x0F == 8, 4 bytes are packed LSB-first per u32le.
  • Flash Chip Identification & 128 KiB Bank Switch: Writing unlock sequence [0x0E005555]=0xAA, [0x0E002AAA]=0x55, [0x0E005555]=0x90 enters ID mode where [0x0E000000] returns manufacturer ID and [0x0E000001] returns device ID (confirmed hardware IDs: 0xD4BF SST 64K, 0x1CC2 Macronix 64K, 0x3D1F Atmel 64K, 0x09C2 Macronix 128K, 0x1362 Sanyo 128K). Bank switching on 128 KiB Flash uses [0x0E005555]=0xAA, [0x0E002AAA]=0x55, [0x0E005555]=0xB0, [0x0E000000]=bank (0 or 1), and 0xF0 terminates ID/command mode.

4. Edge Cases & Loader/Parser Rules

  • VRAM 16-Bit Write & LZ77 Displacement Rule: Because GBA VRAM ignores byte-wide writes by duplicating the byte across both halves of a 16-bit write, LZ77UnCompVram (SWI 0x12) buffers halfwords and writes in 16-bit units. Consequently, a raw displacement of 0 (disp = 1 byte back) fails on real hardware because the odd byte has not been committed to VRAM yet; encoders targeting VRAM must enforce disp ≥ 2 (encoded 12-bit offset ≥ 0x001).
  • Decompressed Size Padding & Alignment: For HuffUnComp (SWI 0x13), output is always written in 32-bit words; if the uncompressed size is not a multiple of 4, extra trailing bits/bytes in the final word are written.
  • Save ID String Scanning Rules: When scanning a .gba ROM for save media strings:
    1. Scan on 4-byte aligned offsets (offset % 4 == 0), as official SDK libraries place the string in word-aligned constant pools.
    2. Match exact ASCII prefix followed by 3 ASCII digits ('0'..'9') and a terminating NUL (or space/non-alphanumeric) byte.
    3. Distinguish FLASH_V / FLASH512_V (64 KiB) from FLASH1M_V (128 KiB), and SRAM_V / SRAM_F_V (32 KiB) from EEPROM_V (512 B or 8 KiB).
    4. If multiple strings appear (rare) or none appear (homebrew/no-save ROMs), default gracefully to None unless an explicit hardware configuration overrides it.
  • EEPROM Address Window vs. Large ROMs: On ROMs ≤ 16 MiB, EEPROM responds across 0x0D000000–0x0DFFFFFF; on ROMs > 16 MiB (up to 32 MiB), the ROM extends into 0x0D000000–0x0DF00000, so EEPROM decoding is restricted to 0x0DFFFF00–0x0DFFFFFF.

5. Step-by-Step Parser Pseudocode

function decompress_bios_stream(src, offset):
    header = read_u32le(src, offset)
    comp_type = (header >> 4) & 0x0F
    sub_info  = header & 0x0F
    out_size  = (header >> 8) & 0x00FFFFFF

    if comp_type == 1:  # LZ77 (0x10)
        pos = offset + 4
        out = byte[out_size]
        out_pos = 0
        while out_pos < out_size:
            flags = src[pos]; pos += 1
            for bit in range(7, -1, -1):
                if out_pos >= out_size:
                    break
                if (flags & (1 << bit)) == 0:
                    out[out_pos] = src[pos]; pos += 1; out_pos += 1
                else:
                    b0 = src[pos]; b1 = src[pos + 1]; pos += 2
                    length = ((b0 >> 4) & 0x0F) + 3
                    disp   = (((b0 & 0x0F) << 8) | b1) + 1
                    if disp > out_pos:
                        error("LZ77 displacement before start of output")
                    for _ in range(length):
                        if out_pos >= out_size: break
                        out[out_pos] = out[out_pos - disp]
                        out_pos += 1
        return out

    elif comp_type == 2:  # Huffman (0x24 / 0x28)
        bit_width = sub_info  # 4 or 8
        tree_size = src[offset + 4]
        root_off  = offset + 5
        stream_off = offset + 4 + (tree_size + 1) * 2
        out = byte[out_size]
        out_pos = 0
        node_off = root_off
        word_pos = stream_off
        nibble_buf = 0; have_low_nibble = false
        while out_pos < out_size:
            w = read_u32le(src, word_pos); word_pos += 4
            for bit in range(31, -1, -1):
                if out_pos >= out_size: break
                dir = (w >> bit) & 1
                node_val = src[node_off]
                child_off = (node_off & ~1) + ((node_val & 0x3F) * 2) + 2 + dir
                is_leaf = ((node_val & (0x80 >> dir)) != 0)
                if is_leaf:
                    sym = src[child_off]
                    if bit_width == 8:
                        out[out_pos] = sym; out_pos += 1
                    else:  # 4-bit symbol packed LSB-first
                        if not have_low_nibble:
                            nibble_buf = sym & 0x0F; have_low_nibble = true
                        else:
                            out[out_pos] = nibble_buf | ((sym & 0x0F) << 4)
                            out_pos += 1; have_low_nibble = false
                    node_off = root_off
                else:
                    node_off = child_off
        return out

    elif comp_type == 3:  # Run-Length (0x30)
        pos = offset + 4
        out = byte[out_size]
        out_pos = 0
        while out_pos < out_size:
            flag = src[pos]; pos += 1
            if (flag & 0x80) != 0:
                run_len = (flag & 0x7F) + 3
                val = src[pos]; pos += 1
                for _ in range(run_len):
                    if out_pos >= out_size: break
                    out[out_pos] = val; out_pos += 1
            else:
                lit_len = (flag & 0x7F) + 1
                for _ in range(lit_len):
                    if out_pos >= out_size: break
                    out[out_pos] = src[pos]; pos += 1; out_pos += 1
        return out

    else:
        error("Unsupported or Diff-filter compression type")

function detect_save_media_id(rom_bytes):
    prefixes = ["EEPROM_V", "SRAM_V", "SRAM_F_V", "FLASH1M_V", "FLASH512_V", "FLASH_V"]
    matches = []
    for off in range(0, len(rom_bytes) - 12, 4):  # 4-byte aligned scan
        for p in prefixes:
            if rom_bytes[off : off + len(p)] == ascii(p):
                ver = rom_bytes[off + len(p) : off + len(p) + 3]
                if all_ascii_digits(ver):
                    matches.append((off, p + decode_ascii(ver)))
    return matches

6. Provenance & Confidence

The 32-bit BIOS compression headers, SWI 0x10–0x18 behaviors, LZ77/Huffman/RLE bit-level decoding rules, Flash 0x0E005555/0x0E002AAA command sequences, and SDK save ID string prefixes are Confirmed Hardware/BIOS Spec behaviors documented in GBATEK and verified against GBA BIOS disassembly.

Save Detection Caveats: Save ID string detection is an SDK-Revision Convention rather than a hardware register; homebrew or custom-linked ROMs without Nintendo SDK backup libraries may omit these strings entirely. Furthermore, EEPROM_Vnnn does not distinguish 512-byte (4 Kbit) from 8 KiB (64 Kbit) EEPROM chips—the size must be inferred dynamically from the bit count of the first EEPROM DMA3 transfer (9-bit vs. 17-bit header before payload).
