.gba Cartridge ROM Header, Nintendo Logo & Complement Check

Game Boy Advance · Cartridge ROM Image Header Specification

Every Game Boy Advance Game Pak ROM image begins with a fixed 192-byte (0xC0) platform header mapped at physical base address 0x08000000. The internal 16 KiB BIOS strictly enforces the ARM reset branch, the 156-byte Huffman-compressed Nintendo Logo sequence, the fixed identifier byte 0x96, and the 8-bit complement checksum before transferring control to cartridge code.

1. Identification & Scope

A raw .gba image has no external container wrapper: byte 0x00000000 of the file corresponds directly to CPU address 0x08000000 (and mirrors 0x0A000000 / 0x0C000000). The cartridge header occupies offsets 0x000–0x0BF (192 bytes) and is shared identically by Cartridge ROM images and Multiboot images, which append additional vectors at 0x0C0–0x0E3.

  • Hardware / BIOS Revisions: Identical header verification logic applies across original AGB-001, AGB-SP (AGS-001/101), Game Boy Micro (OXY-001), Game Boy Player, and Nintendo DS / DS Lite GBA-mode BIOS.
  • Magic Hex & ASCII Signatures:
    • 0x000–0x003: Typically xx xx xx EA (little-endian ARM unconditional branch opcode B target).
    • 0x004–0x09F: Exact 156-byte compressed Nintendo Logo payload (compared byte-for-byte or after BIOS decompression against the BIOS reference).
    • 0x0B2: Fixed magic byte 0x96.
    • 0x0A0–0x0B1: Uppercase ASCII Title (12 bytes), Game Code (4 bytes), and Maker Code (2 bytes).
  • Endianness Rules: All multi-byte integers and ARM7TDMI instructions in the header are stored in little-endian byte order.

2. Binary Layout Tables

Standard .gba Cartridge Header (Offsets 0x000–0x0BF, 192 Bytes)
Offset Size Type Field Description
0x000 4 B u32le ROM Entry Point 32-bit ARM instruction executed at 0x08000000 on cartridge boot; normally an unconditional branch B <start> (bits 31..24 = 0xEA).
0x004 156 B u8[156] Nintendo Logo Compressed Nintendo logo bitmap data (4-byte BIOS Huffman header omitted; supplied internally by BIOS). Must match the exact 156-byte hardware sequence.
0x0A0 12 B char[12] Game Title Uppercase ASCII title string, padded on the right with 0x00 bytes. Included in complement check.
0x0AC 4 B char[4] Game Code 4-character uppercase ASCII product identifier (T CC R: category, 2-char unique code, region/language). Included in complement check.
0x0B0 2 B char[2] Maker Code 2-character uppercase ASCII licensee/publisher code (e.g., "01" for first-party hardware vendor). Included in complement check.
0x0B2 1 B u8 Fixed Value Mandatory constant 0x96. Boot fails if any other value is present. Included in complement check.
0x0B3 1 B u8 Main Unit Code Target hardware identifier; must be 0x00 for standard GBA models. Included in complement check.
0x0B4 1 B u8 Device Type Normally 0x00. Bit 7 (0x80) identifies hardware debugging units exposing debug RAM/control; included in complement check.
0x0B5 7 B u8[7] Reserved Area Zero-filled (0x00) on standard retail ROMs. Included in complement check.
0x0BC 1 B u8 Software Version Revision number (0x00 for initial release, incremented for mask ROM revisions). Final byte covered by complement check.
0x0BD 1 B u8 Complement Check 8-bit header checksum calculated over bytes 0x0A0..0x0BC. BIOS halts if invalid.
0x0BE 2 B u16le Reserved Area Normally 0x0000. Not covered by the complement check; followed immediately at 0x0C0 by cartridge code or multiboot header.

3. Flags, Enums & Decoding Formulas

Complement Check Formula (0x0BD)

The 8-bit complement check at 0x0BD validates the 29 bytes spanning 0x0A0..0x0BC:

sum = 0
for i in 0x0A0 .. 0x0BC:
    sum = (sum + rom[i]) & 0xFF
expected_complement = (-(sum + 0x19)) & 0xFF
# Equivalently:
# expected_complement = (0x100 - ((sum + 0x19) & 0xFF)) & 0xFF
# Verification condition:
# (sum + 0x19 + rom[0x0BD]) & 0xFF == 0

ARM Entrypoint Branch Decoding (0x000)

The 32-bit little-endian instruction at 0x000 is evaluated in ARM state at PC = 0x08000000 (with ARM7TDMI 2-stage pipeline prefetch offset +8):

word0 = read_u32le(rom, 0x000)
cond_and_op = (word0 >> 24) & 0xFF    # 0xEA = unconditional ARM B
imm24 = word0 & 0x00FFFFFF
if (imm24 & 0x00800000) != 0:
    offset_words = imm24 - 0x01000000  # sign-extend 24-bit value
else:
    offset_words = imm24
target_address = (0x08000000 + 8 + (offset_words << 2)) & 0xFFFFFFFF
Header Control Byte Encodings (0x0B2–0x0B4)
Offset Value / Mask Meaning
0x0B2 0x96 Required fixed identifier byte; any other value causes BIOS boot failure.
0x0B3 0x00 Standard Game Boy Advance main unit code.
0x0B4 0x00 Normal retail cartridge / non-debug unit.
0x0B4 0x80 (bit 7) Hardware debugger flag; indicates AGB debug monitor/DACS target support (bits 0..6 reserved).

4. Edge Cases & Loader/Parser Rules

  • Minimum & Maximum Size Bounds: A valid ROM image must be at least 0xC0 (192) bytes to hold the header, and cannot exceed 32 MiB (0x02000000 bytes) in the standard 0x08000000–0x09FFFFFF Game Pak aperture.
  • ROM Mirroring & Open-Bus Reads: Commercial Game Pak ROMs are typically power-of-two sizes (4 MiB, 8 MiB, 16 MiB, 32 MiB). Addresses beyond the physical mask ROM size mirror the ROM or return Game Pak open-bus values ((address >> 1) & 0xFFFF on the multiplexed 16-bit address/data bus).
  • Cartridge GPIO / RTC Overlap at 0x080000C4–0x080000C9: Cartridges containing General Purpose I/O peripherals (such as Real-Time Clocks, solar sensors, or rumble motors) expose three 16-bit write/read registers at 0x080000C4 (Data), 0x080000C6 (Direction), and 0x080000C8 (Control). When GPIO read-back is enabled, reads at 0x080000C4..0x080000C9 return GPIO pins rather than ROM data; normal parsers reading raw .gba files still see the underlying ROM bytes at 0x0C4..0x0C9.
  • Entrypoint vs. Multiboot Coexistence: Dual-purpose images sometimes populate both 0x000 (cartridge reset branch) and 0x0C0 (multiboot RAM branch). A cartridge ROM parser treats 0x000 as the primary reset vector mapped at 0x08000000 and only inspects 0x0C0 if checking for multiboot capability.
  • Strict Logo Verification: Real GBA BIOS hardware decompresses the 156 bytes at 0x004–0x09F (prepending its internal Huffman header) and compares the result; in practice, only the exact 156-byte sequence above passes hardware boot. Note that some development/BIOS-bypass contexts skip logo validation, so static parsers should report logo mismatch as a validation failure rather than aborting header field extraction.
  • Generalized Loader Mapping: Load the raw ROM linearly at virtual/physical base 0x08000000 (and mirror to 0x0A000000 and 0x0C000000). Do not apply emulator-specific save patching or game-specific overrides at header parse time.

function parse_gba_rom_header(bytes):
    if len(bytes) < 0xC0:
        error("File smaller than 192-byte GBA ROM header")
    if len(bytes) > 0x02000000:
        warn("ROM exceeds 32 MiB Game Pak window (0x08000000..0x09FFFFFF)")

    entry_opcode = read_u32le(bytes, 0x000)
    is_arm_branch = ((entry_opcode >> 24) & 0xFF) == 0xEA
    entry_target = null
    if is_arm_branch:
        imm24 = entry_opcode & 0x00FFFFFF
        if (imm24 & 0x00800000) != 0:
            imm24 -= 0x01000000
        entry_target = (0x08000000 + 8 + (imm24 << 2)) & 0xFFFFFFFF

    logo_valid = (bytes[0x004 : 0x0A0] == NINTENDO_LOGO_BYTES)

    title_raw  = bytes[0x0A0 : 0x0AC]
    title      = decode_ascii_trim_null(title_raw)
    game_code  = decode_ascii(bytes[0x0AC : 0x0B0])
    maker_code = decode_ascii(bytes[0x0B0 : 0x0B2])

    fixed_byte   = bytes[0x0B2]
    main_unit    = bytes[0x0B3]
    device_type  = bytes[0x0B4]
    reserved_b5  = bytes[0x0B5 : 0x0BC]
    sw_version   = bytes[0x0BC]
    complement   = bytes[0x0BD]
    reserved_be  = read_u16le(bytes, 0x0BE)

    # Complement check over 0x0A0..0x0BC
    sum_bytes = 0
    for i in range(0x0A0, 0x0BD):
        sum_bytes = (sum_bytes + bytes[i]) & 0xFF
    expected_complement = (-(sum_bytes + 0x19)) & 0xFF
    checksum_valid = (complement == expected_complement)

    # Generalized loader mapping
    rom_map_size = min(len(bytes), 0x02000000)
    map_region(base=0x08000000, data=bytes[0 : rom_map_size])  # WS0
    map_region(base=0x0A000000, data=bytes[0 : rom_map_size])  # WS1 mirror
    map_region(base=0x0C000000, data=bytes[0 : rom_map_size])  # WS2 mirror

    return {
        entry_opcode, is_arm_branch, entry_target,
        logo_valid, title, game_code, maker_code,
        fixed_byte_valid = (fixed_byte == 0x96),
        main_unit, device_type, sw_version,
        complement, expected_complement, checksum_valid
    }

6. Provenance & Confidence

Header offsets 0x000–0x0BF, the 156-byte Huffman logo sequence, the fixed byte 0x96, the complement check over 0x0A0–0x0BC, and the 32 MiB 0x08000000 ROM mapping are Confirmed Hardware/BIOS Spec behaviors verified against GBA BIOS ROM execution and GBATEK documentation.

Reserved & Peripheral Caveats: Fields at 0x0B5–0x0BB and 0x0BE–0x0BF are reserved/zero-filled on standard retail cartridges (Reserved); hardware debugging flags at 0x0B4 bit 7 and cartridge-specific GPIO registers at 0x080000C4–0x080000C9 depend on cartridge PCB hardware rather than the base Game Pak ROM specification. Additionally, save media type is not stored in the 192-byte header and must be identified separately via SDK save ID strings.
