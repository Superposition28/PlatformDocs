.mb Multiboot Header & Link / JoyBus Boot Protocol

Game Boy Advance · EWRAM Multiboot Image & Transfer Protocol Specification

Game Boy Advance Multiboot images allow a slave GBA without a cartridge (or holding START+SELECT) to receive and execute up to ~256 KiB of code directly in External Work RAM (0x02000000) over the Link Cable (Normal or MultiPlay mode via BIOS SWI 0x25) or a JoyBus host link. The format extends the standard 192-byte cartridge header with RAM and JoyBus branch entrypoints at 0x0C0–0x0E3.

Canonical Filenames
*.mb (standalone Multiboot binary), *.gba / *.bin (dual-boot or EWRAM-linked image)
Magic Bytes
Standard header (0x0B2 == 0x96, 156-byte logo) plus ARM branch 0xEAxxxxxx at 0x0C0 (Normal/MultiPlay) and/or 0x0E0 (JoyBus)
Endianness
Little-Endian in EWRAM image; SIO/JoyBus serial transfers exchange 16-bit and 32-bit little-endian words

Nintendo Game Boy Advance BIOS (SWI 0x25 MultiBoot & slave ROM bootloader), loaded at 0x02000000
Role/MIME
RAM-resident link-bootable executable image (application/x-gba-multiboot, unofficial)

1. Identification & Scope

A Multiboot image shares the exact first 0xC0 (192) bytes of a .gba Cartridge ROM Header and appends a 36-byte extended multiboot header from 0x0C0 to 0x0E3. Unlike cartridge ROMs mapped at 0x08000000, Multiboot images are copied into the 256 KiB External Work RAM window at 0x02000000–0x0203FFFF.

  • Transfer Scope: The initial 192-byte header (0x000–0x0BF) is exchanged unencrypted during the Link Cable handshake so the slave BIOS can verify the Nintendo Logo and complement check; the body starting at 0x0C0 (up to 0x3FF40 bytes) is transferred encrypted by BIOS SWI 0x25 (MultiBoot).
  • Dual-Purpose Images: Many builds place an ARM branch at 0x000 (if booted from ROM) and a second ARM branch at 0x0C0 (if booted from EWRAM via Multiboot).
  • Endianness Rules: All fields inside the .mb image and MultiBootParam structure are little-endian.

2. Binary Layout Tables

Extended Multiboot Header (Offsets 0x0C0–0x0E3, Following 0x000–0x0BF Shared Header)
Offset Size Type Field Description
0x000 192 B Header Standard GBA Header Identical to .gba header (0x000–0x0BF): ROM entrypoint, 156-byte logo, title, game/maker codes, 0x96, complement check.
0x0C0 4 B u32le RAM Entry Point ARM branch opcode (B <ram_start>, 0xEAxxxxxx) executed at 0x020000C0 when booted via Normal or MultiPlay mode.
0x0C4 1 B u8 Boot Mode Initialize to 0x00 in image. Overwritten by slave BIOS before jump: 0x01 = JoyBus, 0x02 = Normal, 0x03 = MultiPlay.
0x0C5 1 B u8 Slave / Client ID Initialize to 0x00 in image. Overwritten by BIOS in Normal/MultiPlay mode with slave number (0x01, 0x02, or 0x03); untouched in JoyBus mode.
0x0C6 26 B u8[26] Reserved / Unused Zero-filled padding up to 0x0DF. Do not place code at 0x0C4–0x0C5 as BIOS overwrites those bytes.
0x0E0 4 B u32le JoyBus Entry Point ARM branch opcode (B <joy_start>, 0xEAxxxxxx) executed at 0x020000E0 when booted via JoyBus mode.

Link Cable MultiBoot Handshake & Transfer Sequence (16-bit MultiPlay Frames)
Step Master Sends Slave Replies Protocol Role
1 0x6200 0xFFFF / 0x0000 / 0x720x Poll for connected slaves; 0x720x identifies slave bitmask x (clients 1..3).
2 0x610y 0x720x Confirm recognized client mask y.
3 hdr[0x00..0xBE] 0x000x Transfer 96 halfwords (0xC0-byte header) unencrypted; slave verifies logo and complement check.
4 0x6200 / 0x620y 0x000x / 0x720x Confirm header receipt and re-exchange client status.
5 0x63pp 0x73cc Master sends palette_data (pp); slaves return client_data (cc) for encryption seed m.
6 0x64hh 0x73rr Master sends handshake_data (hh); slaves return random bytes (rr) for final CRC seed f.
7 SWI 0x25 stream Ack / echo Encrypted 32-bit words from 0x0C0 to boot_endp (sent as 32-bit in Normal mode or 2×16-bit in MultiPlay).
8 0x0065 / 0x0066 + CRC16 0x0075 / CRC16 Both sides exchange 16-bit CRC; on match, slaves stamp 0x020000C4..C5 and jump to 0x020000C0.

3. Flags, Enums & Decoding Formulas

Boot Mode (0x0C4), Client ID (0x0C5) & JoyBus Command Bytes
Subsystem Value Meaning
Boot Mode (0x0C4) 0x01 Booted via JoyBus mode (jumps to 0x020000E0).
Boot Mode (0x0C4) 0x02 Booted via Normal 32-bit SIO mode (jumps to 0x020000C0).
Boot Mode (0x0C4) 0x03 Booted via MultiPlay 16-bit mode (jumps to 0x020000C0).
Client ID (0x0C5) 0x01..0x03 Slave player index assigned by BIOS in Normal/MultiPlay modes (0x0C5 is not overwritten in JoyBus mode).
JoyBus Cmd 0x00 Reset / Status: Resets JoyBus state and returns 16-bit device ID + JSTAT status byte.
JoyBus Cmd 0x14 Read (JOY_TRANS): Host reads 4 bytes written by GBA into 0x04000154 + JSTAT.
JoyBus Cmd 0x15 Write (JOY_RECV): Host writes 4 bytes into GBA 0x04000150 and receives JSTAT.

4. Edge Cases & Loader/Parser Rules

  • Payload Size Bounds & Alignment: Transfer body length (boot_endp - boot_srcp, excluding the initial 0xC0 header) must be a multiple of 0x10 bytes, with a minimum of 0x100 bytes and a maximum of 0x3FF40 bytes (total image max 0x40000 = 256 KiB, fitting entirely in EWRAM 0x02000000–0x0203FFFF).
  • ROM vs. Multiboot Entrypoint Branching: Static analyzers and loaders must check which entrypoint is valid. A pure .mb image may contain a placeholder or dummy loop at 0x000 and its real ARM branch at 0x0C0 (with base address 0x02000000). Conversely, a JoyBus-only boot targets 0x020000E0.
  • BIOS Overwrite of 0x020000C4–0x020000C5: Executable instructions or constants placed at offsets 0x0C4–0x0C5 will be clobbered by the slave BIOS before jumping to 0x020000C0 or 0x020000E0.
  • Logo & Complement Check Still Apply: Even though Multiboot runs from EWRAM, the slave BIOS still checks the 156-byte Nintendo Logo, fixed byte 0x96 at 0x0B2, and complement check at 0x0BD during the unencrypted header phase.
  • Generalized EWRAM Loader Mapping: Map the full .mb binary (0x000..len) starting at EWRAM base 0x02000000 (not 0x08000000), initialize simulated BIOS stamp bytes 0x020000C4 (boot mode) and 0x020000C5 (client ID), and branch in ARM state to 0x020000C0 (or 0x020000E0 for JoyBus).

5. Step-by-Step Parser Pseudocode

function parse_and_load_multiboot(bytes, boot_mode = 0x02, client_id = 0x01):
    if len(bytes) < 0x1C0:
        error("Image too small for 0xC0 header + 0x100 minimum Multiboot payload")
    if len(bytes) > 0x40000:
        error("Multiboot image exceeds 256 KiB EWRAM capacity (0x40000 bytes)")

    body_size = len(bytes) - 0x0C0
    if (body_size % 0x10) != 0:
        warn("Multiboot payload length (len - 0xC0) is not 16-byte aligned")

    # Validate shared 0x000..0x0BF header fields
    rom_hdr = parse_gba_rom_header(bytes[0x000 : 0x0C0])
    if not rom_hdr.logo_valid or not rom_hdr.fixed_byte_valid or not rom_hdr.checksum_valid:
        warn("Multiboot header failed BIOS logo / 0x96 / complement validation")

    ram_branch = read_u32le(bytes, 0x0C0)
    joy_branch = read_u32le(bytes, 0x0E0) if len(bytes) >= 0x0E4 else 0

    function decode_ewram_branch(opcode, pc_addr):
        if ((opcode >> 24) & 0xFF) != 0xEA:
            return null
        imm24 = opcode & 0x00FFFFFF
        if (imm24 & 0x00800000) != 0:
            imm24 -= 0x01000000
        return (pc_addr + 8 + (imm24 << 2)) & 0xFFFFFFFF

    ram_target = decode_ewram_branch(ram_branch, 0x020000C0)
    joy_target = decode_ewram_branch(joy_branch, 0x020000E0)

    # Generalized EWRAM loader mapping
    map_region(base=0x02000000, data=bytes[0 : len(bytes)])
    write_u8(0x020000C4, boot_mode)   # 0x01=JoyBus, 0x02=Normal, 0x03=MultiPlay
    if boot_mode in (0x02, 0x03):
        write_u8(0x020000C5, client_id)

    start_pc = 0x020000E0 if boot_mode == 0x01 else 0x020000C0
    return { rom_hdr, ram_target, joy_target, start_pc, body_size }

6. Provenance & Confidence

The extended header layout (0x0C0–0x0E3), BIOS SWI 0x25 MultiBootParam offsets, payload size limits (0x100..0x3FF40), Normal/MultiPlay handshake frames, and the rolling encryption/CRC16 formulas are Confirmed Hardware/BIOS Spec details established by GBA BIOS disassembly and GBATEK documentation.

Reserved & Protocol Caveats: Fields marked reserved1, reserved2, reserved3, and system_work2 in MultiBootParam are BIOS-internal scratch areas (Reserved) and should not be read or modified by user code after invoking SWI 0x25. For JoyBus transfers, timing requirements and host-side poll intervals depend on the external JoyBus master hardware (e.g., GameCube SIO) rather than fixed GBA BIOS delays.
