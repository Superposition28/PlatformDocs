1. Identification & Scope

This document covers two foundational Windows platform container formats:

  • MSF 7.0 / Program Database (.pdb): Multi-Stream File (MSF) version 7.00 identified by the 32-byte ASCII+control magic Microsoft C/C++ MSF 7.00\r\n\x1ADS\0\0\0 at offset 0x00. Linked PE images reference their matching PDB via an IMAGE_DEBUG_DIRECTORY entry of type 2 (IMAGE_DEBUG_TYPE_CODEVIEW) carrying an RSDS (0x53445352) record.
  • OLE Compound File Binary (CFB / .msi): Structured Storage container ([MS-CFB]) identified by the 8-byte signature D0 CF 11 E0 A1 B1 1A E1 at offset 0x00. Windows Installer packages (.msi), patches (.msp), and merge modules (.msm) store relational installer tables, string pools, and embedded CAB archives as CFB streams.

All integer fields in both formats are little-endian. Note that 16-byte Microsoft GUIDs serialize their first three components in little-endian (Data1: u32le, Data2: u16le, Data3: u16le) and the final 8 bytes (Data4) in big-endian byte order.

4. Edge Cases & Loader/Parser Rules

  • MSF Discontiguous Streams & Free Page Maps: Any stream (including the Stream Directory itself) may span non-contiguous pages. When allocating or walking FPM blocks, note that FPM blocks appear periodically every BlockSize pages (each FPM block holds BlockSize * 8 bits, covering one interval of BlockSize or BlockSize * 8 pages depending on tooling).
  • Portable PDB vs. Native MSF 7.0 PDB: .NET Portable PDBs use ECMA-335 CLI metadata streams starting with magic BSJB (0x424A5342) rather than MSF 7.0, even though both share the .pdb extension and PE RSDS pointer.
  • CFB v3 Header Size & StreamSize Masking: Version 3 CFB files have 512-byte sectors, yet v4 files have 4096-byte sectors (the 512-byte header is zero-padded to 4096 bytes). In v3 files, the upper 32 bits of StreamSize may contain garbage in legacy writers and should be masked with & 0xFFFFFFFF.
  • MSI Compressed Stream Names: Windows Installer .msi databases encode table and string-pool stream names in CFB using a 6-bit Base64-like Unicode range (U+3800..U+4840), where characters in [0x3800..0x47FF] pack two 6-bit symbols per 16-bit char and [0x4800..0x483F] encodes one 6-bit symbol.

5. Complete Step-by-Step Parser Pseudocode

function parse_msf7(buf: bytes) -> dict:
    magic = b"Microsoft C/C++ MSF 7.00\r\n\x1aDS\x00\x00\x00"
    require(len(buf) >= 0x38 and buf[0:32] == magic, "invalid MSF 7.00 magic")

    block_size    = u32le(buf, 0x20)
    num_blocks    = u32le(buf, 0x28)
    dir_bytes     = u32le(buf, 0x2C)
    block_map_pg  = u32le(buf, 0x34)
    require(block_size in [512, 1024, 2048, 4096], "invalid BlockSize")
    require(num_blocks * block_size <= len(buf), "truncated MSF file")

    n_dir_pages = (dir_bytes + block_size - 1) // block_size
    bm_off = block_map_pg * block_size
    dir_buf = bytearray()
    for i in range(n_dir_pages):
        pg = u32le(buf, bm_off + i * 4)
        dir_buf.extend(buf[pg * block_size : (pg + 1) * block_size])
    dir_buf = dir_buf[0 : dir_bytes]

    num_streams = u32le(dir_buf, 0)
    sizes = [u32le(dir_buf, 4 + i * 4) for i in range(num_streams)]
    pos = 4 + num_streams * 4
    streams = []
    for sz in sizes:
        if sz == 0xFFFFFFFF:
            streams.append(null)
            continue
        pgs = (sz + block_size - 1) // block_size
        data = bytearray()
        for _ in range(pgs):
            pg = u32le(dir_buf, pos); pos += 4
            data.extend(buf[pg * block_size : (pg + 1) * block_size])
        streams.append(bytes(data[0 : sz]))

    // Match PDB Info Stream (Stream 1) against PE RSDS entry:
    s1 = streams[1]
    pdb_info = { Version: u32le(s1, 0), Signature: u32le(s1, 4), Age: u32le(s1, 8), Guid: s1[12:28] }
    return { info: pdb_info, streams: streams }

function parse_cfb_header(buf: bytes) -> dict:
    require(len(buf) >= 512 and buf[0:8] == b"\xD0\xCF\x11\xE0\xA1\xB1\x1A\xE1", "invalid CFB magic")
    require(u16le(buf, 0x1C) == 0xFFFE, "expected little-endian CFB")
    sec_shift = u16le(buf, 0x1E)
    sec_size = 1 << sec_shift
    return {
        MajorVersion:    u16le(buf, 0x1A),
        SectorSize:      sec_size,
        MiniSectorSize:  1 << u16le(buf, 0x20),
        NumFATSectors:   u32le(buf, 0x2C),
        FirstDirSector:  u32le(buf, 0x30),
        MiniCutoff:      u32le(buf, 0x38),
        FirstMiniFAT:    u32le(buf, 0x3C),
        FirstDIFAT:      u32le(buf, 0x44),
        DIFAT0:          [u32le(buf, 0x4C + i * 4) for i in range(109)],
    }

6. Provenance & Confidence

Confirmed Specifications: PE CodeView RSDS and IMAGE_DEBUG_DIRECTORY are defined in the Microsoft PE Format spec; OLE Compound File Binary is formally specified in Microsoft Open Specifications [MS-CFB]; MSF 7.0 / PDB SuperBlock, PDB Info, TPI, DBI, and IPI headers are confirmed in Microsoft's published microsoft-pdb reference repository and LLVM PDB documentation.

Undocumented PDB Sub-Streams Caveat: While the MSF 7.0 container, PDB Info, TPI/IPI headers, and DBI fixed header are well-documented, several toolchain-internal DBI substreams (such as Edit-and-Continue ECSubstream, linker Fixup/Omap tables, and incremental NamedStreamMap hash internals) are toolchain-version-specific and not guaranteed stable across MSVC/LLVM releases.
