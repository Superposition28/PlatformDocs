Architecture & Win32/Win64 Loader Model

Windows NT separates executables into on-disk FileAlignment blocks (typically 0x0200 bytes) and in-memory SectionAlignment pages (typically 0x1000 bytes, 4 KiB). Every linked PE image is a self-describing virtual memory snapshot anchored at a preferred ImageBase.

  1. Header Validation & Mapping: The kernel/user loader (MmCreateSection / ntdll!LdrInitializeThunk) verifies the DOS MZ header, follows e_lfanew to the PE\0\0 signature, validates the COFF Machine and Optional Header Magic (0x010B for PE32, 0x020B for PE32+), and maps headers plus section raw bytes into virtual pages, zero-filling any VirtualSize > SizeOfRawData tail.
  2. ASLR & Base Relocation: When IMAGE_DLLCHARACTERISTICS_DYNAMIC_BASE is set or a base collision occurs, the loader maps the module at a new base and processes DataDirectory[5] (.reloc) to patch absolute virtual addresses by delta = ActualBase - ImageBase.
  3. Import Resolution & API Sets: The loader walks DataDirectory[1] (Import Directory Table), resolves dependency DLL names (including Win10/11 API Set forwarders such as api-ms-win-*), looks up functions by hint/name or ordinal in the callee's Export Directory (DataDirectory[0]), and writes resolved virtual addresses into the Import Address Table (IAT), then marks read-only IAT pages non-writable.
  4. Exception, TLS & Security Initialization: On x64 and ARM64, the loader registers DataDirectory[3] (.pdata RUNTIME_FUNCTION tables) for stack unwinding and SEH. If DataDirectory[9] (.tls) is present, it allocates per-thread TLS slots and invokes registered TLS callbacks prior to calling AddressOfEntryPoint.
  5. Distribution, Resources & Symbols: Standard Win32 metadata lives in .rsrc (version blocks, SxS manifests, icons), Authenticode PKCS#7 signatures in DataDirectory[4], CodeView RSDS debug pointers in DataDirectory[6] linking to external .pdb (MSF 7.0) symbol files, and system installers in .msi OLE Compound File databases.
