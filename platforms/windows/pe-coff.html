Portable Executable & COFF Header Layout (.exe / .dll)

Executable Format · Windows NT PE32 / PE32+

Microsoft's Portable Executable (PE) format wraps COFF object headers in an MS-DOS MZ compatibility header and defines the virtual memory layout, section mapping, and 16 data directory slots used by Windows x86, x86-64, and ARM64 binaries.

Canonical Filenames
.exe, .dll, .sys, .ocx, .scr, .cpl, .efi (UEFI subset), .mui
Magic Bytes
4D 5A ("MZ" at 0x00); 50 45 00 00 ("PE\0\0" at e_lfanew); Optional Header 0x010B (PE32) or 0x020B (PE32+)

1. Identification & Scope

A valid Windows PE image is identified in three stages rather than by a single offset-zero signature:

  1. DOS MZ Header (0x00): Bytes 0x00..0x01 must be 0x4D 0x5A ("MZ", read as u16le 0x5A4D). The 32-bit little-endian offset e_lfanew at 0x3C points to the PE header.
  2. PE Signature (e_lfanew): Four bytes at e_lfanew must equal 0x50 0x45 0x00 0x00 ("PE\0\0", u32le 0x00004550). Legacy 16-bit NE ("NE"), LE ("LE"), and LX ("LX") headers share the MZ/0x3C pointer mechanism but lack PE\0\0.
  3. Optional Header Magic (e_lfanew + 0x18): Distinguishes 32-bit PE32 (0x010B) from 64-bit PE32+ (0x020B), which widens ImageBase and stack/heap sizes from u32le to u64le and omits BaseOfData.

All fields in PE/COFF headers are strictly little-endian. Section names in linked images are fixed 8-byte UTF-8/ASCII buffers (zero-padded if shorter than 8 bytes, not necessarily null-terminated if exactly 8 bytes).

RVA-to-File-Offset Translation Formula

mapped_size(sec) = (sec.VirtualSize != 0) ? sec.VirtualSize : sec.SizeOfRawData
if rva < OptionalHeader.SizeOfHeaders:
    return rva  // falls within mapped PE headers
for sec in Sections:
    if sec.VirtualAddress <= rva < sec.VirtualAddress + mapped_size(sec):
        delta = rva - sec.VirtualAddress
        if delta >= sec.SizeOfRawData or sec.PointerToRawData == 0:
            return UNMAPPED_ZERO_FILL  // virtual BSS / zero-padded tail
        return sec.PointerToRawData + delta
return INVALID_RVA

4. Edge Cases & Loader/Parser Rules

  • FileAlignment vs. SectionAlignment: In standard executables, FileAlignment == 0x200 and SectionAlignment == 0x1000. When SectionAlignment < PageSize (e.g., native drivers or compact images with SectionAlignment == FileAlignment), Windows maps the raw file directly without re-aligning sections, and VirtualAddress must equal PointerToRawData.
  • VirtualSize > SizeOfRawData (Zero-Fill): Common in .data sections that merge initialized globals with trailing .bss. Disk bytes end at PointerToRawData + SizeOfRawData; the loader zeroes [VirtualAddress + SizeOfRawData, VirtualAddress + VirtualSize) in memory. Conversely, SizeOfRawData > VirtualSize occurs due to FileAlignment padding on disk; bytes beyond VirtualSize are disk padding.
  • Truncated NumberOfRvaAndSizes: Although 16 is standard, packed or minimal images may declare fewer than 16 entries (or more, though Windows ignores indices ≥ 16). Always check index < NumberOfRvaAndSizes and verify directory bounds inside SizeOfOptionalHeader.
  • Rich Header (MSVC Linker Metadata): Linkers since Visual Studio 6.0 insert an undocumented XOR-encoded block between the DOS stub and e_lfanew, ending with "Rich" (0x68636952) + 4-byte XOR mask key. Every preceding u32le word back to the decoded "DanS" (0x536E6144) marker is XORed with that key. The Windows loader completely ignores bytes between 0x40 and e_lfanew.
  • Generalized Loader Mapping Scope: This specification covers header parsing and section virtual mapping only; actual instruction execution, Win32 subsystem initialization, and application runtime behavior are outside this document.

5. Complete Step-by-Step Parser Pseudocode

function parse_pe(buf: bytes) -> PEImage:
    require(len(buf) >= 0x40, "truncated DOS header")
    require(u16le(buf, 0x00) == 0x5A4D, "missing MZ magic")

    pe_off = u32le(buf, 0x3C)
    require(pe_off >= 0x40 and pe_off + 24 <= len(buf), "invalid e_lfanew")
    require(buf[pe_off : pe_off + 4] == b"PE\x00\x00", "missing PE signature")

    coff_off = pe_off + 4
    coff = {
        Machine:              u16le(buf, coff_off + 0x00),
        NumberOfSections:     u16le(buf, coff_off + 0x02),
        TimeDateStamp:        u32le(buf, coff_off + 0x04),
        PointerToSymbolTable: u32le(buf, coff_off + 0x08),
        NumberOfSymbols:      u32le(buf, coff_off + 0x0C),
        SizeOfOptionalHeader: u16le(buf, coff_off + 0x10),
        Characteristics:      u16le(buf, coff_off + 0x12),
    }

    opt_off = coff_off + 20
    require(opt_off + coff.SizeOfOptionalHeader <= len(buf), "truncated Optional Header")
    require(coff.SizeOfOptionalHeader >= 2, "missing Optional Header magic")

    magic = u16le(buf, opt_off)
    is_pe32_plus = (magic == 0x020B)
    require(magic == 0x010B or is_pe32_plus, "unsupported Optional Header magic")

    min_opt = is_pe32_plus ? 112 : 96
    require(coff.SizeOfOptionalHeader >= min_opt, "short Optional Header")

    opt = {
        Magic:               magic,
        AddressOfEntryPoint: u32le(buf, opt_off + 0x10),
        ImageBase:           is_pe32_plus ? u64le(buf, opt_off + 0x18) : u32le(buf, opt_off + 0x1C),
        SectionAlignment:    u32le(buf, opt_off + 0x20),
        FileAlignment:       u32le(buf, opt_off + 0x24),
        SizeOfImage:         u32le(buf, opt_off + 0x38),
        SizeOfHeaders:       u32le(buf, opt_off + 0x3C),
        CheckSum:            u32le(buf, opt_off + 0x40),
        Subsystem:           u16le(buf, opt_off + 0x44),
        DllCharacteristics:  u16le(buf, opt_off + 0x46),
        NumberOfRvaAndSizes: is_pe32_plus ? u32le(buf, opt_off + 0x6C) : u32le(buf, opt_off + 0x5C),
    }

    dd_off = opt_off + (is_pe32_plus ? 0x70 : 0x60)
    max_dd = (coff.SizeOfOptionalHeader - (dd_off - opt_off)) // 8
    dd_count = min(opt.NumberOfRvaAndSizes, max_dd, 16)
    data_dirs = []
    for i in range(dd_count):
        data_dirs.append({
            VirtualAddress: u32le(buf, dd_off + i * 8 + 0),
            Size:           u32le(buf, dd_off + i * 8 + 4),
        })

    sec_off = opt_off + coff.SizeOfOptionalHeader
    require(sec_off + coff.NumberOfSections * 40 <= len(buf), "truncated Section Headers")
    sections = []
    for i in range(coff.NumberOfSections):
        s = sec_off + i * 40
        sections.append({
            Name:             rstrip_zeros(buf[s : s + 8]).decode("utf-8", errors="replace"),
            VirtualSize:      u32le(buf, s + 0x08),
            VirtualAddress:   u32le(buf, s + 0x0C),
            SizeOfRawData:    u32le(buf, s + 0x10),
            PointerToRawData: u32le(buf, s + 0x14),
            Characteristics:  u32le(buf, s + 0x24),
        })

    return PEImage(coff, opt, data_dirs, sections)

6. Provenance & Confidence

Confirmed Specification: All offsets, types, magic constants, machine IDs, section flags, and IMAGE_OPTIONAL_HEADER32/64 layouts are directly documented in Microsoft's official PE Format specification and Windows SDK winnt.h.

Toolchain & Undocumented Internals Caveat: The Rich header embedded between the DOS stub and e_lfanew is an undocumented Microsoft link.exe artifact rather than part of the PE/COFF standard; binaries produced by LLVM lld-link, MinGW/GCC, or stripped post-build tools may omit it or alter its entries. Likewise, TimeDateStamp no longer represents a wall-clock build time when deterministic linking (/Brepro) is enabled.
