PE Data Directories: Imports, Exports, Relocations, TLS, Exceptions & Authenticode

Executable Sub-Tables · PE32 / PE32+ DataDirectory[0,1,3,4,5,9,13]

Binary structures referenced by the PE Optional Header's DataDirectory array to resolve dynamic imports/exports, rebase ASLR images, initialize thread-local storage, unwind exceptions, and verify Authenticode signatures.

1. Identification & Scope

Each loader table is located by reading { VirtualAddress, Size } from OptionalHeader.DataDirectory[slot]. For slots 0, 1, 3, 5, 9, and 13, VirtualAddress is an RVA translated through the section table; for slot 4 (Certificate Table), VirtualAddress is a raw file offset outside the virtual memory map.

All table headers and array elements are little-endian. Note that Import Lookup Table (ILT) and Import Address Table (IAT) thunks as well as IMAGE_TLS_DIRECTORY pointers are 32-bit in PE32 (0x010B) and 64-bit in PE32+ (0x020B).

4. Edge Cases & Loader/Parser Rules

  • Forwarded Exports: In AddressOfFunctions[i], if export_rva falls strictly inside [DataDir[0].VirtualAddress, DataDir[0].VirtualAddress + DataDir[0].Size), the entry is not code — it is an RVA to a null-terminated ASCII forwarder string (e.g. "KERNELBASE.CreateFileW" or "NTDLL.#42").
  • Ordinal-Only Exports: NumberOfFunctions can exceed NumberOfNames, and slots in AddressOfFunctions can be 0 (unused ordinal gaps). Only exports present in AddressOfNameOrdinals have symbolic names.
  • Authenticode Raw File Offset Quirk: Unlike all other data directories, DataDirectory[4].VirtualAddress is an absolute file offset, not an RVA. Multiple stacked certificates inside DataDirectory[4] must be iterated by advancing align_up(dwLength, 8) until DataDirectory[4].Size is exhausted. Authenticode hashing excludes the 4-byte PE CheckSum, the 8-byte DataDirectory[4] slot, and the certificate table bytes.
  • TLS Callback Array Termination: TLS directories store full VAs rather than RVAs, so parsers must subtract ImageBase (and apply relocations if rebased) before RVA lookup. Empty callback arrays either have AddressOfCallBacks == 0 or point directly to a 0 pointer sentinel.
  • Generalized Loader Scope: Only static directory structures and generalized Win32/Win64 resolution semantics are described; runtime API Set schema tables (apisetschema.dll) and kernel-mode Driver Signing enforcement details vary by OS build.

5. Complete Step-by-Step Parser Pseudocode

function parse_imports(buf: bytes, pe: PEImage) -> list:
    dd = pe.data_dirs[1]
    if dd.VirtualAddress == 0: return []
    off = rva_to_offset(pe, dd.VirtualAddress)
    imports = []
    while off + 20 <= len(buf):
        ilt_rva  = u32le(buf, off + 0x00)
        name_rva = u32le(buf, off + 0x0C)
        iat_rva  = u32le(buf, off + 0x10)
        if ilt_rva == 0 and name_rva == 0 and iat_rva == 0:
            break
        dll_name = read_cstr(buf, rva_to_offset(pe, name_rva))
        thunk_rva = (ilt_rva != 0) ? ilt_rva : iat_rva
        thunk_off = rva_to_offset(pe, thunk_rva)
        step = pe.is_pe32_plus ? 8 : 4
        ord_flag = pe.is_pe32_plus ? (1 << 63) : (1 << 31)
        syms = []
        while true:
            val = pe.is_pe32_plus ? u64le(buf, thunk_off) : u32le(buf, thunk_off)
            if val == 0: break
            if (val & ord_flag) != 0:
                syms.append({ ordinal: val & 0xFFFF })
            else:
                hint_off = rva_to_offset(pe, val & 0x7FFFFFFF)
                syms.append({ hint: u16le(buf, hint_off), name: read_cstr(buf, hint_off + 2) })
            thunk_off += step
        imports.append({ dll: dll_name, symbols: syms })
        off += 20
    return imports

function parse_exports(buf: bytes, pe: PEImage) -> list:
    dd = pe.data_dirs[0]
    if dd.VirtualAddress == 0: return []
    ed = rva_to_offset(pe, dd.VirtualAddress)
    base    = u32le(buf, ed + 0x10)
    n_funcs = u32le(buf, ed + 0x14)
    n_names = u32le(buf, ed + 0x18)
    eat_off = rva_to_offset(pe, u32le(buf, ed + 0x1C))
    ent_off = rva_to_offset(pe, u32le(buf, ed + 0x20))
    eot_off = rva_to_offset(pe, u32le(buf, ed + 0x24))

    name_by_idx = {}
    for i in range(n_names):
        idx = u16le(buf, eot_off + i * 2)
        name_rva = u32le(buf, ent_off + i * 4)
        name_by_idx[idx] = read_cstr(buf, rva_to_offset(pe, name_rva))

    exports = []
    for idx in range(n_funcs):
        func_rva = u32le(buf, eat_off + idx * 4)
        if func_rva == 0: continue
        is_fwd = (dd.VirtualAddress <= func_rva < dd.VirtualAddress + dd.Size)
        exports.append({
            ordinal:   base + idx,
            name:      name_by_idx.get(idx, null),
            rva:       is_fwd ? null : func_rva,
            forwarder: is_fwd ? read_cstr(buf, rva_to_offset(pe, func_rva)) : null,
        })
    return exports

6. Provenance & Confidence

Confirmed Specification: Import/Export descriptors, Base Relocations, TLS directories, x64/ARM64 RUNTIME_FUNCTION records, and WIN_CERTIFICATE headers are documented in Microsoft's PE Format specification, x64/ARM64 ABI documentation, and Authenticode PE Signing Specification.

Platform & Crypto Caveats: Modern Windows executables may carry dual SHA-1 + SHA-256 nested signatures inside a single WIN_CERTIFICATE PKCS#7 blob (szOID_NESTED_SIGNATURE) and page-hash tables for fast validation. Full X.509/PKCS#7 trust verification depends on the Windows Root Certificate store and time-stamping authorities rather than header structure alone.
