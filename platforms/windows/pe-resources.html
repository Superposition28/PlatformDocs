PE .rsrc Resource Tree, Version Info, Manifests & Icons

Executable Resource Section · DataDirectory[2]

Hierarchical 3-level resource tree embedded in Windows PE binaries (.rsrc) storing localized UI assets, VS_VERSIONINFO metadata, Side-by-Side (SxS) XML manifests, and multi-resolution icon groups.

1. Identification & Scope

The resource tree begins at the RVA given by OptionalHeader.DataDirectory[2] (normally the start of the .rsrc section). By Windows convention, the tree has exactly three directory levels:

  1. Level 1 — Type: Standard numeric RT_* ID (e.g. 3 = RT_ICON, 14 = RT_GROUP_ICON, 16 = RT_VERSION, 24 = RT_MANIFEST) or custom UTF-16LE string name.
  2. Level 2 — Name / ID: Resource identifier (integer ID or UTF-16LE string).
  3. Level 3 — Language: 16-bit Windows LANGID (e.g. 0x0409 for en-US, 0x0000 language-neutral), whose entries point to IMAGE_RESOURCE_DATA_ENTRY leaves.

All integers in .rsrc are little-endian. Directory-internal offsets (names and child directories) are relative to the start of the resource table (rsrc_base), whereas leaf OffsetToData is an RVA relative to ImageBase.

RT_MANIFEST (Type 24) SxS XML Elements

  • Resource IDs: 1 = CREATEPROCESS_MANIFEST_RESOURCE_ID (default for .exe), 2 = ISOLATIONAWARE_MANIFEST_RESOURCE_ID (default for .dll), 3 = ISOLATIONAWARE_NOSTATICIMPORT_MANIFEST_RESOURCE_ID.
  • Namespaces & Key Elements: Root <assembly xmlns="urn:schemas-microsoft-com:asm.v1" manifestVersion="1.0"> containing <trustInfo>/<security>/<requestedPrivileges>/<requestedExecutionLevel level="asInvoker|highestAvailable|requireAdministrator"/>, <compatibility>/<application>/<supportedOS Id="{...}"/>, and <application xmlns="urn:schemas-microsoft-com:asm.v3">/<windowsSettings> (dpiAwareness, longPathAware).

4. Edge Cases & Loader/Parser Rules

  • Two Different Offset Bases: Every pointer inside IMAGE_RESOURCE_DIRECTORY_ENTRY (both name offsets and child directory/data-entry offsets) is relative to the beginning of the resource directory (DataDirectory[2].VirtualAddress). Only IMAGE_RESOURCE_DATA_ENTRY.OffsetToData is a full PE RVA.
  • VS_VERSIONINFO wValueLength Unit Quirk: In binary nodes (wType == 0, such as root VS_VERSION_INFO and Var translation arrays), wValueLength is in bytes. In text String leaf nodes (wType == 1), Microsoft's resource compiler stores wValueLength in UTF-16 characters (including the null terminator), so byte length is wValueLength * 2.
  • 256×256 PNG Icons vs. DIB Icons: Starting with Windows Vista, RT_ICON entries (especially 256×256 where bWidth == 0, bHeight == 0) may hold a complete PNG file rather than a headerless DIB. Always inspect the first 8 bytes of the RT_ICON payload for 89 50 4E 47 0D 0A 1A 0A before parsing as BITMAPINFOHEADER.
  • Deeper or Cyclic Resource Trees: Although standard Win32 tools generate a strict 3-level tree, malformed or obfuscated PEs can contain deeper nesting or self-referential offsets; parsers should enforce a visited-offset set or depth cap.

5. Complete Step-by-Step Parser Pseudocode

function walk_rsrc_dir(buf: bytes, pe: PEImage, rsrc_off: int, dir_rel: int, depth: int, path: list, out: list):
    require(depth <= 8, "excessive resource tree depth")
    d = rsrc_off + dir_rel
    require(d + 16 <= len(buf), "truncated IMAGE_RESOURCE_DIRECTORY")
    n_named = u16le(buf, d + 0x0C)
    n_id    = u16le(buf, d + 0x0E)
    total   = n_named + n_id
    entries = d + 16
    require(entries + total * 8 <= len(buf), "truncated resource entries")

    for i in range(total):
        e = entries + i * 8
        name_or_id = u32le(buf, e + 0x00)
        off_to_data = u32le(buf, e + 0x04)

        if (name_or_id & 0x80000000) != 0:
            str_off = rsrc_off + (name_or_id & 0x7FFFFFFF)
            char_len = u16le(buf, str_off)
            key = buf[str_off + 2 : str_off + 2 + char_len * 2].decode("utf-16-le")
        else:
            key = name_or_id & 0xFFFF

        child_rel = off_to_data & 0x7FFFFFFF
        if (off_to_data & 0x80000000) != 0:
            walk_rsrc_dir(buf, pe, rsrc_off, child_rel, depth + 1, path + [key], out)
        else:
            de = rsrc_off + child_rel
            require(de + 16 <= len(buf), "truncated IMAGE_RESOURCE_DATA_ENTRY")
            data_rva  = u32le(buf, de + 0x00)
            data_size = u32le(buf, de + 0x04)
            data_off  = rva_to_offset(pe, data_rva)
            out.append({ path: path + [key], rva: data_rva, offset: data_off, size: data_size })

function parse_vs_fixedfileinfo(payload: bytes) -> dict|null:
    if len(payload) < 6: return null
    wLength = u16le(payload, 0x00)
    wValueLength = u16le(payload, 0x02)
    wType = u16le(payload, 0x04)
    pos, key = read_utf16le_z(payload, 0x06)
    pos = (pos + 3) & ~3
    if key != "VS_VERSION_INFO" or wValueLength < 52 or pos + 52 > len(payload):
        return null
    if u32le(payload, pos) != 0xFEEF04BD:
        return null
    return {
        file_ver:    (u16le(payload, pos+0x0A), u16le(payload, pos+0x08), u16le(payload, pos+0x0E), u16le(payload, pos+0x0C)),
        product_ver: (u16le(payload, pos+0x12), u16le(payload, pos+0x10), u16le(payload, pos+0x16), u16le(payload, pos+0x14)),
        file_flags:  u32le(payload, pos + 0x1C) & u32le(payload, pos + 0x18),
        file_os:     u32le(payload, pos + 0x20),
        file_type:   u32le(payload, pos + 0x24),
    }

6. Provenance & Confidence

Confirmed Specification: IMAGE_RESOURCE_DIRECTORY, IMAGE_RESOURCE_DIRECTORY_ENTRY, IMAGE_RESOURCE_DATA_ENTRY, VS_VERSIONINFO / VS_FIXEDFILEINFO, SxS manifests, and GRPICONDIR are specified in Microsoft's PE Format specification and Windows SDK headers (winnt.h, verrsrc.h).

Tooling & MUI Caveats: Multilingual User Interface (.mui) binaries redirect localized resources into language-specific satellite DLLs while retaining a MUI custom resource in the main binary. Additionally, VS_VERSIONINFO builders vary on whether wLength of the final child node includes trailing 4-byte padding; parsers should clamp child iteration to the parent node's end = start + wLength.
