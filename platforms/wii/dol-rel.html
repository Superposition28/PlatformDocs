Wii .dol / .rel Executables & IOS/MEM1/MEM2 Loader Model

Executable & Dynamic Module Formats · Route #wii-dol-rel

Big-endian PowerPC static executable (.dol) and relocatable dynamic module (.rel) containers inherited from GameCube and extended on Wii to span MEM1, MEM2, and Starlet/IOS low-memory boot globals.

1. Identification & Scope

Wii Broadway executables retain the GameCube binary container formats while expanding the target virtual memory space from 24 MiB (MEM1) to 88 MiB (MEM1 + MEM2) under Starlet/IOS supervision:

  • .dol (Static Executable): A 0x100-byte (256-byte) header describing up to 7 executable text sections and 11 initialized data sections, one contiguous BSS region, and a virtual entry point. There is no magic signature; structural validation checks that section offsets are >= 0x100, section ranges remain in bounds, and load addresses fall within valid MEM1/MEM2 virtual space.
  • .rel (Relocatable Module): A dynamically loaded PowerPC module linked at runtime via the SDK's OSLink loader. Wii builds predominantly emit .rel format version 3 (0x00000003 at 0x1C), adding fixSize at 0x48.
  • Scope Note: This specification covers container headers, section tables, import/relocation encodings, and generalized IOS/MEM1/MEM2 boot loader mapping; application-specific code/data payloads are excluded.

3. Flags, Enums & Decoding Formulas

3.1 .rel Relocation Opcodes & Patching Equations

Let P be the virtual address of the instruction/word being patched (sectionBase[curSec] + cursor) and S be the resolved symbol virtual address (addend if TargetModuleId == 0, otherwise targetSectionBase[entry.Section] + entry.Addend):

  • 0 (R_PPC_NONE): No operation.
  • 1 (R_PPC_ADDR32): Write 32-bit value S at P.
  • 2 (R_PPC_ADDR24): Patch 24-bit branch target bits [29:6] ((orig & ~0x03FFFFFC) | (S & 0x03FFFFFC)).
  • 3 (R_PPC_ADDR16): Write u16be(S & 0xFFFF) at P.
  • 4 (R_PPC_ADDR16_LO): Write u16be(S & 0xFFFF) at P.
  • 5 (R_PPC_ADDR16_HI): Write u16be((S >> 16) & 0xFFFF) at P.
  • 6 (R_PPC_ADDR16_HA): Write u16be(((S + 0x8000) >> 16) & 0xFFFF) at P (sign-adjusted high half for paired addi/lwz).
  • 7 (R_PPC_ADDR14), 8 (BRTAKEN), 9 (BRNTAKEN): Patch 14-bit conditional branch displacement (orig & ~0xFFFC) | (S & 0xFFFC).
  • 10 (R_PPC_REL24): PC-relative 24-bit branch: (orig & ~0x03FFFFFC) | ((S - P) & 0x03FFFFFC).
  • 11 (R_PPC_REL14), 12 (BRTAKEN), 13 (BRNTAKEN): PC-relative 14-bit branch: (orig & ~0xFFFC) | ((S - P) & 0xFFFC).
  • 201 (R_DOLPHIN_NOP): Advance cursor += OffsetDelta without patching (used when delta exceeds 65,535 bytes).
  • 202 (R_DOLPHIN_SECTION): Set curSec = entry.Section and reset cursor = 0.
  • 203 (R_DOLPHIN_END): Terminate current import relocation stream.
  • 204 (R_DOLPHIN_MRKREF): Metadata marker; ignored by standard linkers.

3.2 Generalized MEM1/MEM2 & IOS Low-Memory Loader Mapping

Before jumping to DOL.EntryPoint, the Wii boot chain (Starlet IOS + apploader/NAND loader) populates standard Broadway low-memory globals in MEM1:

  • 0x80000028 (u32be): Physical MEM1 size (0x01800000 = 24 MiB).
  • 0x8000002C (u32be): Console hardware type flag.
  • 0x800000F8 (u32be): Bus clock frequency (243000000 Hz).
  • 0x800000FC (u32be): Broadway CPU clock frequency (729000000 Hz).
  • 0x80003100–0x80003110: Physical/simulated MEM1 size, MEM1 end (0x81800000), and MEM1 arena low/high bounds.
  • 0x80003118–0x80003128: Physical/simulated MEM2 size (0x04000000 = 64 MiB), MEM2 end / IOS boundary (typically 0x93400000–0x93600000), MEM2 usable start (0x90000800), and MEM2 arena end.
  • 0x80003130–0x80003134: IPC shared buffer start and end in upper MEM2.
  • 0x80003140 (u32be): Active IOS slot and revision (e.g., (ios_num << 16) | ios_rev).

4. Edge Cases & Loader/Parser Rules

  • MEM1 vs. MEM2 Section Routing: A Wii .dol may place sections across both 0x80000000–0x817FFFFF (MEM1) and 0x90000000–0x93FFFFFF (MEM2), or uncached mirrors 0xC0000000+ / 0xD0000000+. A generalized loader must verify that MEM2 sections do not overlap the upper Starlet/IOS private/IPC region.
  • BSS Overlap / Zero-Fill Ordering: .dol BSS (0xD8–0xDF) must be zeroed before copying initialized Text and Data sections (or zeroed only for bytes outside initialized sections). Revolution SDK elf2dol merges gaps into the BSS span that can enclose initialized sections such as .sdata2, so zeroing BSS afterwards would clobber initialized data.
  • Cache Coherency (DCFlush / ICInvalidate): On real Broadway hardware or accurate emulators, after writing executable sections or applying .rel instruction patches, the loader must flush the data cache (DCFlushRange) and invalidate the instruction cache (ICInvalidateRange).
  • .rel Section 0 & BSS Allocation: Section index 0 in a .rel is always a null/dummy entry (OffsetAndFlags == 0, Length == 0). A section with FileOffset == 0 and Length > 0 represents the module's BSS block of size BssSize, allocated dynamically and assigned at runtime.
  • R_DOLPHIN_NOP Chaining: Because OffsetDelta is 16-bit unsigned, gaps larger than 65,535 bytes between relocations are encoded as one or more R_DOLPHIN_NOP (201) records adding 0xFFFF or the remainder before the patching entry.

5. Step-by-Step Parser Pseudocode

function load_wii_dol(dol_bytes, mem1, mem2):
    assert len(dol_bytes) >= 0x100

    # Zero BSS before copying initialized Text/Data segments (elf2dol BSS can span initialized sections)
    bss_addr = u32be(dol_bytes, 0xD8)
    bss_size = u32be(dol_bytes, 0xDC)
    if bss_addr != 0 and bss_size != 0:
        zero_virtual_mem(mem1, mem2, bss_addr, bss_size)

    for i in 0..6:
        off  = u32be(dol_bytes, 0x00 + i * 4)
        addr = u32be(dol_bytes, 0x48 + i * 4)
        size = u32be(dol_bytes, 0x90 + i * 4)
        if off != 0 and size != 0:
            write_virtual_mem(mem1, mem2, addr, dol_bytes[off : off + size], exec=true)

    for i in 0..10:
        off  = u32be(dol_bytes, 0x1C + i * 4)
        addr = u32be(dol_bytes, 0x64 + i * 4)
        size = u32be(dol_bytes, 0xAC + i * 4)
        if off != 0 and size != 0:
            write_virtual_mem(mem1, mem2, addr, dol_bytes[off : off + size], exec=false)

    return { entry_point: u32be(dol_bytes, 0xE0) }

function link_wii_rel(rel_bytes, loaded_modules, alloc_mem):
    mod_id      = u32be(rel_bytes, 0x00)
    num_sec     = u32be(rel_bytes, 0x0C)
    sec_off     = u32be(rel_bytes, 0x10)
    version     = u32be(rel_bytes, 0x1C)
    bss_size    = u32be(rel_bytes, 0x20)
    imp_off     = u32be(rel_bytes, 0x28)
    imp_size    = u32be(rel_bytes, 0x2C)
    align_val   = (version >= 2) ? u32be(rel_bytes, 0x40) : 32
    bss_align   = (version >= 2) ? u32be(rel_bytes, 0x44) : 32

    sec_bases = array(num_sec, 0)
    bss_base = (bss_size > 0) ? alloc_mem(bss_size, bss_align) : 0
    if bss_base != 0:
        zero_mem(bss_base, bss_size)

    for s in 0..(num_sec - 1):
        val = u32be(rel_bytes, sec_off + s * 8)
        len = u32be(rel_bytes, sec_off + s * 8 + 4)
        file_off = val & ~3
        if len == 0:
            continue
        if file_off == 0:
            sec_bases[s] = bss_base
        else:
            base = alloc_mem(len, align_val)
            copy_mem(base, rel_bytes[file_off : file_off + len])
            sec_bases[s] = base

    loaded_modules[mod_id] = sec_bases

    for k in 0..(imp_size // 8 - 1):
        target_mod = u32be(rel_bytes, imp_off + k * 8)
        rel_pos    = u32be(rel_bytes, imp_off + k * 8 + 4)
        cur_sec    = 0
        cursor     = 0
        while true:
            delta  = u16be(rel_bytes, rel_pos + 0)
            rtype  = rel_bytes[rel_pos + 2]
            sym_s  = rel_bytes[rel_pos + 3]
            addend = u32be(rel_bytes, rel_pos + 4)
            rel_pos += 8

            if rtype == 203: // R_DOLPHIN_END
                break
            elif rtype == 202: // R_DOLPHIN_SECTION
                cur_sec = sym_s
                cursor  = 0
                continue
            elif rtype == 201: // R_DOLPHIN_NOP
                cursor += delta
                continue
            elif rtype == 204 or rtype == 0:
                cursor += delta
                continue

            cursor += delta
            P = sec_bases[cur_sec] + cursor
            S = (target_mod == 0) ? addend : (loaded_modules[target_mod][sym_s] + addend)
            apply_ppc_reloc(rtype, P, S)

6. Provenance & Confidence

Loader & IOS Revision Caveat: Exact upper MEM2 arena boundaries (0x80003120 / 0x80003128) and IPC buffer allocations vary across IOS slots and SDK versions. Generalized loaders should configure these globals dynamically according to the active IOS profile rather than assuming a single static MEM2 ceiling.
  • Confirmed Specification: Both the 256-byte .dol header and .rel v1–v3 headers, PowerPC relocation opcodes (0–13), Dolphin control opcodes (201–204), and Broadway MEM1/MEM2 low-memory global slots (0x80000000–0x800031FF) are confirmed across Wii SDK binaries and System Menu/apploader behavior.
  • Relocation Variant Note: Relocation types 14–200 (such as SDA21 or GOT relocations) are defined in generic PowerPC ELF ABI specifications but are not emitted in standard linked .rel v3 files; unhandled opcodes should raise a diagnostic rather than silently continuing.
