Wii Optical Disc Layout (RVL)

Optical Media Container · Route #wii-wii-disc

Proprietary 12 cm optical disc image format combining an unencrypted disc header and partition directory with AES-128-CBC encrypted, RSA/SHA-1 authenticated partitions divided into 0x8000-byte hashed clusters.

Canonical Filenames
Raw optical sector dump (*.iso / *.gcm), or sparse/compressed external containers wrapping raw RVL disc sectors
Magic Bytes
0x5D1C9EA3 at offset 0x00018 (Wii magic); 0x00000000 at 0x0001C (GameCube magic slot); 0xC3F81A8E at 0x4FFFC
Endianness
Big-endian across all disc headers, partition tables, Ticket/TMD fields, and inner FST/DOL structures
Platform/OS Scope
Nintendo Wii (RVL) optical drive interface (/dev/di) and Starlet IOS crypto engine
Role/MIME
Encrypted multi-partition optical disc image (application/x-wii-iso-image)

1. Identification & Scope

A raw Wii optical disc image is a fixed-sector byte stream (single-layer 4,699,979,776 bytes = 2,294,912 × 2048-byte sectors; dual-layer 8,511,160,320 bytes = 4,155,840 × 2048-byte sectors). Unlike GameCube discs, which store an unencrypted filesystem at the disc root, a Wii disc reserves only the outer header (0x00000–0x4FFFF) as plaintext and encapsulates all executable and filesystem payloads inside one or more encrypted partitions.

  • Signature Distinction: At offset 0x00018, Wii discs contain big-endian 5D 1C 9E A3 (0x5D1C9EA3), whereas offset 0x0001C is zeroed (00 00 00 00). GameCube discs leave 0x00018 zeroed and store C2 33 9F 3D (0xC2339F3D) at 0x0001C.
  • Endianness: Every integer in the disc header, partition tables, Ticket, TMD, certificate chain, and decrypted partition filesystem is big-endian. Several offset and size fields store word addresses (shifted right by 2 bits, i.e. byte_offset = field << 2) so 32-bit fields can address up to 16 GiB on dual-layer discs.

0x0000 620 u8[31][20] H0 31 SHA-1 hashes, one per 0x400-byte sub-block of the 0x7C00-byte decrypted payload.

0x0280 160 u8[8][20] H1 8 SHA-1 hashes covering H0 (0x000..0x26B, 620 bytes) of each cluster in the 8-cluster subgroup.
0x0320 32 u8[32] PadH1 Zero padding after H1 array.
0x0340 160 u8[8][20] H2 8 SHA-1 hashes covering H1 (0x280..0x31F, 160 bytes) of each 8-cluster subgroup in the 64-cluster group.
0x03E0 32 u8[32] PadH2 Zero padding after H2 array (note: payload decryption IV comes from ClusterCipher[0x03D0..0x03DF] at the end of the encrypted H2 field, not from PadH2).
0x0400 31,744 u8[0x7C00] PayloadData 31 × 0x400-byte data sub-blocks encrypted with AES-128-CBC.

3. Flags, Enums & Decoding Formulas

3.1 Wii Magic vs. GameCube Magic

  • Wii Optical Disc: u32be(0x0018) == 0x5D1C9EA3 and u32be(0x001C) == 0x00000000.
  • GameCube Optical Disc: u32be(0x0018) == 0x00000000 and u32be(0x001C) == 0xC2339F3D.

3.2 AES-128-CBC Title Key & Cluster IV Derivation

  1. Select Common Key: Inspect Ticket byte 0x01F1 (CommonKeyIndex). Index 0x00 selects the standard Wii Common Key; index 0x01 selects the Korean Common Key. (vWii introduces index 0x02.)
  2. Decrypt Title Key:
    • Ciphertext: 16 bytes at Ticket[0x01BF..0x01CE].
    • IV: Ticket[0x01DC..0x01E3] || 0x00[8] (8-byte big-endian Title ID followed by 8 zero bytes).
    • TitleKey = AES_128_CBC_Decrypt(CommonKey[Index], IV_title, EncryptedTitleKey).
  3. Decrypt Cluster Hash Block (0x0000..0x03FF):
    • HashBlockPlain = AES_128_CBC_Decrypt(TitleKey, 0x00[16], ClusterCipher[0x0000..0x03FF]).
  4. Decrypt Cluster Payload (0x0400..0x7FFF):
    • Rather than chaining from the end of the 0x400-byte hash block (0x03F0..0x03FF), Wii hardware and IOS explicitly supply the final 16 bytes of the encrypted H2 array as the payload IV: IV_payload = ClusterCipher[0x03D0..0x03DF].
    • PayloadPlain = AES_128_CBC_Decrypt(TitleKey, IV_payload, ClusterCipher[0x0400..0x7FFF]).

3.3 H0 / H1 / H2 / H3 SHA-1 Verification Tree

Every cluster index c (0-based within the partition's encrypted data stream) maps to virtual decrypted byte range [c * 0x7C00, (c + 1) * 0x7C00):

  • H0 (Sub-block level): For k = 0..30, SHA1(PayloadPlain[k*0x400 : (k+1)*0x400]) == H0[k].
  • H1 (8-cluster subgroup level): Let sub = c & 7. SHA1(HashBlockPlain[0x000..0x26B]) (all 620 bytes of H0) must equal H1[sub].
  • H2 (64-cluster group level): Let grp = (c >> 3) & 7. SHA1(HashBlockPlain[0x280..0x31F]) (all 160 bytes of H1) must equal H2[grp].
  • H3 (Partition global table): Let h3Idx = c >> 6. SHA1(HashBlockPlain[0x340..0x3DF]) (all 160 bytes of H2) must equal H3Table[h3Idx * 20 : (h3Idx + 1) * 20].
  • Root Anchor: SHA1(H3Table[0 .. TMD.Content[0].ContentSize]) must equal TMD.Content[0].ContentSha1, and TMD/Ticket signatures chain to the Wii Root CA via the partition's Certificate Chain.

4. Edge Cases & Loader/Parser Rules

  • Partition Types: Disc partition tables classify partitions by PartType: 0 = Data (main executable title), 1 = Update (system IOS & System Menu WADs under _sys/), and 2 = Channel (or a 4-byte ASCII Title ID for embedded installable channels). A parser should walk all non-empty tables 0..3 and distinguish partitions by both type and table index.
  • 0x7C00 Payload vs. 0x400 Hash Block Stride: Physical cluster stride on disc is 0x8000 (32,768 bytes), whereas decrypted logical stride is 0x7C00 (31,744 bytes). Converting a decrypted virtual partition offset voff to physical disc offset requires integer division: cluster = voff / 0x7C00, intra = voff % 0x7C00, discOff = PartOffset + DataOffset + cluster * 0x8000 + 0x0400 + intra.
  • Unencrypted Development Discs: If disc header byte 0x0061 (DisableEncryption) is non-zero, partition clusters are stored without AES encryption or without the 0x400 hash header depending on disc master configuration; verify 0x0060 and 0x0061 before assuming retail cluster framing.
  • Inner Decrypted Partition FST Shifted Offsets: Inside the decrypted partition stream at 0x0420–0x042F, DOL offset, FST offset, and FST size are stored as u32be shifted right by 2 bits (val << 2). Inside the FST itself, file offsets are also stored as u32be shifted right by 2 bits (unlike GameCube FST byte offsets), enabling files beyond 4 GiB.
  • Generalized Boot Rule: On partition boot, IOS loads the TMD's SystemVersion IOS slot, mounts the partition via /dev/di, executes the apploader at decrypted offset 0x02440, maps the main .dol into MEM1/MEM2, and transfers control to its entry point.

5. Step-by-Step Parser Pseudocode

function parse_wii_disc(disc_stream, common_keys):
    hdr = read_bytes(disc_stream, 0x00000, 0x100)
    assert u32be(hdr, 0x18) == 0x5D1C9EA3
    assert u32be(hdr, 0x1C) == 0x00000000
    is_encrypted = (hdr[0x61] == 0x00)
    verify_hashes = (hdr[0x60] == 0x00)

    part_dir = read_bytes(disc_stream, 0x40000, 0x20)
    partitions = []
    for t in 0..3:
        count = u32be(part_dir, t * 8)
        table_off = u32be(part_dir, t * 8 + 4) << 2
        if count == 0 or table_off == 0:
            continue
        entries = read_bytes(disc_stream, table_off, count * 8)
        for i in 0..(count - 1):
            p_off = u32be(entries, i * 8) << 2
            p_type = u32be(entries, i * 8 + 4)
            partitions.append({ table: t, type: p_type, offset: p_off })

    for part in partitions:
        phdr = read_bytes(disc_stream, part.offset, 0x2C0)
        ticket = phdr[0x000 : 0x2A4]
        tmd_size = u32be(phdr, 0x2A4)
        tmd_off  = part.offset + (u32be(phdr, 0x2A8) << 2)
        h3_off   = part.offset + (u32be(phdr, 0x2B4) << 2)
        data_off = part.offset + (u32be(phdr, 0x2B8) << 2)
        data_len = u32be(phdr, 0x2BC) << 2

        tmd = read_bytes(disc_stream, tmd_off, tmd_size)
        h3_table = read_bytes(disc_stream, h3_off, 0x18000)
        if verify_hashes:
            assert sha1(h3_table) == tmd[0x1E4 + 0x10 : 0x1E4 + 0x24]

        key_idx = ticket[0x1F1]
        iv_title = ticket[0x1DC : 0x1E4] + bytes(8 zero bytes)
        title_key = aes128_cbc_decrypt(common_keys[key_idx], iv_title, ticket[0x1BF : 0x1CF])

        part.read_virtual = function(voff, length):
            out = empty_buffer()
            while length > 0:
                cluster_idx = voff // 0x7C00
                intra = voff % 0x7C00
                take = min(length, 0x7C00 - intra)
                c_raw = read_bytes(disc_stream, data_off + cluster_idx * 0x8000, 0x8000)

                if is_encrypted:
                    h_plain = aes128_cbc_decrypt(title_key, bytes(16 zero bytes), c_raw[0x0000 : 0x0400])
                    d_plain = aes128_cbc_decrypt(title_key, c_raw[0x03D0 : 0x03E0], c_raw[0x0400 : 0x8000])
                else:
                    h_plain = c_raw[0x0000 : 0x0400]
                    d_plain = c_raw[0x0400 : 0x8000]

                if verify_hashes:
                    for k in 0..30:
                        assert sha1(d_plain[k*0x400 : (k+1)*0x400]) == h_plain[k*20 : (k+1)*20]
                    assert sha1(h_plain[0x000 : 0x26C]) == h_plain[0x280 + (cluster_idx & 7)*20 : ... + 20]
                    assert sha1(h_plain[0x280 : 0x320]) == h_plain[0x340 + ((cluster_idx >> 3) & 7)*20 : ... + 20]
                    assert sha1(h_plain[0x340 : 0x3E0]) == h3_table[(cluster_idx >> 6)*20 : ... + 20]

                out.append(d_plain[intra : intra + take])
                voff += take
                length -= take
            return out

6. Provenance & Confidence

Cryptographic & Legal Boundary: This specification intentionally omits retail AES-128 common keys, RSA root public moduli, and signing keys. Parsers must accept external user-supplied key material at runtime rather than embedding proprietary keys.
  • Confirmed Specification: Disc header magic (0x5D1C9EA3), 0x40000 partition table structure, v0 Ticket/TMD layouts, Certificate Chain key encodings, 0x8000-byte cluster framing (0x400 hash block + 0x7C00 payload), H0–H3 SHA-1 verification tree, and shifted inner FST/DOL pointers are confirmed across retail Wii optical media and IOS /dev/di behavior.
  • Reserved / Partially Documented Fields: Ticket bytes 0x1F2–0x221 and TMD bytes 0x1AE–0x1D7 (beyond confirmed IPC mask subsets) contain internal licensing/access flags whose full bit-level semantics depend on specific IOS revisions.
