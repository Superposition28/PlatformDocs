1. Hardware & IOS Architecture

The Nintendo Wii (internal model prefix RVL) pairs a GameCube-compatible PowerPC processor with a dedicated ARM security and I/O subsystem inside the Hollywood package:

  • Broadway (PowerPC): Executes user titles, System Menu, and SDK libraries in big-endian 32-bit mode at 729 MHz. It has no direct access to NAND flash, SD cards, USB, Wi-Fi, or raw optical disc decryption keys under normal security policy; instead, it issues Inter-Process Communication (IPC) requests to Starlet via memory-mapped registers and shared MEM2 buffers.
  • Starlet (ARM926EJ-S) & IOS: Runs the Input/Output System (IOS) microkernel at 243 MHz. Each IOS slot (e.g., IOS9, IOS36, IOS58) is an independently versioned ARM binary stored on NAND. Starlet enforces cryptographic signature checks (RSA-2048/4096, ECDSA), drives hardware AES-128-CBC and SHA-1 engines, and exposes virtual device nodes such as /dev/di (Disc Interface), /dev/fs (NAND filesystem), and /dev/es (E-Ticket Services).
  • AHBPROT Escalation: When a title's Title Metadata (TMD) sets access-rights bit 0 (0x00000001), IOS disables the AHB memory protection bridge before launching Broadway, granting the PowerPC direct access to Starlet-side hardware registers.

3. Optical Disc & NAND Title Model

All executable software on Wii is organized under a unified 64-bit Title ID model shared by optical discs, NAND channels, and IOS modules:

  • 64-bit Title ID (u64be): Split into an upper 32-bit Title Type and a lower 32-bit Unique ID (typically 4 ASCII characters for retail discs/channels):
    • 0x00000001 — System titles (0x0000000100000002 System Menu; 0x00000001000000xx IOS slots; 0x0000000100000100 BC; 0x0000000100000101 MIOS).
    • 0x00010000 — Disc-based titles and saved data directories.
    • 0x00010001 — Downloadable / installed Channels.
    • 0x00010002 — System Channels pre-installed on NAND.
    • 0x00010004 — Disc-installed / disc-bound Channels.
    • 0x00010005 — Downloadable content (DLC) packages.
    • 0x00010008 — Hidden / EULA / system data channels.
  • Signed Authentication Trio: Both disc partitions and NAND/WAD titles rely on a Certificate Chain (Root CA → XS/CP signing certs), a Ticket (.tik, carrying the AES-128-CBC encrypted Title Key), and Title Metadata (.tmd, declaring the required IOS version, boot content index, and per-content SHA-1 digests).
  • Boot Flow: For optical discs, the System Menu reads the unencrypted disc header and partition table at 0x40000, loads the target partition's Ticket/TMD, spawns the requested IOS on Starlet, verifies the 0x8000-byte AES/SHA-1 cluster tree, runs the partition apploader, maps the .dol into MEM1/MEM2, and jumps to its entry point. For NAND channels, ES/System Menu launches the TMD's BootIndex content (.app) directly as a .dol or NAND loader.
