1. Identification & Scope

Every executable, DLL, and system service module on Xbox 360 is packaged as an XEX container. Unlike standard Windows PE files loaded directly by the NT loader, the Xbox 360 kernel (xboxkrnl.exe) and Hypervisor require an outer security envelope containing RSA-2048 signatures, SHA-1 page descriptor digests, an encrypted AES-128 title key, execution/media restrictions, and a directory of typed optional headers.

Hybrid Endianness Architecture: A parser must handle three distinct byte-order layers in a single XEX file:

  • Layer 1 — XEX Container (Big-Endian): The XEX header, optional header directory, optional header structs, security info, page descriptors, and import tables are all Big-Endian.
  • Layer 2 — Embedded PE/COFF Headers (Little-Endian): Once decrypted and decompressed, the inner image begins with standard Windows PE32 headers (MZ, PE\0\0, COFF File Header with machine 0x01F2, PE32 Optional Header magic 0x010B, and 40-byte Section Headers) encoded in Little-Endian.
  • Layer 3 — Mapped Sections (Big-Endian): The code (.text), read-only data (.rdata), initialized data (.data), and embedded .spa resources inside those PE sections are Big-Endian PowerPC 32-bit instructions and data.

3. Flags, Enums & Decoding Formulas

Optional Header ID Encoding

Every entry in the Optional Header Directory uses the low byte of HeaderID (sizeCode = HeaderID & 0xFF) to specify how ValueOrOffset is interpreted:

  • sizeCode == 0x00 or 0x01: ValueOrOffset is an inline 32-bit value or bitfield (for example, 0x00010100 Entry Point, 0x00010201 Image Base Address, 0x00020200 Default Stack Size).
  • 0x02 <= sizeCode <= 0xFE: ValueOrOffset is a file offset to a fixed-length structure of size sizeCode * 4 bytes (for example, 0x00040006 Execution Info has sizeCode = 6 → 24 bytes; 0x00020104 TLS Info has sizeCode = 4 → 16 bytes).
  • sizeCode == 0xFF: ValueOrOffset is a file offset to a variable-length structure whose first u32be word specifies its total byte length (for example, 0x000002FF Resource Info, 0x000003FF File Format Info, 0x000103FF Import Libraries, 0x000183FF Original PE Name, 0x000200FF Static Libraries).

LZX Normal Compression Block Chaining

When CompressionType == 2 (Normal), the decrypted payload (after AES-128-CBC decryption, if encrypted) consists of chained blocks starting with FirstBlockSize (from File Format Info):

  1. Each block begins with a 24-byte block header: u32be NextBlockSize and u8[20] NextBlockHash (SHA-1 digest of the next block, used for streaming verification).
  2. The remaining CurrentBlockSize - 24 bytes contain one or more compressed chunks prefixed by u16be CompressedChunkSize, followed by exactly CompressedChunkSize bytes of LZX bitstream data.
  3. Chunk reading continues until CompressedChunkSize == 0 or the block ends, concatenating the extracted chunks across all chained blocks into a contiguous LZX bitstream (decoded in standard 32 KiB / 0x8000-byte LZX frames using the declared WindowSize); block chaining terminates when NextBlockSize == 0.

4. Edge Cases & Loader Rules

  • XEX1 (0x58455831) vs. XEX2 (0x58455832): Early XDK pre-retail builds use XEX1, which has a smaller Security Info header before the page descriptor list (omitting later XEX2 fields such as ExportTableAddress and HeaderDigest at those exact offsets) and uses early devkit key material. Always dispatch Security Info parsing by checking Magic.
  • Encryption Precedes Compression: When both EncryptionType == 1 and CompressionType != 0 are set, the entire payload starting at SizeOfHeaders must be decrypted with AES-128-CBC (zero IV) before interpreting Basic block headers or Normal LZX block headers.
  • Basic Compression (CompressionType == 1): No LZX decoder is required. For each {DataSize, ZeroSize} descriptor in File Format Info, copy DataSize bytes from the decrypted stream into the output buffer and emit ZeroSize zero bytes (representing uninitialized .bss or alignment gaps).
  • PE Section Mapping & Truncated Raw Data: When mapping the unpacked PE32 image to virtual memory at ImageBase, VirtualSize often exceeds SizeOfRawData. Fill [VirtualAddress .. VirtualAddress + SizeOfRawData) from PointerToRawData and zero-fill the remainder up to VirtualSize. Some tool-extracted PE images already mirror virtual layout on disk; verify whether PointerToRawData matches VirtualAddress or file offsets.
  • Generalized Import Resolution (xboxkrnl.exe / xam.xex): Import records in 0x000103FF point to 32-bit slots inside the mapped PE image. Each slot encodes an import entry (such as (LibraryIndex << 24) | Ordinal and a type indicator distinguishing function call thunks from imported kernel variables). At runtime, the loader patches function thunk slots with PowerPC branch/jump trampolines (e.g., lis / ori / mtctr / bctr) targeting the resolved ordinal in xboxkrnl.exe or xam.xex, and patches variable slots with the exported data address.

5. Step-by-Step Parser Pseudocode

function ParseXex2(stream, masterKeySelector):
    magic = stream.ReadBytes(0x00, 4)
    assert magic == "XEX2"  # XEX1 uses an earlier SecurityInfo layout

    moduleFlags = stream.ReadU32BE(0x04)
    sizeOfHeaders = stream.ReadU32BE(0x08)
    securityOffset = stream.ReadU32BE(0x10)
    optCount = stream.ReadU32BE(0x14)

    optHeaders = {}
    for i in 0 .. optCount - 1:
        entryOff = 0x18 + i * 8
        hid = stream.ReadU32BE(entryOff)
        val = stream.ReadU32BE(entryOff + 4)
        low = hid & 0xFF
        if low == 0x00 or low == 0x01:
            optHeaders[hid] = { kind: "inline", value: val }
        elif low == 0xFF:
            sz = stream.ReadU32BE(val)
            optHeaders[hid] = { kind: "bytes", offset: val, data: stream.ReadBytes(val, sz) }
        else:
            optHeaders[hid] = { kind: "bytes", offset: val, data: stream.ReadBytes(val, low * 4) }

    # Security Info
    secImageSize = stream.ReadU32BE(securityOffset + 0x004)
    imageFlags = stream.ReadU32BE(securityOffset + 0x10C)
    loadAddress = stream.ReadU32BE(securityOffset + 0x110)
    encryptedAesKey = stream.ReadBytes(securityOffset + 0x150, 16)
    pageSize = (imageFlags & 0x10000000) != 0 ? 0x1000 : 0x10000

    # Payload extraction (decryption -> decompression)
    rawPayload = stream.ReadBytes(sizeOfHeaders, stream.Length - sizeOfHeaders)
    fmt = optHeaders[0x000003FF].data
    encType = ReadU16BE(fmt, 0x04)
    compType = ReadU16BE(fmt, 0x06)

    if encType == 1:
        titleKey = DecryptTitleKey(encryptedAesKey, masterKeySelector)
        payload = Aes128CbcDecrypt(rawPayload, titleKey, iv=0x00*16)
    else:
        payload = rawPayload

    if compType == 0:
        peBytes = payload
    elif compType == 1:  # Basic
        peBytes = ByteBuffer()
        pos = 0
        for off in range(8, len(fmt), 8):
            dataSz = ReadU32BE(fmt, off)
            zeroSz = ReadU32BE(fmt, off + 4)
            peBytes.Append(payload[pos : pos + dataSz])
            peBytes.AppendZeros(zeroSz)
            pos += dataSz
    elif compType == 2:  # Normal (LZX)
        windowSize = ReadU32BE(fmt, 0x08)
        blockSize = ReadU32BE(fmt, 0x0C)
        lzxStream = ByteBuffer()
        pos = 0
        while blockSize > 0:
            nextSize = ReadU32BE(payload, pos)
            # nextHash = payload[pos + 4 : pos + 24]
            cursor = pos + 24
            blockEnd = pos + blockSize
            while cursor < blockEnd:
                chunkSize = ReadU16BE(payload, cursor)
                cursor += 2
                if chunkSize == 0:
                    break
                lzxStream.Append(payload[cursor : cursor + chunkSize])
                cursor += chunkSize
            pos = blockEnd
            blockSize = nextSize
        peBytes = DecompressLzxFrames(lzxStream, windowSize, frameSize=0x8000, outputSize=secImageSize)

    # Parse Little-Endian PE32 headers inside peBytes
    assert peBytes[0:2] == "MZ"
    peOff = ReadU32LE(peBytes, 0x3C)
    assert peBytes[peOff : peOff + 4] == "PE\0\0"
    numSections = ReadU16LE(peBytes, peOff + 0x06)
    optSize = ReadU16LE(peBytes, peOff + 0x14)
    secTableOff = peOff + 0x18 + optSize
    # Map sections to virtual memory at loadAddress and resolve 0x000103FF imports
    return { LoadAddress: loadAddress, ImageSize: secImageSize, PEImage: peBytes, OptionalHeaders: optHeaders }

6. Provenance & Confidence

Cryptographic & Key Material Caveat: Retail Xbox 360 executables are signed with Microsoft's private RSA-2048 keys and have their per-image AesKey encrypted under the retail console key (whereas devkit XEXs use separate devkit key material). No retail or devkit Microsoft cryptographic keys are embedded in this specification. Clean-room parsers require externally supplied keys (or unencrypted/devkit dumps) to decrypt EncryptionType == 1 retail binaries.

  • High Confidence (Confirmed Container Spec): XEX2 main header layout, optional header ID low-byte encoding rules, File Format Info (`Basic` and `Normal` LZX chunking), Execution Info, Resource Info, Import Libraries, and Security Info offsets are established across official XDK definitions and open-source Xbox 360 loaders/analysis tools.
  • SDK-Revision & Environment Dependent: Optional header IDs added in later dashboard/SDK revisions (e.g., newer rating/kinect/system capability flags) and XEX1 pre-retail layouts vary by SDK build. Delta patches (CompressionType == 3) depend on matching the exact BaseVersion image.
