STFS — Secure Transacted File System Container

Package & Virtual Filesystem · Xbox 360 Storage

Cryptographically signed, SHA-1 hash-tree-verified container format used across Xbox 360 HDD, Memory Unit, and USB FATX storage for user profiles, savegames, downloadable content (DLC), title updates, gamerpics, and Xbox LIVE Arcade packages.

1. Identification & Scope

STFS packages begin with a 4-byte ASCII signature identifying the signing authority:

  • CON (0x434F4E20): Console-signed packages created by a retail or devkit Xbox 360 (savegames, user profiles, local themes/screenshots). Carries an embedded 0x1A8-byte Console Public Key Certificate signed by Microsoft plus a per-package signature.
  • PIRS (0x50495253): Microsoft-signed packages distributed offline (on-disc installers, demos, system/dashboard packages).
  • LIVE (0x4C495645): Microsoft Xbox LIVE server-signed packages (DLC, XBLA titles, Title Updates, Marketplace content).

Mixed Endianness Warning: Although Xbox 360 is big-endian, STFS mixes byte orders inside its core structures. Content Metadata fields (ContentSize, TitleID, FileSize, PathIndicator) and Hash Table NextBlockNumber pointers (u24be) are Big-Endian, whereas the Volume Descriptor fields FileTableBlockCount (u16le) and FileTableBlockNumber (u24le), as well as each File Entry's ValidDataBlocks, AllocatedBlocks, and StartingBlockNumber (u24le), are Little-Endian.

3. Flags, Enums & Decoding Formulas

Block & Hash Tree Spacing Formulas (Female vs. Male)

Every STFS storage block is 0x1000 (4096) bytes, starting at DataStart = align_up(HeaderSize, 0x1000) (typically 0xA000 for HeaderSize = 0x971A, or 0xB000 for v2 headers). Each hash block indexes up to 170 child blocks, creating up to three hash levels:

  • Level 0 (L0): Covers 170 data blocks per table.
  • Level 1 (L1): Present when TotalAllocatedBlockCount > 170; covers 170² = 28,900 data blocks per table.
  • Level 2 (L2): Present when TotalAllocatedBlockCount > 28,900; covers 170³ = 4,913,000 data blocks per table.

Let the Hash Table Spacing Factor S be determined by BlockSeparation & 1:

  • Read-Only ("Female", BlockSeparation & 1 == 1): S = 1 (one hash block allocated per hash table; typical of LIVE/PIRS read-only distributions).
  • Read-Write ("Male", BlockSeparation & 1 == 0): S = 2 (two alternating hash blocks allocated per hash table for atomic transacted updates; typical of CON saves and profiles).

For any logical dataBlock index (0 .. TotalAllocatedBlockCount - 1), its physical backingBlock index relative to DataStart is:

backingBlock(dataBlock) = dataBlock
    + (floor(dataBlock / 170) + 1) * S
    + (TotalAllocatedBlockCount > 170 ? (floor(dataBlock / 28900) + 1) * S : 0)
    + (TotalAllocatedBlockCount > 28900 ? (floor(dataBlock / 4913000) + 1) * S : 0)

fileOffset(backingBlock) = DataStart + backingBlock * 0x1000

The corresponding L0 Hash Table backing block for dataBlock sits immediately before its 170-block data group:

group = floor(dataBlock / 170)
l0Base = group * (170 + S)
       + (TotalAllocatedBlockCount > 170 ? (floor(group / 170) + 1) * S : 0)
       + (TotalAllocatedBlockCount > 28900 ? (floor(group / 28900) + 1) * S : 0)
# For Male (S == 2), active L0 table is l0Base + activeBit (0 or 1) from L1/root bit

4. Edge Cases & Loader Rules

  • Contiguous (0x40) vs. Chained Blocks: When FlagsAndNameLen & 0x40 is set, a file's logical blocks are allocated sequentially (StartingBlockNumber, StartingBlockNumber + 1, ...). When bit 6 is clear, follow NextBlockNumber (u24be) inside entry currentBlock % 170 of the active L0 hash table until 0xFFFFFF or AllocatedBlocks is reached. Note that some modified CON files set the contiguous bit inconsistently; falling back to L0 chaining whenever NextBlockNumber < TotalAllocatedBlockCount prevents truncation.
  • Active Hash Table in Male (S = 2) Packages: In read-write packages, each hash table occupies two consecutive 0x1000 blocks. The active top-level table is selected by (BlockSeparation >> 1) & 1, and lower-level active table indices are stored in bit 6 (0x40) of the parent hash entry's status/block flags (with fallback: pick whichever of the two candidate blocks matches the parent SHA-1 hash).
  • Directory Reconstruction & PathIndicator: The File Entry Table is a flat array of 0x40-byte records across FileTableBlockCount blocks. Entries with FileName[0] == 0x00 are deleted/unused. Folders have FlagsAndNameLen & 0x80 set; child files/folders reference their parent's 0-based index in the File Entry Table via PathIndicator (0xFFFF denotes root).
  • SVOD Mode (DescriptorType == 1): If 0x03A9 equals 1, the package header still begins with LIVE/PIRS, but the 36-byte descriptor at 0x0379 is an SVOD Volume Descriptor rather than STFS, and payload blocks live in external Data0000, Data0001, ... files.
  • End-of-File Truncation: The last data block of a file is zero-padded (or stale-padded) to 0x1000; always slice output strictly to FileSize bytes.

5. Step-by-Step Parser Pseudocode

function OpenStfsPackage(stream):
    magic = stream.ReadBytes(0x0000, 4)
    assert magic in ["CON ", "PIRS", "LIVE"]

    headerSize = stream.ReadU32BE(0x0340)
    descType = stream.ReadU32BE(0x03A9)
    assert descType == 0  # STFS (1 = SVOD)

    dataStart = (headerSize + 0xFFF) & ~0xFFF
    if dataStart < 0xA000:
        dataStart = 0xA000

    # Volume Descriptor at 0x0379 (Mixed endianness!)
    blockSep = stream.ReadU8(0x037B)
    S = (blockSep & 1) == 1 ? 1 : 2
    rootActiveBit = (blockSep >> 1) & 1
    ftBlockCount = stream.ReadU16LE(0x037C)
    ftStartBlock = stream.ReadU24LE(0x037E)
    totalBlocks = stream.ReadU32BE(0x0395)

    function DataToBacking(db):
        b = db + (floor(db / 170) + 1) * S
        if totalBlocks > 170:
            b += (floor(db / 28900) + 1) * S
        if totalBlocks > 28900:
            b += (floor(db / 4913000) + 1) * S
        return b

    function ReadL0NextBlock(db):
        grp = floor(db / 170)
        l0Backing = grp * (170 + S)
        if totalBlocks > 170:
            l0Backing += (floor(grp / 170) + 1) * S
        if totalBlocks > 28900:
            l0Backing += (floor(grp / 28900) + 1) * S
        # Select active table (for S==2, verify via parent hash or active bit)
        tableOff = dataStart + (l0Backing + (S == 2 ? ActiveL0Bit(grp, rootActiveBit) : 0)) * 0x1000
        entryOff = tableOff + (db % 170) * 24
        return stream.ReadU24BE(entryOff + 0x15)

    function ReadBlockChain(startBlock, blockCount, contiguous, maxBytes):
        out = ByteBuffer()
        cur = startBlock
        while cur != 0xFFFFFF and len(out) < maxBytes:
            phys = DataToBacking(cur)
            chunk = stream.ReadBytes(dataStart + phys * 0x1000, min(0x1000, maxBytes - len(out)))
            out.Append(chunk)
            if contiguous:
                cur = cur + 1
                if blockCount > 0 and (cur - startBlock) >= blockCount:
                    break
            else:
                cur = ReadL0NextBlock(cur)
        return out

    # Parse File Entry Table
    ftBytes = ReadBlockChain(ftStartBlock, ftBlockCount, contiguous=false, maxBytes=ftBlockCount * 0x1000)
    entries = []
    for idx in 0 .. (len(ftBytes) / 0x40) - 1:
        rec = ftBytes[idx * 0x40 : (idx + 1) * 0x40]
        if rec[0] == 0:
            break
        flags = rec[0x28]
        nameLen = flags & 0x3F
        entries.append({
            Index: idx,
            Name: DecodeUtf8(rec[0 : nameLen]),
            IsDir: (flags & 0x80) != 0,
            Contiguous: (flags & 0x40) != 0,
            ValidBlocks: ReadU24LE(rec, 0x29),
            StartBlock: ReadU24LE(rec, 0x2F),
            ParentIndex: ReadU16BE(rec, 0x32),
            FileSize: ReadU32BE(rec, 0x34)
        })
    return entries

6. Provenance & Confidence

Signature & Console Key Caveat: LIVE and PIRS signatures are generated using Microsoft private RSA-2048 keys, and CON package signatures are tied to per-console RSA-1024 private keys stored inside hardware fuses/keyvaults. No Microsoft or console private keys are included here. Reading and verifying internal SHA-1 hash trees requires no secret keys, whereas forging valid signatures for unmodified retail consoles is not possible without key material.

  • High Confidence (Confirmed Layout & Hashing): Magic signatures, mixed-endian Volume Descriptor and File Entry record layouts, Female/Male hash table spacing formulas, and SHA-1 L0/L1/L2 tree verification are completely verified across retail packages and open-source STFS implementations.
  • Schema Revisions: MetadataVersion == 2 expands localized string slots and thumbnail buffers beyond 0x971A (pushing DataStart to 0xB000 or 0xC000); always compute DataStart from HeaderSize at 0x0340 rather than hardcoding 0xA000.
