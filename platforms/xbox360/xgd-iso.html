Xbox 360 Optical Disc Layout (XGD2 / XGD3 & XDVDFS)

Optical Disc & Filesystem · Xbox 360 Media

Dual-layer DVD-9 optical disc layout used by retail Xbox 360 software, combining an outer Video/SystemUpdate compatibility partition, an XDVDFS game partition anchored by a sector-32 Volume Descriptor, and physical/cryptographic security sectors (PFI, DMI, SS).

1. Identification & Scope

Xbox 360 optical media uses two dual-layer disc formats—XGD2 (2005–2011) and XGD3 (2011 onward)—built on 2048-byte (0x800) logical sectors. A full raw/Redump disc image contains an outer DVD-Video/SystemUpdate region (visible to standard DVD players as a compatibility video partition) followed by random-looking security padding and the Xbox 360 XDVDFS (Xbox DVD File System) game partition.

Hybrid Endianness: All XDVDFS Volume Descriptor integers (RootDirSector, RootDirSize, CreationTimestamp) and Directory Entry offsets/sizes (LeftSubtreeOffset, RightSubtreeOffset, StartSector, FileSize) are Little-Endian, matching the x86 heritage of the original XDVDFS specification. By contrast, DVD Physical Format Information (PFI) and drive-level security sector fields follow ECMA-267 / MMC Big-Endian conventions.

3. Flags, Enums & Decoding Formulas

Partition Detection & File Offset Formulas

# Probe candidate partition bases (sector 32 = +0x10000)
CandidateBases = [ 0x00000000, 0x0FD90000, 0x02080000 ]
VolumeDescriptorOffset = GamePartitionBase + (32 * 0x800)   # GamePartitionBase + 0x10000
FileByteOffset(sector) = GamePartitionBase + (sector * 0x800)

Directory BST Offsets & Attributes

  • Child Node Byte Offset: Inside a directory's byte buffer, child offsets are scaled by 4: leftByteOffset = LeftSubtreeOffset * 4, rightByteOffset = RightSubtreeOffset * 4.
  • BST Ordering: Entries are ordered lexicographically using case-insensitive ASCII comparison (tolower) so the kernel can locate files (such as default.xex) in O(log N) time without reading the entire directory sequentially.
  • Attributes Bitmask: 0x01 = Read-Only, 0x02 = Hidden, 0x04 = System, 0x10 = Directory, 0x20 = Archive, 0x80 = Normal.

4. Edge Cases & Loader Rules

  • Sector-Boundary 0xFF Padding in Directory Tables: An XDVDFS directory node is never allowed to span across a 2048-byte (0x800) sector boundary. When the remaining bytes in a sector cannot fit the next node, the remainder of that sector is filled with 0xFF. Note that any BST traversal reading LeftSubtreeOffset * 4 or RightSubtreeOffset * 4 jumps directly past padding, whereas linear directory scanners must skip 0xFF padding (where Left == 0xFFFF) to the next 0x800 boundary.
  • Redump Full ISO vs. Partition-Only XISO: Full Redump dumps preserve the outer Video/SystemUpdate partitions, putting the XDVDFS game partition at 0x0FD90000 (XGD2) or 0x02080000 (XGD3). Trimmed XISO dumps shift the game partition to 0x00000000. Probing all three offsets against "MICROSOFT*XBOX*MEDIA" handles all variants uniformly (whereas Original Xbox XGD1 uses 0x18300000).
  • Zero-Length Files & Empty Directories: An empty directory has FileSize == 0; do not attempt to parse nodes when FileSize == 0. Empty files have FileSize == 0 and may carry StartSector == 0.
  • XGD3 Content Integrity Verification (CIV) & AP2.5: XGD3 discs store extra cryptographic challenge sectors and runtime CIV checks queried by the kernel through the optical drive; these live outside XDVDFS file payloads and are absent from trimmed XISO images.

5. Step-by-Step Parser Pseudocode

function MountXdvdfs(isoStream):
    MAGIC = "MICROSOFT*XBOX*MEDIA"
    gameBase = null
    for base in [0x00000000, 0x0FD90000, 0x02080000]:
        if base + 0x10800 <= isoStream.Length:
            head = isoStream.ReadBytes(base + 0x10000, 20)
            tail = isoStream.ReadBytes(base + 0x107EC, 20)
            if head == MAGIC and tail == MAGIC:
                gameBase = base
                break
    assert gameBase != null

    vdOff = gameBase + 0x10000
    rootSector = isoStream.ReadU32LE(vdOff + 0x14)
    rootSize   = isoStream.ReadU32LE(vdOff + 0x18)

    function ReadDirectory(dirSector, dirSize, parentPath):
        if dirSize == 0:
            return []
        buf = isoStream.ReadBytes(gameBase + dirSector * 0x800, dirSize)
        results = []
        visited = set()
        stack = [0]

        while len(stack) > 0:
            off = stack.pop()
            if off in visited or off + 14 > len(buf):
                continue
            visited.add(off)

            leftDword  = ReadU16LE(buf, off + 0x00)
            rightDword = ReadU16LE(buf, off + 0x02)
            if leftDword == 0xFFFF and rightDword == 0xFFFF:
                continue

            startSec = ReadU32LE(buf, off + 0x04)
            fileSize = ReadU32LE(buf, off + 0x08)
            attrs    = buf[off + 0x0C]
            nameLen  = buf[off + 0x0D]
            name     = DecodeAscii(buf[off + 0x0E : off + 0x0E + nameLen])
            fullPath = parentPath + "/" + name

            if (attrs & 0x10) != 0:
                results.extend(ReadDirectory(startSec, fileSize, fullPath))
            else:
                results.append({
                    Path: fullPath,
                    FileOffset: gameBase + startSec * 0x800,
                    Size: fileSize,
                    Attributes: attrs
                })

            if leftDword != 0:
                stack.append(leftDword * 4)
            if rightDword != 0:
                stack.append(rightDword * 4)

        return results

    return ReadDirectory(rootSector, rootSize, "")

6. Provenance & Confidence

Security Sector & Drive Challenge Caveat: SS.bin signatures, PFI/DMI drive-layer checks, and XGD3 AP2.5/CIV challenge tables rely on Microsoft RSA-2048 keys and proprietary optical drive firmware challenge-response protocols. No Microsoft keys or drive secrets are embedded here. Standard XDVDFS partition extraction requires no cryptographic keys.

  • High Confidence (Confirmed Layout): XGD2 (0x0FD90000), XGD3 (0x02080000), trimmed XISO (0x00000000), sector-32 Volume Descriptor layout, and XDVDFS BST node structure are verified across Redump preservation sets and Xbox 360 filesystem tools.
  • Wave & Security Variations: Exact byte layouts of the outer Video/$SystemUpdate partitions vary across XGD2 Waves 1–13 and XGD3 revisions, and SSv1 vs. SSv2 challenge tables differ in AP2.5 coverage, without affecting the Game Partition XDVDFS parser.
