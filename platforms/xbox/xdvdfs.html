XDVDFS / XISO Optical Disc Filesystem

Original Xbox · Optical Disc Filesystem

Proprietary read-only optical disc filesystem (also known as GDFX / Xbox DVD File System) used on Original Xbox XGD1 game discs and trimmed XISO images. Organizes files in 2048-byte sectors using a sector-32 volume descriptor and sector-aligned binary search tree (BST) directory tables.

1. Identification & Scope

XDVDFS divides the game partition into fixed 2048-byte (0x800) sectors. Relative to the start of the XDVDFS partition (PartitionBase), sectors 0..31 are reserved/zeroed and Sector 32 (PartitionBase + 0x10000) holds the primary Volume Descriptor.

  • Magic Verification: The 20-byte ASCII string MICROSOFT*XBOX*MEDIA appears twice in Sector 32: at offset 0x0000 and again at offset 0x07EC (the final 20 bytes of the 2048-byte sector).
  • Endianness: All sector indices, byte sizes, and BST offsets are little-endian (u16le, u32le, u64le).
  • Partition Base Offset: On trimmed XISO images, PartitionBase = 0x00000000. On full Original Xbox XGD1 disc dumps, a 387 MB DVD-Video compatibility partition precedes the game partition, placing the XDVDFS partition at PartitionBase = 0x18300000 (so the Volume Descriptor sits at 0x18310000).

BST Alignment, Child Offsets & Sector-Tail Padding Formulas

// Byte offset of a directory or file payload in the image stream:
absolute_offset = PartitionBase + (u64(StartSector) * 2048)

// Aligned size of a single directory entry record (4-byte alignment):
entry_byte_size = (14 + FilenameLength + 3) & ~3

// Converting LeftChildOffset / RightChildOffset to byte offset within the directory table:
left_byte_offset  = u32(LeftChildOffset)  * 4    // 0 means no left child
right_byte_offset = u32(RightChildOffset) * 4    // 0 means no right child

Entries are never split across a 2048-byte sector boundary. Whenever the next directory entry does not fit in the remaining bytes of the current 2048-byte sector, the remainder of that sector is filled with 0xFF bytes (observed as LeftChildOffset == 0xFFFF), and the next entry begins at offset 0 of the following sector.

4. Edge Cases & Loader Rules

  • Full Redump XGD1 vs. Trimmed XISO Detection: Parsers must probe candidate partition bases before failing. For Original Xbox images, check 0x00000000 + 0x10000 (trimmed XISO) and 0x18300000 + 0x10000 (full XGD1 ISO with 387 MB DVD-Video partition) for MICROSOFT*XBOX*MEDIA. (Xbox 360 XGD2/XGD3 discs place XDVDFS at other partition offsets.)
  • Non-Recursive Stack-Based BST Traversal: Each directory table encodes an alphabetical binary search tree keyed by uppercase ASCII filename comparison, where entry 0 at byte offset 0 is the root node. To prevent stack overflow on malformed or unbalanced trees and avoid missing entries if tree order is non-standard, parsers should maintain an explicit work stack (plus a visited-offset set) rather than unbounded recursion.
  • Cycle & Bounds Guards: Always validate left_byte_offset < DirectorySize, right_byte_offset < DirectorySize, track visited `(dir_sector, entry_offset)` pairs to reject self-loops, and cap directory nesting depth (e.g., 64 levels).
  • Empty Directory / Zero-Length Files: If RootDirectorySize == 0, the volume has no files. A directory entry with Attributes & 0x10 and FileSize == 0 represents an empty directory; do not attempt to read a directory table from sector 0 if StartSector == 0 or FileSize == 0.
  • Sector-Tail 0xFF vs. 0x00 Padding: Some mastering tools pad sector tails with 0xFF (triggering 0xFFFF on LeftChildOffset), while others leave trailing 0x00 bytes where FilenameLength == 0. Either condition ends scanning for the current sector and advances to the next 2048-byte sector if within DirectorySize.

5. Step-by-Step Parser Pseudocode

const SECTOR_SIZE = 2048
const XDVDFS_MAGIC = b"MICROSOFT*XBOX*MEDIA"
const CANDIDATE_BASES = [0x00000000, 0x18300000]  // XISO, XGD1

function parse_xdvdfs(stream):
    partition_base = null
    for base in CANDIDATE_BASES:
        if base + 0x10000 + SECTOR_SIZE <= size_of(stream):
            if read_bytes(stream, base + 0x10000, 20) == XDVDFS_MAGIC:
                partition_base = base
                break
    assert partition_base != null

    vd_off = partition_base + 0x10000
    assert read_bytes(stream, vd_off + 0x07EC, 20) == XDVDFS_MAGIC
    root_sector = read_u32le(stream, vd_off + 0x0014)
    root_size   = read_u32le(stream, vd_off + 0x0018)
    if root_sector == 0 or root_size == 0:
        return []

    files = []
    dir_queue = [{ path: "", sector: root_sector, size: root_size, depth: 0 }]
    visited_dirs = set()

    while dir_queue is not empty:
        dir = pop(dir_queue)
        if dir.depth > 64 or (dir.sector, dir.path) in visited_dirs:
            continue
        visited_dirs.add((dir.sector, dir.path))

        table = read_bytes(stream, partition_base + dir.sector * SECTOR_SIZE, dir.size)
        // Non-recursive BST traversal using an explicit offset stack
        stack = [0]
        visited_nodes = set()

        while stack is not empty:
            off = pop(stack)
            if off in visited_nodes or off + 14 > length(table):
                continue
            left_units  = read_u16le(table, off + 0x00)
            right_units = read_u16le(table, off + 0x02)
            if left_units == 0xFFFF:
                continue
            visited_nodes.add(off)

            start_sector = read_u32le(table, off + 0x04)
            file_size    = read_u32le(table, off + 0x08)
            attrs        = read_u8(table, off + 0x0C)
            name_len     = read_u8(table, off + 0x0D)
            if name_len == 0 or off + 14 + name_len > length(table):
                continue

            name = decode_ascii(table[off + 14 .. off + 14 + name_len])
            full_path = dir.path == "" ? name : dir.path + "/" + name

            if (attrs & 0x10) != 0:
                if start_sector != 0 and file_size > 0:
                    push(dir_queue, { path: full_path, sector: start_sector, size: file_size, depth: dir.depth + 1 })
            else:
                files.append({
                    path: full_path,
                    offset: partition_base + start_sector * SECTOR_SIZE,
                    size: file_size,
                    attrs: attrs,
                })

            if right_units != 0:
                push(stack, right_units * 4)
            if left_units != 0:
                push(stack, left_units * 4)

    return files

6. Provenance & Confidence

High Confidence: The 2048-byte sector grid, Sector 32 volume descriptor layout, dual MICROSOFT*XBOX*MEDIA magic strings, 4-byte aligned BST directory entry format, 0xFFFF sector-boundary padding, and 0x18300000 XGD1 partition offset are completely deterministic and verified across Xbox kernels and archival ISO tooling.

Raw vs. Trimmed Image Caveat: Redump-style full XGD1 optical dumps retain the 0x18300000-byte DVD-Video partition (and security/SS/DMI metadata in separate sidecar files), whereas community-trimmed XISOs strip the video partition so XDVDFS begins at offset 0x0. Wait to verify MagicTail at +0x07EC in addition to MagicHead at +0x0000 if rejecting corrupt sector-32 descriptors.
