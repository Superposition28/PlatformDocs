Xbox Executable (.xbe)

Original Xbox · Platform Executable Format

Native executable format for the Original Xbox kernel (xboxkrnl.exe). Replaced standard Win32 PE/COFF headers with a flat XBEH image header, an RSA-2048 signed digest over header and section hashes, XOR-obfuscated entry and kernel thunk addresses, and statically linked XDK library version descriptors.

1. Identification & Scope

Every Original Xbox disc boots from default.xbe in the root of the XDVDFS partition (or an explicit XBE launched via XLaunchNewImage). Although produced by the XDK linker from a PE/COFF intermediate image (and preserving several diagnostic PE fields such as PeStackCommit and PeHeapReserve), the on-disk XBE removes the DOS MZ and PE headers entirely.

  • Magic: Offset 0x0000 contains the 4-byte ASCII signature XBEH (58 42 45 48, 0x48454258 in u32le).
  • Addressing Rule: Header pointers are 32-bit Virtual Addresses (VAs) anchored at BaseAddress (normally 0x00010000). Header structures reside within the first SizeOfHeaders bytes mapped at BaseAddress, so a header-resident VA converts directly to file offset via VA - BaseAddress.
  • Endianness: All integer fields, pointers, and UTF-16LE strings are little-endian.

3. Flags, Enums & Decoding Formulas

XOR Address Unmasking (EntryPoint & KernelImageThunkAddress)

To distinguish retail, debug/devkit, and arcade builds and deter naive static inspection, the XBE header stores EntryPoint and KernelImageThunkAddress XORed with 32-bit constants. Unmasking is simple bitwise XOR: 

real_entry_va        = header.EntryPoint ^ XOR_EP_KEY
real_kernel_thunk_va = header.KernelImageThunkAddress ^ XOR_KT_KEY

Kernel Thunk Import Table & Startup Logo

  • Kernel Thunk Entries: At the unmasked KernelImageThunkAddress VA, a 0x00000000-terminated array of u32le values encodes ordinal imports into xboxkrnl.exe. Every valid entry has bit 31 set (entry & 0x80000000 != 0), and the kernel export ordinal is ordinal = entry & 0x7FFFFFFF.
  • Startup Logo & Inserted Image Sections: LogoBitmapAddress / LogoBitmapSize point to an RLE-compressed 100×17 grayscale bitmap displayed by the kernel before jumping to the entry point. Many XBEs also embed dashboard title/save icons in InsertedFile sections named $$XTIMAGE and $$XSIMAGE formatted as XPR0 containers.

4. Edge Cases & Loader Rules

  • Retail vs. Debug vs. Chihiro Detection: Because the header stores no explicit "build type" enum, parsers try each (XOR_EP_KEY, XOR_KT_KEY) pair in turn. A key pair matches when BaseAddress ≤ unmasked_ep < BaseAddress + SizeOfImage (specifically falling inside an Executable section) and unmasked_kt falls within a readable section or header range with valid 0x8000xxxx ordinals terminated by 0.
  • Virtual-to-File Address Translation: VAs in [BaseAddress, BaseAddress + SizeOfHeaders) map to va - BaseAddress. VAs inside sections must be translated by locating the section where sec.VirtualAddress ≤ va < sec.VirtualAddress + sec.RawSize and computing sec.RawAddress + (va - sec.VirtualAddress); offsets in [sec.RawSize, sec.VirtualSize) have no backing bytes on disk and zero-fill in RAM.
  • Generalized Section & Thunk Mapping: A clean-room loader allocates virtual memory spanning [BaseAddress, BaseAddress + SizeOfImage), copies bytes [0, SizeOfHeaders) to BaseAddress, maps each section’s RawSize bytes to VirtualAddress (zero-padding up to VirtualSize), and patches the u32le array at unmasked_kt with kernel export addresses or import stubs.
  • Inserted Sections: Sections marked with InsertedFile (0x00000008) and without Preload (0x00000002) are commonly metadata/image payloads ($$XTIMAGE, $$XSIMAGE) rather than code/data needed at launch.

5. Step-by-Step Parser Pseudocode

function parse_xbe(file):
    magic = read_bytes(file, 0x0000, 4)
    assert magic == b"XBEH"

    base_addr    = read_u32le(file, 0x0104)
    size_headers = read_u32le(file, 0x0108)
    size_image   = read_u32le(file, 0x010C)
    hdr_size     = read_u32le(file, 0x0110)
    assert hdr_size >= 0x0178 and size_headers <= size_of(file)

    cert_va      = read_u32le(file, 0x0118)
    num_sections = read_u32le(file, 0x011C)
    sec_hdrs_va  = read_u32le(file, 0x0120)
    init_flags   = read_u32le(file, 0x0124)
    raw_ep       = read_u32le(file, 0x0128)
    tls_va       = read_u32le(file, 0x012C)
    raw_kt       = read_u32le(file, 0x0158)
    num_libs     = read_u32le(file, 0x0160)
    libs_va      = read_u32le(file, 0x0164)

    // 1. Parse section headers (all within header block)
    sections = []
    sec_off = sec_hdrs_va - base_addr
    for i in 0 .. num_sections - 1:
        off = sec_off + i * 0x38
        s = {
            flags:        read_u32le(file, off + 0x00),
            va:           read_u32le(file, off + 0x04),
            vsize:        read_u32le(file, off + 0x08),
            raw_addr:     read_u32le(file, off + 0x0C),
            raw_size:     read_u32le(file, off + 0x10),
            name_va:      read_u32le(file, off + 0x14),
            digest:       read_bytes(file, off + 0x24, 20),
        }
        assert s.raw_addr + s.raw_size <= size_of(file)
        s.name = read_cstr(file, va_to_file_offset(s.name_va, base_addr, size_headers, sections))
        sections.append(s)

    // 2. Detect Retail vs Debug vs Chihiro XOR keys
    keys = [
        ("Retail",  0xA8FC57AB, 0x5B6D40B6),
        ("Debug",   0x94859D4B, 0xEFB1F152),
        ("Chihiro", 0x40B5C16E, 0x2290059D),
    ]
    target_kind, entry_va, kt_va = null, 0, 0
    for (kind, xor_ep, xor_kt) in keys:
        ep = raw_ep ^ xor_ep
        kt = raw_kt ^ xor_kt
        if in_executable_section(ep, sections) and va_to_file_offset(kt, base_addr, size_headers, sections) != null:
            target_kind, entry_va, kt_va = kind, ep, kt
            break
    assert target_kind != null

    // 3. Parse Certificate
    cert_off = va_to_file_offset(cert_va, base_addr, size_headers, sections)
    cert = {
        size:          read_u32le(file, cert_off + 0x00),
        title_id:      read_u32le(file, cert_off + 0x08),
        title_name:    read_utf16le_z(file, cert_off + 0x0C, 40),
        allowed_media: read_u32le(file, cert_off + 0x9C),
        game_region:   read_u32le(file, cert_off + 0xA0),
        version:       read_u32le(file, cert_off + 0xAC),
    }

    // 4. Parse Kernel Thunk Ordinals
    kt_off = va_to_file_offset(kt_va, base_addr, size_headers, sections)
    kernel_ordinals = []
    while true:
        val = read_u32le(file, kt_off)
        if val == 0: break
        assert (val & 0x80000000) != 0
        kernel_ordinals.append(val & 0x7FFFFFFF)
        kt_off += 4

    // 5. Parse Library Versions
    lib_off = va_to_file_offset(libs_va, base_addr, size_headers, sections)
    libraries = []
    for i in 0 .. num_libs - 1:
        off = lib_off + i * 0x10
        flags = read_u16le(file, off + 0x0E)
        libraries.append({
            name:     read_ascii_z(file, off + 0x00, 8),
            major:    read_u16le(file, off + 0x08),
            minor:    read_u16le(file, off + 0x0A),
            build:    read_u16le(file, off + 0x0C),
            qfe:      flags & 0x1FFF,
            approved: (flags >> 13) & 0x3,
            debug:    (flags & 0x8000) != 0,
        })

    return { target_kind, base_addr, entry_va, init_flags, cert, sections, kernel_ordinals, libraries }

6. Provenance & Confidence

High Confidence (Hardware / Kernel ABI): The 0x0178-byte base header, 0x01D0-byte certificate, 56-byte section descriptors, 16-byte library version records, 24-byte TLS directory, XOR unmasking keys (Retail/Debug/Chihiro), and ordinal thunk encoding are universally fixed by the Original Xbox kernel loader and verified across retail and XDK tools.

Revision-Dependent Fields: Header extensions past 0x0178 (LibraryFeatures, DebugInfo) and certificate extensions past 0x01D0 (OnlineService, ExtraSecurityFlags, CodeEncKey) appear only in later XDK builds and must always be gated on SizeOfImageHeader and Certificate.Size.

Signing & Prototype Key Caveat: The 256-byte DigitalSignature uses Microsoft’s retail RSA-2048 private key (only the public modulus resides in retail boot ROMs and is not reproduced here). Early pre-release/beta XDK prototypes used separate XOR obfuscation keys that differ from the three production/devkit/Chihiro pairs tabulated above.
