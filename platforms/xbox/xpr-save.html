1. Identification & Scope

The Original Xbox dashboard displays title and save-game entries stored under TDATA\<TitleID>\ and UDATA\<TitleID>\ using two complementary platform conventions:

  • Text Metadata (TitleMeta.xbx, SaveMeta.xbx): Plain UTF-16LE text files beginning with the little-endian BOM (FF FE) and containing Key=Value pairs separated by CRLF.
  • Packed GPU Resources (XPR0, XPR1, and *Image.xbx): Binary containers produced by XDK Bundler to map D3D8 resource headers (such as D3DTexture) directly into contiguous GPU-accessible memory. Dashboard icon files (TitleImage.xbx, SaveImage.xbx, and XBE $$XTIMAGE / $$XSIMAGE sections) are single-texture XPR0 containers.

D3DTexture.Format Bitfield Decoding

is_cubemap  = (Format & 0x00000004) != 0
dimensions  = (Format >> 4)  & 0x0F    // 1 = 1D, 2 = 2D, 3 = 3D
d3d_format  = (Format >> 8)  & 0xFF    // e.g., 0x06 ARGB8888, 0x0C DXT1, 0x0E DXT3, 0x0F DXT5, 0x12 Linear ARGB
mip_levels  = (Format >> 16) & 0x0F
width       = 1 << ((Format >> 20) & 0x0F)
height      = 1 << ((Format >> 24) & 0x0F)
depth       = 1 << ((Format >> 28) & 0x0F)

// Linear texture fallback when Format width/height are 0 and Size != 0:
// width  = (Size & 0x00000FFF) + 1
// height = ((Size >> 12) & 0x00000FFF) + 1

Bulk pixel data for each resource starts at absolute file offset HeaderSize + resource.Data. Non-linear Xbox textures use Morton (Z-order) swizzling for uncompressed pixel formats, whereas DXT1/3/5 compressed textures use standard 4×4 block compression without Morton pixel reordering inside blocks.

4. Edge Cases & Loader Rules

  • .xbx Dual Nature: Despite sharing the .xbx extension, TitleMeta.xbx and SaveMeta.xbx are UTF-16LE text files while TitleImage.xbx and SaveImage.xbx are binary XPR0 containers. Parsers must dispatch by magic bytes (XPR0 vs. FF FE UTF-16LE) rather than extension alone.
  • Dashboard Icon Constraints: Standard Xbox dashboard thumbnails (TitleImage.xbx / SaveImage.xbx) are typically 64×64 or 128×128 DXT1 or ARGB textures inside a 2048-byte-header XPR0 file; however, parsers should read dimensions dynamically from D3DTexture.Format / Size.
  • XPR0 Sentinel Termination & Padding: In XPR0, header structs end at the first u32le == 0xFFFFFFFF before HeaderSize. Remaining bytes between the sentinel and HeaderSize are zero padding used to align the GPU data section to 2048 bytes (0x800).
  • XPR1 Name Table: XPR1 adds a named lookup directory (ResourceCount entries of { NameOffset, ResourceOffset }) ahead of the resource structs so titles can query bundled resources by ASCII name via CXBPackedResource::GetResource(name).

5. Step-by-Step Parser Pseudocode

function parse_xbx_or_xpr(file):
    magic4 = read_bytes(file, 0x0000, 4)

    if magic4 == b"XPR0":
        total_size  = read_u32le(file, 0x0004)
        header_size = read_u32le(file, 0x0008)
        assert header_size <= total_size and total_size <= size_of(file)

        off = 0x000C
        resources = []
        while off + 4 <= header_size:
            common = read_u32le(file, off)
            if common == 0xFFFFFFFF:
                break
            rtype = (common >> 16) & 0x7
            data_rel = read_u32le(file, off + 0x04)
            abs_data = header_size + data_rel
            if rtype == 4 or rtype == 5:  // Texture or Surface
                fmt  = read_u32le(file, off + 0x0C)
                sz   = read_u32le(file, off + 0x10)
                resources.append({ type: rtype, data_offset: abs_data, format: fmt, size_word: sz })
                off += 20
            else if rtype == 2:  // PushBuffer
                sz    = read_u32le(file, off + 0x0C)
                alloc = read_u32le(file, off + 0x10)
                resources.append({ type: rtype, data_offset: abs_data, size: sz, allocation_size: alloc })
                off += 20
            else:  // VertexBuffer (0), IndexBuffer (1), Palette (3), Fixup (6)
                resources.append({ type: rtype, data_offset: abs_data })
                off += 12
        return { kind: "XPR0", resources }

    if magic4 == b"XPR1":
        total_size     = read_u32le(file, 0x0004)
        header_size    = read_u32le(file, 0x0008)
        resource_count = read_u32le(file, 0x000C)
        return { kind: "XPR1", total_size, header_size, resource_count }

    if magic4[0..2] == b"\xFF\xFE":
        text = decode_utf16le(read_bytes(file, 2, size_of(file) - 2))
        kv = {}
        for line in split_lines(text):
            if "=" in line:
                k, v = split_once(line, "=")
                kv[trim(k)] = trim(v)
        return { kind: "XBX_META", entries: kv }

6. Provenance & Confidence

High Confidence: TitleMeta.xbx / SaveMeta.xbx UTF-16LE encoding, the 12-byte XPR0 header, the 20-byte D3DTexture layout, D3DCOMMON_TYPE_* masks, and D3DTexture.Format bitfield shifts are confirmed from Original Xbox XDK D3D8 headers and dashboard save artifacts.

XPR1 Offset-Base & Save Signing Caveat: While the 16-byte XPR1 header and (NameOffset, ResourceOffset) directory structure are standard across later XDK Bundler builds, exact offset-base conventions inside XPR1 directory entries should be cross-checked against the target XDK build’s xpr.h / XBResource loader. Note also that Xbox save files on HDD/MU may carry separate HMAC-SHA1 signatures computed with the title’s XBE SignatureKey outside the .xbx metadata files themselves.
