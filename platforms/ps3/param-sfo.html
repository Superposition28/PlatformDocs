PARAM.SFO / PARAM.SFX & PS3_DISC.SFB

PlayStation 3 System Metadata & Disc Descriptor Formats

PS3 titles rely on two complementary platform metadata containers: the PSF (System File Object) key-value store (PARAM.SFO and companion overlay PARAM.SFX) used by the XMB and CellOS for title attributes, and the SFB disc descriptor (PS3_DISC.SFB) placed at the root of Blu-ray discs. Notably, PARAM.SFO/PARAM.SFX are strictly little-endian despite living inside a big-endian system, whereas PS3_DISC.SFB is big-endian.

1. Identification & Scope

Hybrid Endianness Warning: Although the PlayStation 3 CPU (Cell BE) and nearly all native PS3 system containers (SELF, PKG, TRP, SFB) are big-endian, PARAM.SFO and PARAM.SFX use little-endian 16-bit and 32-bit integers throughout their header, index table, and uint32 values. This layout is inherited directly from Sony's cross-platform PSF specification (originally introduced on PSP).

  • PARAM.SFO: Required in every disc (PS3_GAME/PARAM.SFO), PSN package, save-data directory, and game-data directory. Encodes TITLE_ID, CATEGORY, APP_VER, PS3_SYSTEM_VER, supported display RESOLUTION, SOUND_FORMAT, PARENTAL_LEVEL, and ATTRIBUTE bitmasks.
  • PARAM.SFX: Optional companion PSF file using the exact same \x00PSF binary schema. When present alongside PARAM.SFO (such as in game updates or special packages), it supplies supplemental or overridden XMB keys.
  • PS3_DISC.SFB: Present exclusively at the root of physical PS3 Blu-ray discs (/PS3_DISC.SFB). Uses big-endian 16-bit and 32-bit fields, starting with 0x2E534642 (".SFB"), to declare disc hybrid mode, DISC_ID/TITLE_ID, and disc mastering version.

2. Binary Layout Tables

PARAM.SFO / PARAM.SFX Header (20 bytes, Little-Endian)
Offset Size Type Field Description
0x00 4 u8[4] magic Bytes 00 50 53 46 ("\x00PSF"; 0x46535000 if read as u32le).
0x04 4 u32le version PSF format version: 0x00000101 (v1.1; bytes 01 01 00 00).
0x08 4 u32le key_table_start Absolute file offset where the NUL-terminated ASCII key strings begin.
0x0C 4 u32le data_table_start Absolute file offset where the value payload table begins.
0x10 4 u32le tables_entries Number of 16-byte index records immediately following at 0x14.
PARAM.SFO Index Entry (16 bytes per entry, starting at 0x14, Little-Endian)
Offset Size Type Field Description
0x00 2 u16le key_offset Byte offset of key string relative to key_table_start.
0x02 2 u16le data_fmt Value type tag: 0x0004 (UTF-8 special), 0x0204 (UTF-8 string), 0x0404 (u32le).
0x04 4 u32le data_len Active byte length of value (includes NUL byte for 0x0204; 4 for 0x0404).
0x08 4 u32le data_max_len Total allocated slot size in the data table (4-byte aligned, >= data_len).
0x0C 4 u32le data_offset Byte offset of value payload relative to data_table_start.
PS3_DISC.SFB Header (32 bytes, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be magic Disc descriptor signature: 0x2E534642 (ASCII ".SFB").
0x04 2 u16be version_major Format major version (1).
0x06 2 u16be version_minor Format minor version (0).
0x08 24 u8[24] reserved Zero-filled padding up to directory table start at 0x20.
PS3_DISC.SFB Directory Entry (32 bytes per entry starting at 0x20, Big-Endian)
Offset Size Type Field Description
0x00 16 char[16] key NUL-padded ASCII key (e.g., "HYBRID_FLAG", "DISC_ID"); 0x00 first byte terminates table.
0x10 4 u32be data_offset Absolute file offset where the entry's value payload is stored (commonly 0x200+).
0x14 4 u32be data_size Byte length of the value payload at data_offset.
0x18 8 u8[8] reserved Zero padding.

3. Flags, Enums & Decoding Formulas

PARAM.SFO Data Formats (data_fmt)

  • 0x0004 (PSF_TYPE_BIN): Raw/unterminated UTF-8 or binary blob of length data_len (used e.g. for PARAMS / PARAMS2 in save-data SFOs or custom binary records).
  • 0x0204 (PSF_TYPE_STR): NUL-terminated UTF-8 string; effective string slice is raw[0 .. data_len - 1] (strip trailing 0x00).
  • 0x0404 (PSF_TYPE_INT): 32-bit little-endian unsigned integer (u32le); data_len and data_max_len are both 4.

PS3 Standard Keys & Bitmasks

Common PS3 PARAM.SFO Keys & Encodings
Key Type Meaning & Bitmask / Enum Values
TITLE_ID 0x0204 9-character product code (e.g., BLES#####, BLUS#####, NPUB#####).
CATEGORY 0x0204 2-byte category: DG (Disc Game), HG (HDD Game), GD (Game Data), AP (App), SF (Save Data), 1P/2D (PS1/PS2 Classic).
APP_VER / VERSION 0x0204 Application / package version string ("01.00").
PS3_SYSTEM_VER 0x0204 Minimum required firmware version string (e.g., "03.5500").
BOOTABLE 0x0404 1 = launchable application with EBOOT.BIN, 0 = data-only package.
PARENTAL_LEVEL 0x0404 System parental control level (0–11).
RESOLUTION 0x0404 Supported video bitmask: 0x01=480p, 0x02=576p, 0x04=720p, 0x08=1080i, 0x10=1080p, 0x20=480p 16:9, 0x40=576p 16:9.
SOUND_FORMAT 0x0404 Supported audio bitmask: 0x01=2ch LPCM, 0x04=5.1 LPCM, 0x10=7.1 LPCM, 0x102=Dolby Digital 5.1, 0x202=DTS 5.1.
ATTRIBUTE 0x0404 System capability bitmask: 0x00000001 Remote Play v1, 0x00000002 Copy-Prohibit (save), 0x00000004 Remote Play v2, 0x00000010 Installable/Move, 0x00000020 XMB In-Game BGM, 0x00000040 Cross-Controller, 0x00000080 Screenshot/Trophy-era capability flag.

PS3_DISC.SFB Keys

  • HYBRID_FLAG: ASCII flag string indicating disc content classes (e.g., "g" = PS3 Game, "vg" = BD-Video + PS3 Game hybrid, "u" = update/special).
  • DISC_ID (or TITLE_ID): 9-character product identifier (hyphen often omitted or normalized, padded to 16 bytes).

4. Edge Cases & Loader / Parser Rules

  • 4-Byte Alignment & Padding: In PARAM.SFO, the key table ends with NUL padding to align data_table_start to a 4-byte boundary. Every value slot reserves data_max_len bytes (also 4-byte aligned), while data_len records the active length. Parsers MUST slice data_len bytes rather than reading up to data_max_len when decoding strings, and MUST skip data_max_len when advancing or validating offsets.
  • Lexicographical Key Sorting: Official Sony SFO builders sort keys in ascending ASCII lexicographical order; the XMB/CellOS lookup routines assume sorted order for binary search, so writers modifying an SFO must re-sort index entries by key name.
  • String NUL-Termination Quirks: Although data_fmt == 0x0204 specifies a NUL-terminated UTF-8 string, malformed or patched SFOs occasionally omit the trailing NUL inside data_len. Parsers should clamp to data_len and strip any trailing 0x00 bytes safely.
  • PS3_DISC.SFB Table Termination: The directory table at 0x20 has no explicit entry_count field in its header. Iteration stops upon reading an entry whose 16-byte key begins with 0x00 or when the read cursor reaches the smallest data_offset (commonly 0x200).

5. Parser Pseudocode

function parse_param_sfo(stream):
    magic = read_bytes(stream, 0x00, 4)
    assert magic == b"\x00PSF"
    version          = read_u32le(stream, 0x04)
    key_table_start  = read_u32le(stream, 0x08)
    data_table_start = read_u32le(stream, 0x0C)
    entry_count      = read_u32le(stream, 0x10)

    params = {}
    for i in 0 .. entry_count - 1:
        off          = 0x14 + i * 0x10
        key_off      = read_u16le(stream, off + 0x00)
        data_fmt     = read_u16le(stream, off + 0x02)
        data_len     = read_u32le(stream, off + 0x04)
        data_max_len = read_u32le(stream, off + 0x08)
        data_off     = read_u32le(stream, off + 0x0C)

        assert data_len <= data_max_len
        key_name = read_cstr_ascii(stream, key_table_start + key_off)
        val_pos  = data_table_start + data_off

        if data_fmt == 0x0404:
            assert data_len == 4
            params[key_name] = read_u32le(stream, val_pos)
        elif data_fmt == 0x0204:
            raw = read_bytes(stream, val_pos, data_len)
            params[key_name] = decode_utf8(strip_trailing_nul(raw))
        elif data_fmt == 0x0004:
            params[key_name] = read_bytes(stream, val_pos, data_len)
        else:
            params[key_name] = ("unknown_fmt", data_fmt, read_bytes(stream, val_pos, data_len))

    return { version: version, entries: params }


function parse_ps3_disc_sfb(stream):
    magic = read_u32be(stream, 0x00)
    assert magic == 0x2E534642  // ".SFB"
    ver_major = read_u16be(stream, 0x04)
    ver_minor = read_u16be(stream, 0x06)

    fields = {}
    cursor = 0x20
    limit  = file_size(stream)
    while cursor + 0x20 <= limit:
        raw_key = read_bytes(stream, cursor + 0x00, 16)
        if raw_key[0] == 0x00:
            break
        key_name    = decode_ascii(split_at_first_nul(raw_key))
        data_offset = read_u32be(stream, cursor + 0x10)
        data_size   = read_u32be(stream, cursor + 0x14)
        limit       = min(limit, data_offset)

        raw_val = read_bytes(stream, data_offset, data_size)
        fields[key_name] = decode_ascii(strip_trailing_nul(raw_val))
        cursor += 0x20

    return { version: (ver_major, ver_minor), fields: fields }

6. Provenance & Confidence

  • Confirmed Specification: The 20-byte PSF header, 16-byte index record, data types (0x0004, 0x0204, 0x0404), and PS3_DISC.SFB 32-byte header/directory structure are fully confirmed across retail PS3 discs and PSN packages.
  • Firmware-Revision-Dependent Fields: Higher bits of ATTRIBUTE and newer CATEGORY codes (such as remote play / Vita / Move / BGM extensions) were introduced incrementally across CellOS firmware updates; tools targeting older firmwares may ignore unknown upper bits.

Save-Data & Integrity Note: While disc and package PARAM.SFO files are unencrypted, save-game PARAM.SFO files in SAVEDATA directories store HMAC/CMAC digests inside PARAM.PFD and binary PARAMS/PARAMS2 fields. Editing a save-game SFO without recomputing the companion PARAM.PFD console/disc-keyed hashes will fail system integrity checks.
