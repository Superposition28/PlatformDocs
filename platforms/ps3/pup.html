PS3UPDAT.PUP / .pup (PS3 System Firmware Update)

PlayStation 3 System Software Update Container

PS3UPDAT.PUP (PlayStation Update Package) is Sony Computer Entertainment's big-endian container format for PlayStation 3 system firmware updates, Blu-ray disc minimum-version installers, and incremental delta patches (PS3PATCH.PUP). It pairs a 48-byte SCEUF header, a 32-byte-per-entry file directory, a parallel HMAC-SHA1 hash table, and a header HMAC footer with contiguous plaintext metadata, POSIX ustar archives, and signed SCE\0 payloads.

1. Identification & Scope

Every PlayStation 3 firmware update package begins with the 8-byte signature 53 43 45 55 46 00 00 00 (0x5343455546000000, ASCII "SCEUF\0\0\0" — Sony Computer Entertainment Update File) followed by package_version = 1. All multi-byte integers in the PUP header, entry table, hash table, and embedded SCE\0 containers are strictly big-endian. Embedded tarball members (vsh.tar, update_files.tar, spkg_hdr.tar) use standard 512-byte-blocked POSIX ustar archives, while top-level configuration and EULA members use UTF-8 / ASCII text or XML.

Depending on delivery medium, the container appears in three canonical locations:

  • Optical disc (/PS3_UPDATE/PS3UPDAT.PUP): Bundled on retail Blu-ray game discs to guarantee minimum system software; retail disc images zero-pad the file after header_length + data_length to an exact 256 MiB (0x10000000 bytes).
  • Removable storage (/PS3/UPDATE/PS3UPDAT.PUP): Placed on FAT32 USB storage for offline XMB or Safe Mode installation at exact header_length + data_length size.
  • Network CDN (ps3-updatelist.txt): Distributed either as a full PS3UPDAT.PUP image or as an incremental delta package named PS3PATCH.PUP keyed to a specific base build.

Scope & Disambiguation: This specification covers PlayStation 3 SCEUF (package_version = 1) packages only. PlayStation 4 .PUP installers use an unrelated SLB2 (0x534C4232) container, PSP firmware updates use EBOOT.PBP, and PS Vita SCEUF updates use distinct entry IDs. Furthermore, *.pkg files inside update_files.tar (such as CORE_OS_PACKAGE.pkg) are SCE\0 certified packages (category = 3, SPKG), not PSN \x7FPKG installation archives.

2. Binary Layout Tables

PUP Main Header (48 bytes, offset 0x00..0x2F, Big-Endian)
Offset Size Type Field Description
0x00 8 char[8] magic Container signature: 0x5343455546000000 ("SCEUF\0\0\0").
0x08 8 u64be package_version PUP container format version; always 1 across retail PS3 firmware releases.
0x10 8 u64be image_version Monotonically increasing firmware build number (e.g., 0x06FC = 1788 for FW 1.02; 0x10B94 = 68500 for FW 4.93). Matches the 8-hex-digit ImageVersion in ps3-updatelist.txt.
0x18 8 u64be file_count Number of packed member entries (N) in both the File Entry Table and Hash Entry Table.
0x20 8 u64be header_length Total byte length of the header region (0x50 + N * 0x40). The payload data region starts immediately at this offset.
0x28 8 u64be data_length Total byte length of the contiguous payload data region (sum(entry[i].data_length)).
File Entry Record (32 bytes per entry at 0x30, file_count entries, Big-Endian)
Offset Size Type Field Description
0x00 8 u64be entry_id Numeric member identifier defining role and canonical filename (see Section 3).
0x08 8 u64be data_offset Absolute byte offset of the member payload from the start of the .PUP file.
0x10 8 u64be data_length Exact byte length of the member payload.
0x18 8 u64be padding Reserved zero padding (0).
Hash Entry Record (32 bytes per entry at 0x30 + file_count * 0x20, file_count entries, Big-Endian)
Offset Size Type Field Description
0x00 8 u64be entry_index 0-based index (0 .. file_count - 1) referencing the corresponding File Entry Record (not entry_id).
0x08 20 u8[20] hmac_sha1 20-byte HMAC-SHA1 digest computed over payload bytes [data_offset .. data_offset + data_length).
0x1C 4 u8[4] padding Reserved zero padding (00 00 00 00).
Header Integrity Footer (32 bytes at header_length - 0x20, Big-Endian)
Offset Size Type Field Description
0x00 20 u8[20] header_hmac_sha1 20-byte HMAC-SHA1 digest covering all preceding header bytes [0x00 .. header_length - 0x20) (Main Header + File Entry Table + Hash Entry Table).
0x14 12 u8[12] padding Reserved zero padding (0x00 × 12) extending up to header_length.
Overall Container Region Map
Offset Size Type Field Description
0x00 48 PUPHeader Main Header SCEUF signature, version, build counter, entry count, and region sizes.
0x30 file_count * 0x20 FileEntry[N] File Entry Table Ordered array of 32-byte entry descriptors pointing into the payload region.
0x30 + N * 0x20 file_count * 0x20 HashEntry[N] Hash Entry Table Parallel array of 32-byte HMAC-SHA1 records indexed by entry_index.
0x30 + N * 0x40 32 HeaderFooter Header Integrity Footer 20-byte header_hmac_sha1 + 12-byte zero padding ending at header_length.
header_length data_length u8[data_length] Payload Data Region Contiguously concatenated entry payloads packed without inter-file alignment padding.
header_length + data_length 0 or pad to 0x10000000 u8[] Disc Tail Padding (Optional) Absent in CDN/USB PUPs; Blu-ray disc PS3UPDAT.PUP images append trailing 0x00 bytes to 256 MiB.
Inner update_files.tar (0x300) & spkg_hdr.tar (0x501) SCE Certified Members
SCE Category header_len Canonical Members Role & Container Relationship
0x0001 (SELF) 0x0880 (2176 B) ps3swu.self (0x200), ps3swu2.self (0x601) Top-level PUP System Software Updater executables (SCE\0 SELF, key_revision = 0x0001 or 0x000D).
0x0002 (RVK) 0x0200 (512 B) RL_FOR_PACKAGE.img, RL_FOR_PROGRAM.img Revocation lists inside 0x300; excluded from 0x501 (spkg_hdr.tar).
0x0003 (SPKG) 0x0280 (640 B) UPL.xml.pkg, CORE_OS_PACKAGE.pkg, dev_flash_*.tar.aa.<timestamp>, dev_flash3_*.tar.aa.<timestamp>, BDIT_FIRMWARE_PACKAGE.pkg, BDPT_FIRMWARE_PACKAGE_*.pkg, BLUETOOTH_FIRMWARE.pkg, MULTI_CARD_FIRMWARE.pkg, SYS_CON_FIRMWARE_*.pkg, patch_data.pkg (0x203) Signed system packages containing encrypted/compressed flash tarballs, LV0/LV1/LV2 CoreOS packages, update manifests (UPL.xml), and peripheral firmware.
0x0003 (SPKG Header) 0x0280 (640 B exact) <member_name>.spkg_hdr.1 (in 0x501) Detached 640-byte alternate SCE\0 headers (FW 3.56+) matching each SPKG member in 0x300; identical 32-byte common header (0x00..0x1F) with re-signed metadata/ECDSA blocks (0x20..0x27F).

3. Flags, Enums & Decoding Formulas

Canonical Entry ID Registry

PS3 PUP entry_id Mapping
Entry ID Canonical Filename Payload Format Role & Firmware Notes
0x100 version.txt ASCII text + LF Human-readable firmware version string (e.g., "4.93\n").
0x101 license.xml UTF-8 XML or 3B stub Multi-locale EULA XML (<xml version="1.0" encoding="UTF-8"><locale ...>) from FW 2.40+; 3-byte placeholder "..." in FW 1.02–2.36.
0x102 promo_flags.txt ASCII text Optional promotional / kiosk / shop (SEX) targeting flags; absent from standard retail CEX updates.
0x103 update_flags.txt ASCII text + LF 4-character update mode flag introduced in FW 2.50: "0000\n" for full PS3UPDAT.PUP packages; "1000\n" for incremental PS3PATCH.PUP delta updates.
0x104 patch_build.txt ASCII text + LF Present in incremental PS3PATCH.PUP updates; declares required base version and decimal image_version (e.g., "4.66 64645\n").
0x200 ps3swu.self SCE SELF (cat=1) Primary System Software Updater binary signed with key_revision = 0x0001 for compatibility with pre-3.56 consoles.
0x201 vsh.tar POSIX ustar TAR Updater VSH helper resources (vsh/etc/*.bin, layout_*.txt, 624,640 B) in FW 1.02–1.32; reduced to a 10,240-byte stub archive containing a single 0-byte file named a from FW 1.50 onward.
0x202 dots.txt UTF-8 XML or 3B stub Introduced in FW 2.20 holding localized release-note strings (msg_updater_*); replaced by the 3-byte stub "..." from FW 2.35 onward.
0x203 patch_data.pkg SCE SPKG (cat=3) Present in incremental PS3PATCH.PUP packages; encrypted/compressed patch metadata and delta payload.
0x300 update_files.tar POSIX ustar TAR Primary flash update payload archive containing UPL.xml.pkg, CORE_OS_PACKAGE.pkg, timestamped dev_flash_*.tar.aa.* / dev_flash3_* packages, RL_FOR_*.img, and peripheral firmware SPKGs.
0x501 spkg_hdr.tar POSIX ustar TAR Introduced in FW 3.56; contains detached 640-byte .spkg_hdr.1 alternate headers for every category = 3 SPKG member in 0x300.
0x601 ps3swu2.self SCE SELF (cat=1) Introduced in FW 3.56; secondary System Software Updater binary signed with key_revision = 0x000D for FW 3.56+ consoles and later hardware revisions.

Header Size & HMAC-SHA1 Integrity Formulas

  • Header Size Derivation:
    expected_header_length = 0x30 + (file_count * 0x20) + (file_count * 0x20) + 0x20 = 0x50 + (file_count * 0x40)
  • Header Integrity Check:
    computed_header_hmac = HMAC_SHA1(pup_hmac_key, file[0x00 .. header_length - 0x20])
    Valid when computed_header_hmac == file[header_length - 0x20 .. header_length - 0x0C].
  • Per-Entry Integrity Check:
    For each Hash Entry Record h referencing e = file_entries[h.entry_index]:
    computed_entry_hmac = HMAC_SHA1(pup_hmac_key, file[e.data_offset .. e.data_offset + e.data_length])
    Valid when computed_entry_hmac == h.hmac_sha1.

4. Edge Cases & Loader / Parser Rules

  • Blu-ray Disc 256 MiB Zero-Padding: Retail disc /PS3_UPDATE/PS3UPDAT.PUP files are padded with trailing 0x00 bytes to exactly 268,435,456 bytes (0x10000000), even when header_length + data_length is smaller (for example, ~125 MiB on FW 1.93 or ~194 MiB on FW 3.73). Parsers MUST assert actual_file_size >= header_length + data_length (never require exact equality!) and restrict all reads and hash checks to [0 .. header_length + data_length).
  • Hash Table Indirection (entry_index vs entry_id): Hash Entry Records reference File Entry Records by 0-based table position entry_index (0 .. file_count - 1), not by entry_id. Always validate entry_index < file_count and ensure every entry index is covered once without duplicates.
  • Contiguous Unaligned Payloads & Bounds Validation: Payloads pack contiguously starting at header_length with zero inter-entry alignment padding (e.g., if 0x100 is 5 bytes, 0x101 begins at header_length + 5). Still honor each entry's explicit data_offset and assert header_length >= 0x50 + file_count * 0x40, data_offset >= header_length, and data_offset + data_length <= header_length + data_length using overflow-safe integer arithmetic.
  • FW 3.56+ Dual-Key Updater Selection: Starting with firmware 3.56, Sony introduced new signing keys while retaining backward-compatible entry 0x200 (ps3swu.self, key_revision = 0x0001) alongside 0x601 (ps3swu2.self, key_revision = 0x000D). Pre-3.56 consoles execute 0x200 and verify the embedded SPKG headers in 0x300; FW 3.56+ consoles execute 0x601 and verify the detached 640-byte .spkg_hdr.1 headers from 0x501 paired with the encrypted payloads in 0x300.
  • Inner SPKG Compression & dev_flash Extraction: Inside 0x300 (update_files.tar), each category = 3 SPKG member's data_len field (+0x18 in the SCE\0 common header) declares the uncompressed inner payload length, whereas the stored bytes after header_len (0x280) are AES-encrypted and typically zlib-compressed. Decrypting and decompressing dev_flash_*.tar.aa.<timestamp> yields inner POSIX TAR archives targeting /dev_flash/ (and dev_flash3_* targeting /dev_flash3/).
  • Incremental PS3PATCH.PUP Handling: When 0x103 (update_flags.txt) is "1000\n" and 0x104 (patch_build.txt) / 0x203 (patch_data.pkg) are present, update_files.tar contains a partial delta set applicable only to the exact base firmware version named in patch_build.txt, not a standalone full system flash image.

5. Parser Pseudocode

const PUP_MAGIC = 0x5343455546000000  // "SCEUF\0\0\0"

const ENTRY_NAMES = {
    0x100: "version.txt",
    0x101: "license.xml",
    0x102: "promo_flags.txt",
    0x103: "update_flags.txt",
    0x104: "patch_build.txt",
    0x200: "ps3swu.self",
    0x201: "vsh.tar",
    0x202: "dots.txt",
    0x203: "patch_data.pkg",
    0x300: "update_files.tar",
    0x501: "spkg_hdr.tar",
    0x601: "ps3swu2.self",
}

function parse_ps3_pup(stream, pup_hmac_key = null, verify_hmac = true):
    actual_size = actual_file_size(stream)
    assert actual_size >= 0x30

    magic           = read_u64be(stream, 0x00)
    package_version = read_u64be(stream, 0x08)
    image_version   = read_u64be(stream, 0x10)
    file_count      = read_u64be(stream, 0x18)
    header_length   = read_u64be(stream, 0x20)
    data_length     = read_u64be(stream, 0x28)

    assert magic == PUP_MAGIC
    assert package_version == 1
    assert file_count <= (actual_size - 0x50) / 0x40  // overflow-safe entry bound

    min_header_len = 0x50 + (file_count * 0x40)
    assert header_length >= min_header_len
    assert header_length <= actual_size
    assert data_length <= actual_size - header_length  // allows trailing 256 MiB disc zero-padding

    total_pup_end = header_length + data_length

    if verify_hmac and pup_hmac_key != null:
        header_body      = read_bytes(stream, 0x00, header_length - 0x20)
        stored_hdr_hmac  = read_bytes(stream, header_length - 0x20, 20)
        assert hmac_sha1(pup_hmac_key, header_body) == stored_hdr_hmac

    // 1. Parse File Entry Table (starting at 0x30, 32 bytes each)
    file_entries = []
    for i in 0 .. file_count - 1:
        base       = 0x30 + (i * 0x20)
        entry_id   = read_u64be(stream, base + 0x00)
        offset     = read_u64be(stream, base + 0x08)
        length     = read_u64be(stream, base + 0x10)
        // base + 0x18..0x1F is reserved zero padding

        assert offset >= header_length
        assert length <= total_pup_end - offset
        name = ENTRY_NAMES.get(entry_id, format("unknown_{0:04x}.bin", entry_id))
        file_entries.append({ id: entry_id, name: name, offset: offset, length: length })

    // 2. Parse Hash Entry Table (starting at 0x30 + file_count * 0x20, 32 bytes each)
    hash_table_base = 0x30 + (file_count * 0x20)
    seen_indices = set()
    for i in 0 .. file_count - 1:
        base        = hash_table_base + (i * 0x20)
        entry_index = read_u64be(stream, base + 0x00)
        stored_hmac = read_bytes(stream, base + 0x08, 20)
        // base + 0x1C..0x1F is 4-byte reserved zero padding

        assert entry_index < file_count
        assert entry_index not in seen_indices
        seen_indices.add(entry_index)

        if verify_hmac and pup_hmac_key != null:
            target = file_entries[entry_index]
            payload = read_bytes(stream, target.offset, target.length)
            assert hmac_sha1(pup_hmac_key, payload) == stored_hmac

    // 3. Optional: read member payloads (e.g., inspect POSIX ustar TARs for 0x201, 0x300, 0x501)
    return {
        package_version: package_version,
        image_version: image_version,
        header_length: header_length,
        data_length: data_length,
        entries: file_entries
    }

6. Provenance & Confidence

  • Confirmed Spec Container & Retail Schemas: The 48-byte SCEUF main header, 32-byte File Entry and Hash Entry tables, 32-byte header HMAC footer, entry IDs (0x100, 0x101, 0x103, 0x104, 0x200–0x203, 0x300, 0x501, 0x601), the 5-schema evolution across retail firmware versions 1.02–4.93 and PS3PATCH.PUP, 256 MiB Blu-ray disc zero-padding, POSIX ustar inner TAR layouts, and SCE\0 category 1/2/3 inner headers are verified empirically across official retail firmware packages and disc updates.
  • SDK-Revision-Dependent Unverified / Reserved Non-Retail Variants & Reserved Padding: Promotional/kiosk/DEX-targeted entry IDs (such as 0x102 promo_flags.txt or debug-only updater records), undocumented update_flags.txt bit combinations outside retail 0000/1000, and the trailing padding fields in File Entry, Hash Entry, and Header Footer records (observed as all-zero across retail releases) are SDK/target-dependent or vendor-reserved.

Cryptographic Key Caveat: Sony's PUP HMAC-SHA1 verification key, SELF (ps3swu.self / ps3swu2.self) decryption keys, and SPKG/RVK AES and ECDSA keys are proprietary and intentionally omitted from this specification. Outer PUP parsing, entry extraction, plaintext metadata reading (version.txt, license.xml, update_flags.txt, patch_build.txt, dots.txt), and TAR member enumeration (vsh.tar, update_files.tar, spkg_hdr.tar) operate cleanly without private keys.
