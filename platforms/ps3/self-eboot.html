EBOOT.BIN / SELF / SPRX (PS3 Signed ELF)

PlayStation 3 Executable & Shared Library Format

SELF (Signed ELF) is Sony Computer Entertainment's encrypted and ECDSA-signed container wrapping CellOS 64-bit big-endian PowerPC executables (EBOOT.BIN, *.self) and relocatable dynamic modules (*.sprx), as well as standalone SPU modules. Unencrypted metadata mirrors ELF headers outside the ciphertext so loaders can validate alignment and allocate segments prior to decryption.

1. Identification & Scope

Every signed PlayStation 3 binary begins with the 32-byte SCE Common Header identified by magic 0x53434500 (53 43 45 00, ASCII "SCE\0"). When category == 1 (SELF), the file embeds an Extended SELF Header, Application Info, plaintext copies of the ELF64 header and program headers, a Section Info table, optional SCE Version and Control Info records (including NPDRM blocks), an encrypted Metadata region containing per-segment AES-128 keys/IVs and SHA-1 digests, an ECDSA signature, and finally the encrypted (and optionally zlib-compressed) ELF segment payloads.

Unlike PARAM.SFO (which is little-endian), the entire SELF envelope and its contained CellOS PPU/SPU ELF binaries are strictly big-endian. Decryption of a retail SELF strips the outer SCE wrapper to reconstruct a standard big-endian ELF64 (e_machine = 0x0015, EM_PPC64) or ELF32 (e_machine = 0x0017, EM_SPU) image.

2. Binary Layout Tables

SCE Common Header (32 bytes, offset 0x00..0x1F)
Offset Size Type Field Description
0x00 4 u32be magic Container signature: 0x53434500 ("SCE\0").
0x04 4 u32be version SCE header format version: 2 on standard PS3 retail binaries; 3 in newer/extended SCE revisions.
0x08 2 u16be key_revision Key revision / attribute selector (e.g., 0x0001..0x001C; bit 15 0x8000 marks debug/FSELF).
0x0A 2 u16be category SCE container category: 1 = SELF, 2 = RVK, 3 = PKG, 4 = SPP.
0x0C 4 u32be metadata_offset Offset of MetadataInfo relative to 0x20 (file_offset = 0x20 + metadata_offset).
0x10 8 u64be header_len Total SCE header length in bytes; segment payload data begins at or after this offset.
0x18 8 u64be data_len Declared payload length (size of embedded ELF data or encrypted payload region).

Offset Size Type Field Description
0x20 8 u64be header_type Extended header format type (3 for PS3 SELF).
0x28 8 u64be app_info_offset Absolute file offset of the AppInfoHeader (typically 0x70).
0x30 8 u64be elf_offset Absolute file offset of the embedded ELF64/ELF32 header copy (typically 0x90).
0x38 8 u64be phdr_offset Absolute file offset of the ELF Program Header table copy (typically 0xD0).

0x50 8 u64be sce_version_offset Absolute file offset of the SceVersionInfo record, or 0 if omitted.
0x58 8 u64be control_info_offset Absolute file offset of the chained ControlInfo records, or 0.
0x60 8 u64be control_info_size Total byte length of all chained ControlInfo records.

Offset Size Type Field Description

0x08 8 u64be size Stored byte size in the SELF file (compressed size if compressed == 2).
0x10 4 u32be compressed 1 = uncompressed, 2 = zlib deflate stream.

+0x18 8 u8[8] reserved (In MetadataHeader) Reserved zero fields.
MetadataSectionHeader (48 bytes each, section_count entries after MetadataHeader)
Offset Size Type Field Description
0x00 8 u64be data_offset Absolute file offset of the encrypted/compressed segment payload.
0x08 8 u64be data_size Stored byte size of the segment payload.
0x10 4 u32be type Segment type: 1 = SPU/SHDR, 2 = PHDR (LOAD), 3 = SCE/Note.
0x14 4 u32be program_idx Index into the ELF Phdr[] table corresponding to this segment.
0x18 4 u32be hashed 2 if a 20-byte SHA-1 hash is stored in the key table at sha1_idx.
0x1C 4 u32be sha1_idx 16-byte slot index into the key table for the segment SHA-1 digest (or 0xFFFFFFFF).
0x20 4 u32be encrypted 3 = AES-128-CTR encrypted, 1 = unencrypted.
0x24 4 u32be key_idx 16-byte slot index for AES-128 segment key (or 0xFFFFFFFF).
0x28 4 u32be iv_idx 16-byte slot index for AES-128-CTR segment IV (or 0xFFFFFFFF).
0x2C 4 u32be compressed 2 = zlib deflate compressed, 1 = uncompressed.

3. Flags, Enums & Decoding Formulas

  • SCE category (0x0A): 1 = SELF executable/PRX, 2 = RVK (revocation list), 3 = PKG/other SCE data, 4 = SPP (security policy profile).
  • SCE key_revision / attribute (0x08): Lower bits encode the firmware key-generation era (0x0001..0x001C+ across PS3 system software releases); bit 15 (0x8000) denotes an unencrypted debug / Fake SELF (FSELF) used on development kits.
  • AppInfoHeader.self_type (+0x0C):
    • 1 = LV0 bootloader, 2 = LV1 hypervisor, 3 = LV2 CellOS kernel
    • 4 = Standard Disc/HDD Application (EBOOT.BIN / .sprx)
    • 5 = Isolated SPU Module, 6 = Secure Loader
    • 8 = NPDRM Application / Module (requires ControlInfo type 3 NPD\0 key unwrap)
  • Segment Encryption & Compression Mapping:
    • SectionInfo.compressed == 2 (or MetadataSectionHeader.compressed == 2): payload must be decrypted first (if encrypted), then inflated via standard RFC 1950 zlib (0x78 CMF header) into the ELF segment buffer of size Phdr.p_filesz.
    • MetadataSectionHeader.encrypted == 3: decrypt with AES-128-CTR using key_table[key_idx] and key_table[iv_idx] (counter incremented per 16-byte block).
  • Key Table Indexing Formula: Each slot in the metadata key table is 16 bytes wide, starting at key_table_offset = metadata_header_end + section_count * 0x30. A 20-byte SHA-1 digest occupies two consecutive slots (32 bytes, padded with 12 trailing zero bytes), while an AES key or IV occupies one slot (16 bytes).

4. Edge Cases & Loader / Parser Rules

  • SCE Header Version 2 vs Version 3: Standard PS3 executables and SPRX files use version = 2, where metadata_offset at 0x0C is relative to 0x20 and header_len/data_len are u64be. Version 3 headers appear in certain later SCE tools/platforms and may adjust extended header alignment or add additional ControlInfo / capability blocks; parsers should reject unsupported version values unless explicitly handled.
  • Debug / FSELF vs Retail Encrypted SELF: When (key_revision & 0x8000) != 0 or SectionInfo.encrypted == 0 for all segments, segment payloads are stored unencrypted (though they may still be zlib-compressed). In retail SELFs, MetadataInfo must be decrypted before segment keys are known.
  • NPDRM vs Non-NPDRM Key Unwrapping: If self_type == 8 (or a Type 3 NPD\0 control record is present), the MetadataInfo decryption layer requires the 16-byte title klicensee (obtained from a console .rif/.rap or free license table) mixed with the SCE NPDRM key prior to AES-256-CBC unwrapping.
  • Zlib-Compressed Segments & ELF Reconstruction: When reconstructing an ELF from a decrypted SELF, copy the plaintext ELF header (elf_offset) and program headers (phdr_offset), and optionally the section headers (shdr_offset if non-zero), then write each decompressed segment at its ELF Phdr[program_idx].p_offset (NOT the SELF data_offset).
  • Generalized CellOS PPU ELF64 Loader Mapping:
    • EI_OSABI = 0x66 (CellOS LV2), e_machine = 0x0015 (PPC64), e_type = 0x0002 (ET_EXEC) or 0xFFA4 (ET_SCE_PPURELEXEC for SPRX).
    • OPD & TOC: e_entry points to an 8-byte (or 16-byte) Procedure Descriptor { u64be code_vaddr, u64be toc_vaddr }; the loader sets PC = code_vaddr and r2 = toc_vaddr.
    • PT_PROC_PARAM (0x60000001) & PT_PROC_PRX (0x60000002): Store process stack/SDK metadata and the sys_prx_module_info_t header describing PRX library export/import tables keyed by 32-bit NID hashes and stub descriptor addresses.
    • Embedded SPU ELFs: SPU programs appear either as standalone SELF files (self_type == 5) or as embedded 32-bit big-endian ELFs (e_machine = 0x0017, EM_SPU) inside PPU data segments loaded into 256 KiB SPU Local Stores.

5. Parser Pseudocode

function parse_ps3_self(stream, key_resolver, klicensee = null):
    sce_magic = read_u32be(stream, 0x00)
    assert sce_magic == 0x53434500  // "SCE\0"
    sce_version     = read_u32be(stream, 0x04)
    key_revision    = read_u16be(stream, 0x08)
    category        = read_u16be(stream, 0x0A)
    metadata_offset = read_u32be(stream, 0x0C)
    header_len      = read_u64be(stream, 0x10)
    data_len        = read_u64be(stream, 0x18)

    assert sce_version in (2, 3) and category == 1

    // Extended SELF Header (0x20..0x67)
    app_info_off     = read_u64be(stream, 0x28)
    elf_off          = read_u64be(stream, 0x30)
    phdr_off         = read_u64be(stream, 0x38)
    shdr_off         = read_u64be(stream, 0x40)
    section_info_off = read_u64be(stream, 0x48)
    control_info_off = read_u64be(stream, 0x58)
    control_info_sz  = read_u64be(stream, 0x60)

    auth_id   = read_u64be(stream, app_info_off + 0x00)
    self_type = read_u32be(stream, app_info_off + 0x0C)

    // Walk ControlInfo chain for NPDRM ("NPD\0") if present
    npd_record = null
    if control_info_off != 0 and control_info_sz > 0:
        cur = control_info_off
        while cur < control_info_off + control_info_sz:
            rec_type = read_u32be(stream, cur + 0x00)
            rec_size = read_u32be(stream, cur + 0x04)
            has_next = read_u64be(stream, cur + 0x08)
            if rec_type == 3 and read_u32be(stream, cur + 0x10) == 0x4E504400:
                npd_record = parse_npdrm_record(stream, cur)
            if has_next == 0 or rec_size == 0:
                break
            cur += rec_size

    // Parse embedded ELF header & Phdr table
    elf_class = read_u8(stream, elf_off + 0x04)  // 2 = ELF64 (PPU), 1 = ELF32 (SPU)
    e_phoff   = read_u64be(stream, elf_off + 0x20) if elf_class == 2 else read_u32be(stream, elf_off + 0x1C)
    e_phentsz = read_u16be(stream, elf_off + (0x36 if elf_class == 2 else 0x2A))
    e_phnum   = read_u16be(stream, elf_off + (0x38 if elf_class == 2 else 0x2C))

    phdr = []
    out_elf_size = e_phoff + e_phnum * e_phentsz
    for i in 0 .. e_phnum - 1:
        p_base   = phdr_off + i * e_phentsz
        p_offset = read_u64be(stream, p_base + 0x08) if elf_class == 2 else read_u32be(stream, p_base + 0x04)
        p_filesz = read_u64be(stream, p_base + 0x20) if elf_class == 2 else read_u32be(stream, p_base + 0x10)
        phdr.append({ p_offset: p_offset, p_filesz: p_filesz })
        out_elf_size = max(out_elf_size, p_offset + p_filesz)

    is_debug = (key_revision & 0x8000) != 0
    out_elf  = allocate_buffer(out_elf_size)
    copy_bytes(stream, elf_off, out_elf, 0, 64 if elf_class == 2 else 52)
    copy_bytes(stream, phdr_off, out_elf, e_phoff, e_phnum * e_phentsz)

    if is_debug:
        // Unencrypted FSELF path using SectionInfo[]
        for i in 0 .. e_phnum - 1:
            si_off     = section_info_off + i * 0x20
            seg_off    = read_u64be(stream, si_off + 0x00)
            seg_size   = read_u64be(stream, si_off + 0x08)
            compressed = read_u32be(stream, si_off + 0x10)
            raw = read_bytes(stream, seg_off, seg_size)
            if compressed == 2:
                raw = zlib_decompress(raw)
            write_bytes(out_elf, phdr[i].p_offset, raw)
        return out_elf

    // Retail encrypted SELF path
    meta_info_off = 0x20 + metadata_offset
    (erk, riv) = key_resolver.derive_metadata_keys(self_type, key_revision, npd_record, klicensee)
    enc_meta_info = read_bytes(stream, meta_info_off, 0x40)
    if npd_record != null:
        enc_meta_info[0x00..0x10] = aes128_ecb_decrypt(klicensee_np_key, enc_meta_info[0x00..0x10])
    meta_info = aes256_cbc_decrypt(erk, riv, enc_meta_info)
    assert meta_info[0x10..0x20] == zeros(16) and meta_info[0x30..0x40] == zeros(16)

    meta_key = meta_info[0x00..0x10]
    meta_iv  = meta_info[0x20..0x30]
    enc_hdr_len = header_len - (meta_info_off + 0x40)
    meta_body = aes128_ctr_decrypt(meta_key, meta_iv, read_bytes(stream, meta_info_off + 0x40, enc_hdr_len))

    section_count = read_u32be(meta_body, 0x0C)
    key_count     = read_u32be(meta_body, 0x10)
    key_table_off = 0x20 + section_count * 0x30

    for s in 0 .. section_count - 1:
        sh_off      = 0x20 + s * 0x30
        d_off       = read_u64be(meta_body, sh_off + 0x00)
        d_size      = read_u64be(meta_body, sh_off + 0x08)
        s_type      = read_u32be(meta_body, sh_off + 0x10)
        prog_idx    = read_u32be(meta_body, sh_off + 0x14)
        hashed      = read_u32be(meta_body, sh_off + 0x18)
        sha1_idx    = read_u32be(meta_body, sh_off + 0x1C)
        encrypted   = read_u32be(meta_body, sh_off + 0x20)
        key_idx     = read_u32be(meta_body, sh_off + 0x24)
        iv_idx      = read_u32be(meta_body, sh_off + 0x28)
        compressed  = read_u32be(meta_body, sh_off + 0x2C)

        seg = read_bytes(stream, d_off, d_size)
        if encrypted == 3:
            s_key = meta_body[key_table_off + key_idx * 16 .. +16]
            s_iv  = meta_body[key_table_off + iv_idx  * 16 .. +16]
            seg   = aes128_ctr_decrypt(s_key, s_iv, seg)
        if hashed == 2:
            expected_sha1 = meta_body[key_table_off + sha1_idx * 16 .. +20]
            assert sha1(seg) == expected_sha1
        if compressed == 2:
            seg = zlib_decompress(seg)
        if s_type == 2:  // PHDR LOAD segment
            write_bytes(out_elf, phdr[prog_idx].p_offset, seg)

    return out_elf

6. Provenance & Confidence

  • Confirmed Specification: The 32-byte SCE Common Header, 72-byte Extended SELF Header, 32-byte AppInfo, 32-byte SectionInfo, ControlInfo chaining, 64-byte MetadataInfo, 32-byte MetadataHeader, 48-byte MetadataSectionHeader, and CellOS ELF64-PPC64/ELF32-SPU structures are fully verified across retail PS3 firmware and SDK binaries.
  • Firmware-Revision & Crypto-Gated Fields: Key selection depends on key_revision + self_type mapped to firmware-era root keys (ERK/RIV) and ECDSA curve parameters; capability flags inside opt_header_size vary by SDK version and privilege level.

Cryptographic Key Caveat: Retail SCE ERK/RIV keys, ECDSA private signing keys, and NPDRM master keys are proprietary and intentionally omitted from this specification. An external key resolver or valid user-supplied console license (.rif / .rap) is required to decrypt retail payloads; structural header parsing remains possible without keys.
