TROPHY.TRP (PS3 Trophy Archive Container)

PlayStation 3 Trophy Configuration & Asset Archive

TROPHY.TRP is the big-endian flat archive container used by the PlayStation 3 system software to bundle trophy definitions (TROPCONF.SFM), localized trophy text (TROP.SFM / TROP_XX.SFM), and PNG trophy/set icons (ICON0.PNG, TROP###.PNG, GR####.PNG). Revisions v1 through v3 share a 64-byte header and 64-byte entry records while progressively adding SHA-1 whole-archive integrity and entry-level encryption flags.

1. Identification & Scope

Every PlayStation 3 trophy archive starts with the 4-byte big-endian magic 0xDCA24D00 (bytes DC A2 4D 00, non-ASCII). All numeric fields in the 64-byte header and the contiguous 64-byte entry directory are big-endian. Each title's trophy set is identified by its 12-character NP communication ID (NPWR#####_00) matching NP_COMMUNICATION_ID in PARAM.SFO.

Inside the archive, .SFM members are plain UTF-8 XML documents (TROPCONF.SFM for structural definitions and TROP.SFM / TROP_XX.SFM for localized strings), accompanied by standard PNG images (ICON0.PNG and TROP###.PNG).

2. Binary Layout Tables

TROPHY.TRP Header (64 bytes, offset 0x00..0x3F, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be magic Container signature: 0xDCA24D00.
0x04 4 u32be version Archive format version: 1, 2, or 3.
0x08 8 u64be file_size Total size of the TROPHY.TRP archive in bytes.
0x10 4 u32be entry_count Number of 64-byte file entry records starting at 0x40.
0x14 4 u32be entry_size Byte size of each entry record (always 0x40 = 64 bytes).
0x18 4 u32be dev_flag Development/mode flag (0 = standard retail, 1 = dev/special; zero padding in v1).
0x1C 20 u8[20] sha1_digest (v2 & v3) Whole-file SHA-1 digest with bytes 0x1C..0x2F zeroed; zeroed in v1.
0x30 16 u8[16] padding Reserved zero padding (0x00) up to 0x40.
TRP File Entry Record (64 bytes per entry starting at 0x40, Big-Endian)
Offset Size Type Field Description
0x00 32 char[32] name NUL-padded ASCII filename (max 31 chars + NUL, e.g., "TROPCONF.SFM", "TROP000.PNG").
0x20 8 u64be offset Absolute byte offset of the member file payload from start of TROPHY.TRP.
0x28 8 u64be size Byte length of the member file payload.
0x30 4 u32be flags Entry flags: 0 = plaintext/unencrypted; non-zero (e.g., 1 or 3 in v3) marks special/encrypted entry handling.
0x34 12 u8[12] padding Reserved zero padding.
Standard Embedded Member Files
Filename Format Typical Role
TROPCONF.SFM UTF-8 XML Master configuration: <trophyconf>, <npcommid>, <trophyset-version>, <trophy id="000" hidden="..." ttype="P|G|S|B" pid="...">, and optional <group> nodes.
TROP.SFM UTF-8 XML Default/fallback localized names (<name>) and descriptions (<detail>) for the trophy set and each trophy ID.
TROP_XX.SFM UTF-8 XML Language-specific localization files where XX is a 2-digit CellOS language code (00=JP, 01=EN-US, 02=FR, 03=ES, 04=DE, 05=IT, etc.).
ICON0.PNG PNG (320×176) Trophy set title banner displayed in the XMB Trophy Collection.
TROP###.PNG PNG (240×240) Per-trophy icon matching zero-padded 3-digit id (TROP000.PNG .. TROP999.PNG).
GR####.PNG PNG (320×176) Optional per-group banner for base game / DLC trophy groups (GR0001.PNG, etc.).

3. Flags, Enums & Decoding Formulas

  • Header version Evolution (v1 / v2 / v3):
    • Version 1: No header SHA-1 digest (bytes 0x18..0x3F are zeroed); all entry flags are 0 (plaintext).
    • Version 2: Introduces the 20-byte whole-archive sha1_digest at 0x1C..0x2F (and dev_flag at 0x18).
    • Version 3: Retains the 0x1C SHA-1 digest and adds support for non-zero entry flags (including AES-128-CBC encrypted .SFM/.PNG payloads on systems/SDKs using TRP v3 entry encryption).
  • Entry flags (+0x30):
    • 0x00000000: Standard unencrypted file payload (directly readable as XML or PNG).
    • 0x00000001 / 0x00000003 (v3): Encrypted or protected payload (typically AES-128-CBC with first 16 bytes serving as IV and PKCS#7-like padding in v3 encrypted entries).
  • TROPCONF.SFM Trophy Grades (ttype): P = Platinum, G = Gold, S = Silver, B = Bronze; hidden="yes"|"no" controls pre-unlock visibility; pid binds DLC trophies to base/group indices.
  • SHA-1 Integrity Formula (version >= 2):
    computed_sha1 = SHA1(file[0x00..0x1C] || zeros(20) || file[0x30..file_size])
    Valid when computed_sha1 == file[0x1C..0x30].

4. Edge Cases & Loader / Parser Rules

  • Entry Stride Respect: Always advance entry table reads by entry_size (at 0x14) rather than hardcoding 64, and assert entry_size >= 0x34.
  • Data Alignment & Bounds: Member offsets typically align to 16 or 64 bytes after 0x40 + entry_count * entry_size. Validate offset + size <= file_size and offset >= 0x40 + entry_count * entry_size before reading any member payload.
  • Encrypted v3 Payloads vs Plaintext PS3 Payloads: Most PS3 retail disc/PSN TROPHY.TRP files store flags == 0 (plaintext) even under header v2; however, when encountering version == 3 with non-zero flags (notably flags == 3), a naive parser must not feed raw ciphertext to XML/PNG decoders—check PNG signature (89 50 4E 47) or XML prolog (<?xml) if decrypting without prior flag inspection.
  • Language Code Resolution: If a matching TROP_XX.SFM is absent for the active CellOS language index, the system falls back to TROP.SFM.

5. Parser Pseudocode

function parse_trophy_trp(stream, verify_hash = true, trp_aes_key = null):
    magic = read_u32be(stream, 0x00)
    assert magic == 0xDCA24D00

    version     = read_u32be(stream, 0x04)
    file_size   = read_u64be(stream, 0x08)
    entry_count = read_u32be(stream, 0x10)
    entry_size  = read_u32be(stream, 0x14)
    dev_flag    = read_u32be(stream, 0x18)
    stored_sha1 = read_bytes(stream, 0x1C, 20)

    assert version in (1, 2, 3)
    assert entry_size >= 0x34
    assert actual_file_size(stream) >= file_size

    if verify_hash and version >= 2:
        buf = read_bytes(stream, 0x00, file_size)
        buf[0x1C .. 0x30] = zeros(20)
        assert sha1(buf) == stored_sha1

    table_end = 0x40 + entry_count * entry_size
    entries = []
    for i in 0 .. entry_count - 1:
        base    = 0x40 + i * entry_size
        name    = decode_ascii(split_at_first_nul(read_bytes(stream, base + 0x00, 32)))
        offset  = read_u64be(stream, base + 0x20)
        size    = read_u64be(stream, base + 0x28)
        flags   = read_u32be(stream, base + 0x30)

        assert offset >= table_end and offset + size <= file_size
        payload = read_bytes(stream, offset, size)

        if flags != 0:
            assert trp_aes_key != null  // v3 encrypted entry (flags == 3 / encrypted)
            iv = payload[0x00 .. 0x10]
            payload = aes128_cbc_decrypt_pkcs7(trp_aes_key, iv, payload[0x10 .. size])

        entries.append({ name: name, offset: offset, size: size, flags: flags, data: payload })

    return { version: version, dev_flag: dev_flag, entries: entries }

6. Provenance & Confidence

  • Confirmed Specification: The 64-byte TRP header, 64-byte entry layout, 0xDCA24D00 magic, v2/v3 SHA-1 verification over a zeroed 0x1C..0x2F digest field, and TROPCONF.SFM / TROP*.SFM XML schemas are fully confirmed across PS3 retail releases.
  • Revision-Dependent Fields: Entry-level encryption under version == 3 (non-zero flags) is primarily observed in later SDK/cross-generation trophy archives, whereas the majority of PS3-era TROPHY.TRP archives use v1 or v2 with flags == 0.

Cryptographic Key Caveat: For TRP v3 archives that set per-entry encryption flags, the AES-128 Trophy key is proprietary and omitted from this specification. Unencrypted v1/v2 archives and header/entry metadata remain directly inspectable without keys.
