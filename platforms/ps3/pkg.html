.pkg & .rap (PS3 PSN Package & License)

PlayStation 3 Digital Distribution & Activation Format

The PS3 .pkg format is Sony's big-endian installation archive for PlayStation Network titles, game patches, DLC, themes, and avatars. It encapsulates a 192-byte header, a big-endian Type-Length-Value (TLV) metadata block, an encrypted file/directory item table with payloads, and an integrity/signature footer. Paid NPDRM packages pair with a 16-byte .rap activation key.

1. Identification & Scope

A PS3 .pkg archive is recognized by the 4-byte big-endian magic 0x7F504B47 ("\x7FPKG"). Note that this differs from PlayStation 4 CNT packages (which use 0x7F434E54, "\x7FCNT"). All integer fields inside a PS3 .pkg—header offsets, TLV tags, item records, and sizes—are big-endian, even though extracted files inside the payload may include little-endian PARAM.SFO metadata.

The companion .rap file is a minimal 16-byte (128-bit) license key named <CONTENT_ID>.rap. It carries no header or magic bytes and is transformed by the console's NPDRM activation pipeline (together with act.dat and console IDPS) into a signed .rif file used to unlock NPDRM EBOOT.BIN / .edat content installed from the .pkg.

2. Binary Layout Tables

PS3 .pkg Main Header (192 bytes, offset 0x00..0xBF, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be magic Container signature: 0x7F504B47 ("\x7FPKG").
0x04 2 u16be pkg_revision Package status: 0x8000 = finalized/retail, 0x0000 = debug.
0x06 2 u16be pkg_type Target platform family: 0x0001 = PS3, 0x0002 = PSP / PSVita.
0x08 4 u32be metadata_offset Absolute offset where the metadata TLV block starts (typically 0xC0 or 0x100).
0x0C 4 u32be metadata_count Number of TLV entries in the metadata block.
0x10 4 u32be metadata_size Total byte length of the metadata TLV block.
0x14 4 u32be item_count Number of files and directories inside the encrypted item table.
0x18 8 u64be total_size Total size of the .pkg file in bytes.
0x20 8 u64be data_offset Absolute offset of the encrypted data region (item records + names + file payloads).
0x28 8 u64be data_size Byte length of the encrypted data region (from data_offset to footer).
0x30 48 char[48] content_id NUL-padded 36-character PSN Content ID (e.g., UP0000-NPUB00000_00-EXAMPLE000000000).
0x60 16 u8[16] qa_digest QA / content digest (also serves as the key seed for debug .pkg decryption).
0x70 16 u8[16] pkg_data_riv 128-bit AES-128-CTR initial counter (RIV) for retail .pkg data decryption.
0x80 64 u8[64] header_cmac_digest Header CMAC, NPDRM/SCE verification hashes, and signature fields (0x80..0xBF).
Metadata TLV Record (at metadata_offset, metadata_count records, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be id Metadata tag ID (see Section 3).
0x04 4 u32be size Byte length of the value payload immediately following.
0x08 size u8[size] value Big-endian integer, ASCII string, or digest bytes depending on id.
Decrypted Item Record (32 bytes per entry at data_offset, Big-Endian)
Offset Size Type Field Description
0x00 4 u32be name_offset Offset of UTF-8 relative path string, relative to data_offset.
0x04 4 u32be name_size Byte length of the relative path string (not guaranteed NUL-terminated).
0x08 8 u64be item_data_offset Offset of file payload bytes, relative to data_offset.
0x10 8 u64be item_data_size Byte length of file payload (0 for directory entries).
0x18 4 u32be flags Item type, encryption/overwrite flags, and target key index (see Section 3).
0x1C 4 u32be padding Reserved zero padding.
Trailing PKG Footer (typically 96 bytes at data_offset + data_size) & .rap File
Offset Size Type Field Description
0x00 64 u8[64] signature_block (PKG Footer) ECDSA/CMAC integrity signature over the package data/header.
0x40 20 u8[20] sha1_digest (PKG Footer) Whole-package SHA-1 digest preceding the final 12-byte padding.
0x54 12 u8[12] padding (PKG Footer) Trailing zero padding up to total_size.
0x00 16 u8[16] rap_key (.rap File) Raw 128-bit license activation key; exact file size is always 16 bytes.

3. Flags, Enums & Decoding Formulas

PKG Type & Revision Modes

  • pkg_revision & 0x8000: 1 = Retail finalized package (encrypted with AES-128-CTR using the platform key + pkg_data_riv); 0 = Debug/SDK package (encrypted with a custom SHA-1/XOR keystream derived from qa_digest).
  • pkg_type: 0x0001 = PlayStation 3 (uses PS3 AES-128 key); 0x0002 = PSP / PS Vita (may switch per-item keys based on flags).

Metadata TLV IDs

  • 0x01 = DRM Type (u32be: 1=Network, 2=Local, 3=Free)
  • 0x02 = Content Type (u32be: 0x04=GameData/Patch, 0x05=GameExec, 0x06=PS1/Theme, 0x07=Widget, 0x09=Theme, 0x0C=Avatar, 0x15=PSP, etc.)
  • 0x03 = Package Flags (u32be: EULA, Disc-required, Overwrite, etc.)
  • 0x04 = Package Installed Size (u32be/u64be)
  • 0x05 = Make Package Tool Version (u32be) · 0x06 = App Version / Title Version (u32be BCD)
  • 0x07 = QA Digest (u8[16]) · 0x08 = System Version (u32be)
  • 0x0A = Install Directory / SFO Info · 0x0B = Package Info / Revision

Item flags Bitmask (+0x18)

  • flags & 0xFF (Entry Type): 0x01 = NPDRM SELF, 0x02 = NPDRM EDAT, 0x03 = Raw Unprotected File, 0x04 = Directory, 0x0E = SDAT, 0x0F = NPDRM SPRX / Config.
  • flags & 0x80000000: Overwrite existing file on target installation path.
  • (flags >> 28) & 0x07: Key slot selector for PSP/Vita multi-key packages (0 = standard PS3 PKG key).

Key Derivation Models

  • Retail PS3 Data Stream (AES-128-CTR): The entire encrypted region [data_offset .. data_offset + data_size) is a single contiguous AES-128-CTR stream keyed with the PS3 retail PKG AES-128 key and initial counter pkg_data_riv (from 0x70). Every byte at relative offset rel is decrypted using counter pkg_data_riv + floor(rel / 16).
  • Debug Data Stream (SHA-1 Keystream): Debug PKGs construct a 64-byte state block by repeating qa_digest[0..7] and qa_digest[8..15] in alternating 8-byte lanes, hashing each 64-byte state with SHA-1 while incrementing a 64-bit big-endian counter in the final 8 bytes, and XORing the first 16 digest bytes per 16-byte data block.

4. Edge Cases & Loader / Parser Rules

  • Contiguous Stream Decryption: Item records, item path strings, and item file payloads all live inside the same contiguous encrypted byte range starting at data_offset. Random-access extraction of a single file at relative offset rel must advance the AES-128-CTR counter by rel / 16 blocks (never restart at counter 0!).
  • Extended PKG Header (0xC0..0xFF): Packages built with newer SDKs (especially cross-platform PS3/PSP/Vita PKGs) place an extended header at 0xC0 starting with magic 0x7F657874 ("\x7Fext"), pushing metadata_offset to 0x100 or later. Always seek to metadata_offset rather than hardcoding 0xC0.
  • Non-NUL-Terminated Paths: Item path names are sized explicitly by name_size; slice exact bytes rather than scanning for 0x00. Directory entries ((flags & 0xFF) == 0x04) have item_data_size == 0 and must be created on disk even when empty.
  • .rap vs .rif Activation Model: A .rap file is portable and contains only the 16-byte raw key; on a PS3, installing it transforms the 16-byte .rap through a fixed permutation + AES key-schedule to recover the klicensee, which is then encrypted using the console's act.dat key and IDPS into a 152-byte .rif.

5. Parser Pseudocode

function parse_ps3_pkg(stream, retail_pkg_aes_key):
    magic = read_u32be(stream, 0x00)
    assert magic == 0x7F504B47  // "\x7FPKG"

    pkg_rev    = read_u16be(stream, 0x04)
    pkg_type   = read_u16be(stream, 0x06)
    meta_off   = read_u32be(stream, 0x08)
    meta_cnt   = read_u32be(stream, 0x0C)
    meta_sz    = read_u32be(stream, 0x10)
    item_count = read_u32be(stream, 0x14)
    total_size = read_u64be(stream, 0x18)
    data_off   = read_u64be(stream, 0x20)
    data_sz    = read_u64be(stream, 0x28)
    content_id = read_ascii_z(stream, 0x30, 48)
    qa_digest  = read_bytes(stream, 0x60, 16)
    data_riv   = read_bytes(stream, 0x70, 16)

    // 1. Parse unencrypted Metadata TLV records
    metadata = {}
    cur = meta_off
    for i in 0 .. meta_cnt - 1:
        tlv_id  = read_u32be(stream, cur + 0x00)
        tlv_len = read_u32be(stream, cur + 0x04)
        tlv_val = read_bytes(stream, cur + 0x08, tlv_len)
        metadata[tlv_id] = tlv_val
        cur += 8 + tlv_len

    // 2. Helper to decrypt arbitrary slice [rel_off .. rel_off + len) inside data region
    is_retail = (pkg_rev & 0x8000) != 0
    function decrypt_data_slice(rel_off, length):
        enc = read_bytes(stream, data_off + rel_off, length)
        if is_retail:
            return aes128_ctr_at_offset(retail_pkg_aes_key, data_riv, rel_off, enc)
        else:
            return debug_sha1_xor_at_offset(qa_digest, rel_off, enc)

    // 3. Decrypt and parse Item Record table (item_count * 32 bytes at rel_off = 0)
    item_table = decrypt_data_slice(0, item_count * 0x20)
    entries = []
    for i in 0 .. item_count - 1:
        base      = i * 0x20
        name_off  = read_u32be(item_table, base + 0x00)
        name_sz   = read_u32be(item_table, base + 0x04)
        d_off     = read_u64be(item_table, base + 0x08)
        d_sz      = read_u64be(item_table, base + 0x10)
        flags     = read_u32be(item_table, base + 0x18)

        item_name = decode_utf8(decrypt_data_slice(name_off, name_sz))
        item_type = flags & 0xFF
        payload   = (item_type == 0x04) ? null : decrypt_data_slice(d_off, d_sz)
        entries.append({ name: item_name, type: item_type, flags: flags, data: payload })

    return { content_id: content_id, pkg_type: pkg_type, metadata: metadata, entries: entries }

6. Provenance & Confidence

  • Confirmed Specification: The 192-byte main header, TLV metadata encoding, 32-byte item table, debug SHA-1 XOR stream, retail AES-128-CTR stream addressing, and 16-byte .rap structure are completely documented and verified across PS3 retail and debug packages.
  • Revision-Dependent Fields: Extended headers (0xC0..0xFF) and additional TLV tags (0x0E+) appear in multi-platform (PS3/PSP/Vita) packages and later SDK builders.

Cryptographic Key Caveat: Sony's retail PS3 PKG AES-128 key, Vita/PSP key tables, ECDSA signing keys, and the static RAP-to-klicensee permutation/AES keys are proprietary and intentionally omitted. Debug packages can be decrypted purely from the public qa_digest at offset 0x60; retail decryption requires external key configuration.
