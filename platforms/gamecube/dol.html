GameCube Static Executable (.dol)

Platform Executable · Nintendo GameCube / Dolphin OS

Flat big-endian PowerPC static executable format containing a fixed 256-byte (0x0100) header defining up to 7 text (code) segments, 11 data segments, a zero-initialized BSS span, and an initial execution entry point.

None (identified structurally by valid 0x0100-byte header, segment bounds, and PowerPC RAM addresses)

Nintendo GameCube (IPL / Apploader / Dolphin OS; also inherited by Nintendo Wii)

1. Identification & Scope

Produced by the Dolphin SDK elf2dol tool, a .dol file strips ELF section names, symbol tables, and relocation records into a minimal loadable image. It contains no file magic signature and no internal section names.

  • Header Size: Exactly 0x0100 (256) bytes, always located at file offset 0x0000.
  • Segment Capacity: Fixed array of 7 Text (executable) slots and 11 Data (read-only/initialized) slots, totaling 18 loadable file segments plus 1 contiguous BSS zero-fill descriptor.
  • Endianness: All header fields and PowerPC instructions/data words are big-endian.

2. Binary Layout Tables

.dol Fixed 256-Byte Header (0x0000 – 0x00FF)
Offset Size Type Field Description
0x0000 0x1C (28) u32be[7] TextOffset[0..6] File offsets (from start of .dol) for Text segments 0..6. 0 if slot unused.
0x001C 0x2C (44) u32be[11] DataOffset[0..10] File offsets (from start of .dol) for Data segments 0..10. 0 if slot unused.
0x0048 0x1C (28) u32be[7] TextAddress[0..6] Virtual RAM load addresses for Text segments 0..6 (typically 0x80003100–0x817FFFFF).
0x0064 0x2C (44) u32be[11] DataAddress[0..10] Virtual RAM load addresses for Data segments 0..10.
0x0090 0x1C (28) u32be[7] TextSize[0..6] Byte lengths of Text segments 0..6. 0 if slot unused.
0x00AC 0x2C (44) u32be[11] DataSize[0..10] Byte lengths of Data segments 0..10. 0 if slot unused.
0x00D8 0x04 u32be BssAddress Virtual RAM start address of zero-initialized BSS span (0 if none).
0x00DC 0x04 u32be BssSize Byte length of BSS span to zero-fill (0 if none).
0x00E0 0x04 u32be EntryPoint Initial PowerPC execution address (__start).
0x00E4 0x1C (28) u8[28] Padding Zero-padded reserved bytes up to offset 0x0100.
0x0100 variable u8[] SegmentPayloads Raw binary payloads for active Text and Data segments referenced by the header offset/size arrays.

3. Flags, Enums & Decoding Formulas

Per-Slot Indexing Formula

Unlike interleaved section tables, .dol stores offsets, load addresses, and sizes in parallel arrays. For Text slot i (0 <= i < 7) and Data slot j (0 <= j < 11):

text_offset[i]  = read_u32be(hdr, 0x0000 + i * 4)
text_addr[i]    = read_u32be(hdr, 0x0048 + i * 4)
text_size[i]    = read_u32be(hdr, 0x0090 + i * 4)

data_offset[j]  = read_u32be(hdr, 0x001C + j * 4)
data_addr[j]    = read_u32be(hdr, 0x0064 + j * 4)
data_size[j]    = read_u32be(hdr, 0x00AC + j * 4)

Conventional Dolphin SDK Slot Assignment

The .dol format carries no permission bits beyond the Text vs. Data array split; however, standard Dolphin SDK elf2dol builds map ELF sections in the following order (skipping empty sections or packing sequentially into lower slots):

  • Text Slots (0..6): Typically Text[0] = .init (low startup code), Text[1] = .text (main program code); Text[2..6] unused (0).
  • Data Slots (0..10): Typically assigned across extab, extabindex, .ctors, .dtors, .rodata, .data, .sdata, and .sdata2.
  • BSS Span (0x00D8–0x00DF): Covers zero-initialized regions (.bss, .sbss, .sbss2) as a single contiguous address span [BssAddress, BssAddress + BssSize).

4. Edge Cases & Loader/Parser Rules

  • Zero-Size & Unused Segment Filtering: A segment slot is inactive whenever Offset == 0 or Size == 0. Some linkers or packers leave stale non-zero values in Address when Size == 0; loaders must filter strictly on Offset != 0 && Size != 0 (while flagging (Offset == 0) != (Size == 0) as malformed).
  • File Bounds & Minimum Offset: Every active segment must satisfy Offset >= 0x0100 and Offset + Size <= file_size (checked without 32-bit integer overflow).
  • BSS Span Overlapping Initialized Data: Because elf2dol represents all zero-initialized sections as one contiguous span [BssAddress, BssAddress + BssSize), if the linker places .sdata2 (Data segment) between .sbss and .sbss2, the BSS span will enclose .sdata2. Therefore, a loader MUST clear [BssAddress, BssAddress + BssSize) before copying initialized Text/Data segments into RAM (or explicitly skip loaded segment ranges if clearing afterward).
  • Segment Overlap Detection: Reject or warn on two active segments whose file ranges or target RAM ranges overlap each other.
  • RAM Address & Entry Point Validation: On GameCube, valid cached main RAM addresses fall in 0x80000000–0x817FFFFF (above OS globals at 0x80003100 for normal executables; uncached mirror 0xC0000000–0xC17FFFFF is also valid). Verify EntryPoint falls within one of the active Text segments (and is 4-byte aligned, as PowerPC instructions are 32-bit fixed-width).
  • No Relocation Support: .dol segments are fixed-address; they cannot be relocated to another RAM address without external symbol/relocation metadata.

5. Step-by-Step Parser Pseudocode

struct DolSegment:
    kind: string        // "text" or "data"
    slot: int
    file_offset: u32
    load_addr: u32
    size: u32
    data: bytes

function is_valid_gc_ram(addr, size):
    if size == 0: return true
    end_addr = u64(addr) + u64(size)
    // Cached 24 MiB RAM (0x80000000..0x81800000) or Uncached (0xC0000000..0xC1800000)
    return (addr >= 0x80000000 and end_addr <= 0x81800000)
        or (addr >= 0xC0000000 and end_addr <= 0xC1800000)

function parse_dol(stream, file_size):
    assert file_size >= 0x0100, "File smaller than DOL header"
    hdr = read_bytes(stream, 0x0000, 0x0100)

    segments = []
    for kind, count, off_base, addr_base, size_base in [
        ("text", 7,  0x0000, 0x0048, 0x0090),
        ("data", 11, 0x001C, 0x0064, 0x00AC)
    ]:
        for i in 0 .. count - 1:
            off  = read_u32be(hdr, off_base  + i * 4)
            addr = read_u32be(hdr, addr_base + i * 4)
            size = read_u32be(hdr, size_base + i * 4)

            if off == 0 and size == 0:
                continue
            assert off != 0 and size != 0, "Inconsistent empty segment slot"
            assert off >= 0x0100 and u64(off) + u64(size) <= u64(file_size)
            assert is_valid_gc_ram(addr, size), "Segment load address outside GC RAM"

            payload = read_bytes(stream, off, size)
            segments.append(DolSegment(kind, i, off, addr, size, payload))

    // Check pairwise non-overlap in target virtual RAM
    for a in 0 .. len(segments) - 1:
        for b in a + 1 .. len(segments) - 1:
            s1, s2 = segments[a], segments[b]
            assert (u64(s1.load_addr) + s1.size <= s2.load_addr)
                or (u64(s2.load_addr) + s2.size <= s1.load_addr), "Overlapping RAM segments"

    bss_addr    = read_u32be(hdr, 0x00D8)
    bss_size    = read_u32be(hdr, 0x00DC)
    entry_point = read_u32be(hdr, 0x00E0)

    if bss_size > 0:
        assert is_valid_gc_ram(bss_addr, bss_size)
    assert (entry_point & 3) == 0, "Unaligned PowerPC entry point"
    assert any(s.kind == "text" and entry_point >= s.load_addr and entry_point < s.load_addr + s.size for s in segments)

    return { segments, bss_addr, bss_size, entry_point }

function map_dol_to_memory(parsed_dol, ram):
    // Step 1: Zero BSS first so enclosed initialized data segments (e.g., .sdata2) are not clobbered
    if parsed_dol.bss_size > 0:
        ram.zero(parsed_dol.bss_addr, parsed_dol.bss_size)
    // Step 2: Copy all active text and data segments
    for seg in parsed_dol.segments:
        ram.write(seg.load_addr, seg.data)
    return parsed_dol.entry_point

6. Provenance & Confidence

Identification caveat: Because .dol has no magic bytes, arbitrary big-endian files can occasionally mimic a header if only file size is checked. Always validate segment bounds, non-overlap, RAM range, and 4-byte-aligned EntryPoint containment inside a Text segment.

  • Confirmed Hardware/SDK Spec: The 256-byte header layout (7 Text + 11 Data slots, BssAddress, BssSize, EntryPoint) is completely fixed across all GameCube IPL/BS2 revisions and Dolphin SDK toolchains.
  • Linker-Dependent Behavior: Which logical ELF sections map to which Text/Data indices, and whether BssSize spans .sdata2, depends on the specific linker script (.lcf) used when building the binary.
