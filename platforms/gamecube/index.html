Nintendo GameCube (DOL)

Platform Architecture & Inherited Formats · Big-Endian PowerPC

The Nintendo GameCube (codename Dolphin, model prefix DOL) is a big-endian 32-bit PowerPC console built around an IBM Gekko CPU, an ArtX/Nintendo Flipper system ASIC, 24 MiB of main 1T-SRAM, 16 MiB of auxiliary ARAM, and an 8 cm proprietary CAV optical disc (~1.46 GB).

CPU
IBM PowerPC 750CXe ("Gekko"), 486 MHz, 32-bit big-endian, paired-singles SIMD, 32 KiB L1 I/D + 256 KiB L2 cache.
Memory
24 MiB main 1T-SRAM (0x80000000 cached / 0xC0000000 uncached), 16 MiB ARAM (DMA-only), 3 MiB on-die Flipper 1T-SRAM.
Optical Media
8 cm Nintendo Optical Disc (MiniDVD physical medium), 1,459,978,240 bytes (0x57058000, 712,880 × 2048-byte sectors).
Runtime OS
Dolphin OS (statically linked SDK runtime with dynamic OSLink module loader and DVD FST streaming).

Hardware & Memory Map

GameCube software runs in supervisor mode without virtual memory paging. Fixed PowerPC Block Address Translation (BAT) registers map physical 24 MiB main memory into both cached and uncached virtual windows, alongside memory-mapped Flipper hardware registers and locked L2 cache DMA scratchpad space.

Standard Dolphin OS Virtual Address Regions
Base Address End / Size Cache Mode Region Role
0x80000000 0x800030FF (12.25 KiB) Cached OS Low-Memory Globals Exception vectors, boot.bin/bi2.bin mirror, arena bounds, FST pointer, and debug state.
0x80003100 0x817FFFFF (~24 MiB) Cached Main 1T-SRAM (Executable & Arena) Static .dol code/data segments, heap arena (ArenaLo–ArenaHi), stack, and fst.bin at high RAM.
0xC0000000 0xC17FFFFF (24 MiB) Uncached Uncached Main RAM Alias Uncached mirror of physical 1T-SRAM used for hardware-coherent buffers and direct I/O.
0xCC000000 0xCC00FFFF Guarded / Uncached Flipper Hardware I/O CP, PE, VI, PI, MI, DSP, DI, SI, EXI, and AI memory-mapped register banks.
0xE0000000 0xE0003FFF (16 KiB) Locked Cache Locked L1/DMA Cache Gekko locked data cache window used for high-speed DMA burst transfers.

IPL & Apploader Boot Chain

Unlike PC or standard optical discs that boot via ISO-9660/UDF, the GameCube optical drive uses a proprietary sector framing layer and executes a multi-stage hardware-assisted boot chain directly from fixed disc offsets:

  1. IPL (Boot ROM) Initialization: The 2 MiB internal Macronix IPL ROM initializes Gekko, Flipper, and 1T-SRAM, optionally runs the system menu if the lid is open or no valid disc is present, and reads the first 0x2460 bytes of the disc.
  2. Disc Identification (boot.bin & bi2.bin): IPL validates the big-endian magic word 0xC2339F3D at disc offset 0x001C, populates OS low-memory boot structures from boot.bin (0x0000–0x043F) and bi2.bin (0x0440–0x243F), and reads the 32-byte Apploader header at 0x2440.
  3. Apploader Execution (0x2460+): IPL loads the Apploader binary (size + trailer from 0x2454/0x2458) into RAM (typically 0x81200000) and invokes its entry point. The Apploader registers callbacks with BS2 to stream the main .dol executable (from boot.bin[0x0420]) and fst.bin (from boot.bin[0x0424]) into main RAM, adjusting ArenaHi below fst.bin.
  4. Static Executable Entry (.dol): Once all .dol segments are copied and BSS is cleared, the Apploader returns the .dol entry point (header offset 0x00E0). BS2 jumps to __start, which initializes PowerPC SDA/SDA2 base registers (r13, r2), Dolphin OS subsystems, and main().
  5. Dynamic Linking (.rel) & Disc Banner (opening.bnr): At runtime, titles may load relocatable .rel modules from the FST via OSLink/OSLinkFixed, while the IPL menu reads opening.bnr from the FST root to display the disc icon and localized metadata.

Scope & Provenance Notes

Scope boundary: This section covers only formats inherited from GameCube hardware, IPL/BS2, and Dolphin OS. Game-specific archives, scripting, audio containers, and third-party emulator wrapper formats (such as .gcz, .ciso, or .rvz) are outside this specification.

All multi-byte integers across GameCube disc structures, executables, relocatable modules, and banner pixels are big-endian unless a specific inner payload explicitly specifies otherwise. Retail GameCube discs do not use hardware AES encryption (unlike Nintendo Wii optical discs); the physical disc drive authenticates media via the Burst Cutting Area (BCA) and lead-in control data outside the user-readable 1,459,978,240-byte image.
