PARAM.SFO PSF Binary Table & PSP Metadata Keys

PSP System Parameter Table · Little-Endian

PARAM.SFO uses Sony's binary Parameter System File (\x00PSF) key-value table format to describe UMD discs, Memory Stick EBOOT.PBP packages, firmware updaters, and savedata directories for the PSP XMB and kernel loader.

1. Identification & Scope

PARAM.SFO files begin with the 4-byte signature 00 50 53 46 (\x00PSF) and version 0x00000101 (1.1). Every numeric field in the header, index table, and 0x0404 integer values is little-endian.

Although the PSF binary container is shared with later Sony consoles (PS3/PS4), this specification covers the PSP v1.1 layout and the PSP-specific keys read by the PSP XMB, UMD loader, and savedata utility.

2. Binary Layout

A PSF file consists of four contiguous regions: a 20-byte header, an array of 16-byte index records, a packed NUL-terminated ASCII key table, and a 4-byte-aligned value data table.

PSF Header (20 / 0x14 bytes)
Offset Size Type Field Description
0x00 4 u8[4] magic Constant signature 00 50 53 46 (\x00PSF)
0x04 4 u32le version PSF format version: 0x00000101 (bytes 01 01 00 00 = v1.1)
0x08 4 u32le key_table_offset Absolute byte offset to the Key Table (typically 0x14 + tables_entries * 0x10)
0x0C 4 u32le data_table_offset Absolute byte offset to the Data Table (4-byte aligned)
0x10 4 u32le tables_entries Number of parameter entries N in the Index Table
PSF Index Table Entry (16 / 0x10 bytes per entry, starting at 0x14)
Offset Size Type Field Description
0x00 2 u16le key_offset Offset relative to key_table_offset to NUL-terminated ASCII key name
0x02 2 u16le data_fmt Value encoding type (0x0004, 0x0204, or 0x0404)
0x04 4 u32le data_len Used byte length of the value (for 0x0204 strings, includes trailing 0x00)
0x08 4 u32le data_max_len Allocated slot size in Data Table (4-byte aligned; data_len <= data_max_len)
0x0C 4 u32le data_offset Offset relative to data_table_offset to this entry's value slot

3. Data Formats & Canonical PSP Keys

PSF data_fmt Encodings
Value Size Type Name Decoding Rule
0x0004 Variable u8[data_len] utf8-S (Binary / Special UTF-8) Exact data_len raw bytes; not guaranteed to be NUL-terminated (used for SAVEDATA_PARAMS, SAVEDATA_FILE_LIST)
0x0204 Variable char[data_len] utf8 (String) NUL-terminated UTF-8 text; data_len includes the trailing 0x00 byte and remaining bytes up to data_max_len are zero-padded
0x0404 4 u32le int32 / uint32 32-bit little-endian integer; data_len == 4 and data_max_len == 4

SAVEDATA_TITLE 128 0x0204 Save (MS) Secondary save slot subtitle displayed beneath TITLE

4. Edge Cases & Loader Rules

  • Lexicographical key ordering: Official PSP firmware tools always emit Index Table entries sorted in strictly ascending ASCII byte order of key names. Unsorted entries can fail binary lookup or validation in official XMB parsers.
  • 4-byte alignment padding: The Key Table ends with zero padding bytes so that data_table_offset is aligned to a 4-byte boundary. Likewise, each value slot's data_max_len is typically rounded up to a multiple of 4.
  • 0x0204 length vs. capacity: Always slice UTF-8 strings using data_len and strip the trailing NUL byte (or stop at the first 0x00 within data_len). Do not assume data_max_len - data_len bytes are valid text, and do not fail if third-party tools omit the NUL byte inside data_len while leaving zero padding inside data_max_len.
  • 0x0004 binary payloads: Keys with data_fmt == 0x0004 (SAVEDATA_PARAMS, SAVEDATA_FILE_LIST) contain arbitrary binary data including embedded 0x00 bytes; parsers must return raw bytes of exact length data_len.
  • Bounds checks: Enforce key_table_offset >= 0x14 + tables_entries * 16, key_table_offset <= data_table_offset <= file_size, data_len <= data_max_len, and data_table_offset + data_offset + data_max_len <= file_size.

5. Step-by-Step Parser Pseudocode

function parse_param_sfo(buf):
    if len(buf) < 0x14:
        error("File smaller than 20-byte PSF header")
    if buf[0x00:0x04] != b"\x00PSF":
        error("Invalid PSF magic")

    version           = read_u32le(buf, 0x04)
    key_table_offset  = read_u32le(buf, 0x08)
    data_table_offset = read_u32le(buf, 0x0C)
    entry_count       = read_u32le(buf, 0x10)

    index_end = 0x14 + entry_count * 16
    if index_end > key_table_offset or key_table_offset > data_table_offset or data_table_offset > len(buf):
        error("Invalid PSF table offsets")

    entries = {}
    for i in range(entry_count):
        base         = 0x14 + i * 16
        key_offset   = read_u16le(buf, base + 0x00)
        data_fmt     = read_u16le(buf, base + 0x02)
        data_len     = read_u32le(buf, base + 0x04)
        data_max_len = read_u32le(buf, base + 0x08)
        data_offset  = read_u32le(buf, base + 0x0C)

        k_start = key_table_offset + key_offset
        if k_start >= data_table_offset:
            error("Key offset out of bounds")
        k_end = find_byte(buf, 0x00, start=k_start, end=data_table_offset)
        if k_end is None:
            error("Unterminated key string")
        key_name = decode_ascii(buf[k_start:k_end])

        d_start = data_table_offset + data_offset
        if data_len > data_max_len or d_start + data_max_len > len(buf):
            error("Data slice out of bounds for key " + key_name)

        raw = buf[d_start : d_start + data_len]
        if data_fmt == 0x0404:
            if data_len != 4:
                error("Invalid integer length for key " + key_name)
            value = read_u32le(raw, 0)
        elif data_fmt == 0x0204:
            value = decode_utf8(raw.rstrip(b"\x00"))
        elif data_fmt == 0x0004:
            value = raw
        else:
            value = raw  # preserve unknown format bytes

        entries[key_name] = {
            "format": data_fmt,
            "max_len": data_max_len,
            "value": value
        }

    return {"version": version, "entries": entries}

6. Provenance & Confidence

The PSF v1.1 header, 16-byte index record, 0x0004/0x0204/0x0404 format codes, and core PSP keys (BOOTABLE, CATEGORY, DISC_ID, PSP_SYSTEM_VER, PARENTAL_LEVEL, TITLE, MEMSIZE) are confirmed across retail UMD, Memory Stick, and savedata files.

Firmware-dependent keys & savedata crypto: Localized title keys (TITLE_0 through TITLE_11) expanded across PSP system software updates as additional XMB languages (such as Russian and Chinese) were added. Additionally, the exact cryptographic contents inside SAVEDATA_PARAMS and SAVEDATA_FILE_LIST depend on Kirk/savedata firmware key versions and are documented here only at container-field level.
