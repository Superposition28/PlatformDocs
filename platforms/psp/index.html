PlayStation Portable (PSP)

Platform Overview · Allegrex MIPS32r2 · Little-Endian

Sony's PlayStation Portable (PSP-1000 through PSP-3000, PSP Go N1000, and PSP Street E1000) is a 32-bit little-endian MIPS handheld platform. System software boots signed/encrypted containers from Universal Media Disc (UMD) optical media (disc0:/), Memory Stick PRO Duo (ms0:/), or internal flash storage (ef0:/ on PSP Go) through hardware cryptographic verification on the Kirk security engine.

Primary CPU
Sony/Toshiba Allegrex MIPS32r2 (32-bit little-endian, 1–333 MHz, FPU + VFPU vector coprocessor, 16 KiB I-cache / 16 KiB D-cache)
Media & Coprocessors
Media Engine (secondary MIPS32r2 + VME) for media decoding; Kirk hardware crypto engine (AES-128, SHA-1, ECDSA, PRNG)
Main Memory
32 MiB RAM on PSP-1000 (0x08000000–0x09FFFFFF); 64 MiB RAM on PSP-2000+ (0x08000000–0x0BFFFFFF), plus 16 KiB scratchpad (0x00010000)
Boot Media
UMD ISO-9660 (disc0:/) via PSP_GAME/SYSDIR/EBOOT.BIN, and Memory Stick / Flash (ms0:/, ef0:/) via EBOOT.PBP
OS & Module ABI
PSP Kernel / VSH (XMB) loading relocatable ELF32-MIPS PRX modules (0xFFA0) linked dynamically by 32-bit NID tables

Hardware & Memory Map

Every platform-inherited binary format on the PSP uses little-endian byte ordering (ELFDATA2LSB) to match the Allegrex MIPS32r2 core. Kernel and user code operate across standard MIPS segments mapped into physical DRAM and internal scratchpad:

Allegrex MIPS Logical Address Regions
Address Range Size Region Access / Role Notes
0x00010000–0x00013FFF 16 KiB Scratchpad RAM Fast local SRAM On-chip data scratchpad for low-latency buffers
0x04000000–0x041FFFFF 2 MiB VRAM (eDRAM) GE display / framebuffers Mirrorable as uncached/swizzled video memory
0x08000000–0x087FFFFF 8 MiB Kernel / System Partitions Kernel-mode protected Kernel modules, VSH/system allocations (user space starts at 0x08800000)
0x08800000–0x09FFFFFF 24 MiB User Main RAM (Base) User applications & games Default user partition on PSP-1000 (32 MiB total system RAM)
0x0A000000–0x0BFFFFFF 32 MiB Extended User RAM PSP-2000+ / MEMSIZE=1 Enabled when PARAM.SFO sets MEMSIZE=1 (64 MiB total RAM)
0x88000000–0x8BFFFFFF 32 / 64 MiB kseg0 Kernel Alias Cached kernel address space Used by kernel PRX modules loaded into kernel partitions

UMD & Memory Stick Boot Chain

The PSP XMB shell and kernel executive recognize two primary launch paths depending on the storage device:

  1. UMD Optical Disc (disc0:/): The ISO-9660 volume presents /UMD_DATA.BIN and /PSP_GAME/PARAM.SFO to the XMB for title identification, firmware version checks (PSP_SYSTEM_VER), and graphical preview assets (ICON0.PNG, PIC1.PNG, SND0.AT3). When launched, the kernel mounts disc0:/ and passes /PSP_GAME/SYSDIR/EBOOT.BIN (a ~PSP-encrypted PRX executable) to sceKernelLoadModule.
  2. Memory Stick / Internal Flash (ms0:/, ef0:/): Digital titles, demos, firmware updaters, and homebrew reside in PSP/GAME/<folder>/EBOOT.PBP. The \x00PBP container packs PARAM.SFO, XMB media assets, the executable payload DATA.PSP, and an optional DATA.PSAR archive into a single flat file.
  3. Kernel Module Loading & Dynamic Linking: Once decrypted by the Kirk engine (or accepted directly on devkit/custom environments), the ELF32-MIPS PRX image (e_type = 0xFFA0) is relocated according to its SHT_PRXRELOC table, inspected via .rodata.sceModuleInfo, and dynamically linked against kernel and system libraries by matching 32-bit NIDs in .lib.stub against exported NIDs in .lib.ent.

Scope Boundary

Platform-inherited formats only: This section documents Sony PSP hardware, firmware, and standard preservation image formats. Individual game archives (for example, contents inside PSP_GAME/USRDIR/), proprietary middleware formats, and title-specific data structures are excluded.
