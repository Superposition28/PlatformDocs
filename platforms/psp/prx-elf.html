~PSP Encrypted PRX Wrapper & Relocatable ELF32-MIPS Modules

PSP Executable & Shared Module Formats · Little-Endian

PSP retail executables (EBOOT.BIN, DATA.PSP, system *.PRX) are wrapped in a 336-byte (0x150) ~PSP encrypted/signed header processed by the Kirk hardware crypto engine. Once decrypted (or in plain devkit/homebrew binaries such as BOOT.BIN), the inner image is a little-endian ELF32-MIPS module—either a static executable (ET_EXEC = 0x0002) or a relocatable PRX module (ET_PSP_PRX = 0xFFA0) carrying .rodata.sceModuleInfo, NID import/export tables, and MIPS relocations.

1. Identification & Scope

The PSP kernel loader dispatches executables based on the leading 4-byte signature:

  • 7E 50 53 50 (~PSP): Retail signed and encrypted PRX wrapper (336-byte header). Decryption and CMAC/SHA-1 verification are performed via the Kirk security processor using keys selected by the header's tag and decrypt_mode fields. The decrypted payload may also be compressed (gzip or 2RLZ) before yielding an ELF32 image.
  • 7F 45 4C 46 (\x7FELF): Standard 32-bit little-endian MIPS ELF (EI_CLASS = 1, EI_DATA = 1, e_machine = 8). Static ELFs use e_type = 0x0002 (ET_EXEC), whereas relocatable PRX executables and libraries use Sony's processor-specific type e_type = 0xFFA0 (ET_PSP_PRX).

PRX Relocation Encodings (Elf32_Rel: 8 bytes, SHT_PRXRELOC = 0x700000A0)
Encoding / Type ID / Bits Type Formula Description
Type A r_info bits 0..7 u8 r_type = r_info & 0xFF MIPS relocation type
Type A ofs_base bits 8..15 u8 ofs_base = (r_info >> 8) & 0xFF Program header index of the segment containing r_offset
Type A addr_base bits 16..23 u8 addr_base = (r_info >> 16) & 0xFF Program header index of the target base address added to the relocated word
R_MIPS_NONE 0 Reloc No operation Alignment or padding relocation record
R_MIPS_16 1 Reloc *(u16*)(P) += S 16-bit halfword relocation
R_MIPS_32 2 Reloc *(u32*)(P) += S 32-bit direct pointer relocation
R_MIPS_26 4 Reloc target = ((insn & 0x03FFFFFF) << 2) + S; insn = (insn & 0xFC000000) | ((target >> 2) & 0x03FFFFFF) MIPS j / jal 26-bit instruction target relocation
R_MIPS_HI16 / R_MIPS_LO16 5 / 6 Reloc A = (hi16 << 16) + sign_ext16(lo16) + S; new_hi = (A + 0x8000) >> 16; new_lo = A & 0xFFFF Paired upper/lower 16-bit immediate relocation (compensates for signed LO16 carry)
R_MIPS_GPREL16 7 Reloc *(i16*)(P) += S - gp_value 16-bit signed offset relative to $gp
Type B (0x700000A1) Packed stream Bit-packed Variable-length command stream Compressed relocation stream used in newer PRXs; packs ofs_base, addr_base, relocation type, and offset deltas into compact byte codes

NID Calculation: Each 32-bit Name IDentifier (NID) in early/standard user libraries is the first 4 bytes (interpreted as u32le) of the SHA-1 digest of the ASCII function or variable name. System kernel modules on firmware 3.70+ randomize system NIDs per firmware build.

4. Edge Cases & Loader Rules

  • ~PSP Kirk encryption gate vs. plain ELF: Retail PSP firmware refuses to execute unencrypted ELFs in sceKernelLoadModule. Parsers must check offset 0x00 for ~PSP first; encrypted payloads cannot be parsed as ELF without valid Kirk decryption keys for the header's tag and decrypt_mode.
  • .rodata.sceModuleInfo discovery without section headers: Stripped PRX binaries may have e_shoff == 0. In relocatable PRXs (e_type == 0xFFA0), the kernel locates sceModuleInfo via phdr[0].p_paddr & 0x7FFFFFFF (file offset; bit 31 0x80000000 signals kernel mode).
  • Multiple R_MIPS_HI16 per R_MIPS_LO16: Compiler code generation may emit several R_MIPS_HI16 records sharing one subsequent R_MIPS_LO16. Loaders must queue pending HI16 locations until the matching LO16 provides the signed 16-bit addend, then patch all queued HI16 instructions and the LO16 instruction together.
  • Generalized loader mapping: Allocate contiguous/aligned segment memory for PT_LOAD headers (p_memsz, zero-filling p_memsz - p_filesz), apply SHT_PRXRELOC (0x700000A0) or PT_PRXRELOC relocations using each segment's runtime base address, patch .lib.stub 8-byte MIPS stubs against loaded .lib.ent exports (j target; nop for user calls, or jr $ra; syscall idx for kernel calls), flush D-cache and invalidate I-cache, and invoke module_start (NID 0xD632ACDB).

5. Step-by-Step Parser Pseudocode

function inspect_psp_executable(buf):
    if len(buf) < 0x34:
        error("File too small")

    magic = buf[0x00:0x04]
    if magic == b"~PSP":
        if len(buf) < 0x150:
            error("Truncated ~PSP header")
        psp_hdr = {
            "mod_attribute":  read_u16le(buf, 0x04),
            "comp_attribute": read_u16le(buf, 0x06),
            "modname":        read_ascii_z(buf, 0x0A, 28),
            "nsegments":      buf[0x27],
            "elf_size":       read_u32le(buf, 0x28),
            "psp_size":       read_u32le(buf, 0x2C),
            "boot_entry":     read_u32le(buf, 0x30),
            "modinfo_offset": read_u32le(buf, 0x34),
            "devkit_version": read_u32le(buf, 0x78),
            "decrypt_mode":   buf[0x7C],
            "tag":            read_u32le(buf, 0xC0)
        }
        return {"kind": "~PSP", "encrypted": true, "header": psp_hdr}

    if magic != b"\x7FELF":
        error("Unknown executable magic")

    if buf[0x04] != 1 or buf[0x05] != 1:
        error("Expected ELF32 little-endian")

    e_type    = read_u16le(buf, 0x10)
    e_machine = read_u16le(buf, 0x12)
    if e_machine != 0x0008:
        error("Expected EM_MIPS (0x0008)")

    e_entry = read_u32le(buf, 0x18)
    e_phoff = read_u32le(buf, 0x1C)
    e_shoff = read_u32le(buf, 0x20)
    e_phnum = read_u16le(buf, 0x2C)
    e_shnum = read_u16le(buf, 0x30)

    phdrs = [read_elf32_phdr(buf, e_phoff + i * 0x20) for i in range(e_phnum)]
    shdrs = [read_elf32_shdr(buf, e_shoff + i * 0x28) for i in range(e_shnum)] if e_shoff else []

    modinfo = None
    if e_type == 0xFFA0 and len(phdrs) > 0:
        modinfo_off = phdrs[0].p_paddr & 0x7FFFFFFF
        if modinfo_off + 0x34 <= len(buf):
            modinfo = parse_sce_module_info(buf, modinfo_off)

    relocs = []
    for sh in shdrs:
        if sh.sh_type == 0x700000A0:  # Type A PRX relocations
            for off in range(sh.sh_offset, sh.sh_offset + sh.sh_size, 8):
                r_offset = read_u32le(buf, off)
                r_info   = read_u32le(buf, off + 4)
                relocs.append({
                    "offset":    r_offset,
                    "type":      r_info & 0xFF,
                    "ofs_base":  (r_info >> 8) & 0xFF,
                    "addr_base": (r_info >> 16) & 0xFF
                })

    return {
        "kind": "ELF32-PRX" if e_type == 0xFFA0 else "ELF32-EXEC",
        "e_entry": e_entry,
        "phdrs": phdrs,
        "modinfo": modinfo,
        "reloc_count": len(relocs)
    }

6. Provenance & Confidence

The ELF32-MIPS header, e_type = 0xFFA0, .rodata.sceModuleInfo, .lib.ent, .lib.stub, and Type A SHT_PRXRELOC (0x700000A0) layouts are confirmed across PSP SDK/PRX binaries and standard ELF loaders.

Firmware-revision-dependent ~PSP & Kirk details: While the 336-byte ~PSP header offsets and tag/decrypt_mode fields are well-established, specific Kirk hardware key tables, tag-to-key mappings, comp_attribute compression variants (such as 2RLZ vs. gzip), Type B (0x700000A1) packed relocation opcodes, and post-3.70 kernel NID randomization vary across PSP system software revisions. No proprietary Kirk keys are included here.
