EBOOT.PBP 8-Section Container Format

PSP Executable & XMB Package · Little-Endian

EBOOT.PBP is Sony's standard 8-slot container used on PSP Memory Stick (ms0:/PSP/GAME/), internal flash (ef0:/PSP/GAME/), and firmware updaters. A fixed 40-byte header records the \x00PBP magic, version, and eight ascending byte offsets pointing to metadata, XMB presentation assets, the main executable, and an optional trailing resource archive.

1. Identification & Scope

Any valid PBP file starts at offset 0x00 with the 4-byte signature 00 50 42 50 (\x00PBP) followed by a 32-bit little-endian version word (0x00010000 in standard PSP 1.00+ packages, or 0x00010001 in select later digital/PS1 Classics packages). All integer fields in the PBP header are stored in little-endian byte order for the Allegrex MIPS32r2 processor.

Unlike directory-based archive containers, the PBP header stores no filenames and no explicit section lengths. Instead, it defines eight fixed positional slots at offsets 0x08 through 0x24 whose canonical identities are fixed by specification.

2. Binary Layout

PBP Header Layout (40 / 0x28 bytes)
Offset Size Type Field Description
0x00 4 u8[4] magic Constant signature 00 50 42 50 (\x00PBP)
0x04 4 u32le version Format version, typically 0x00010000 (major 1, minor 0) or 0x00010001
0x08 4 u32le offset_param_sfo Slot 0 offset: PARAM.SFO metadata table (typically 0x00000028)
0x0C 4 u32le offset_icon0_png Slot 1 offset: ICON0.PNG XMB static icon
0x10 4 u32le offset_icon1_pmf Slot 2 offset: ICON1.PMF XMB animated icon video
0x14 4 u32le offset_pic0_png Slot 3 offset: PIC0.PNG XMB secondary info overlay image
0x18 4 u32le offset_pic1_png Slot 4 offset: PIC1.PNG XMB full-screen background image
0x1C 4 u32le offset_snd0_at3 Slot 5 offset: SND0.AT3 XMB background audio
0x20 4 u32le offset_data_psp Slot 6 offset: DATA.PSP executable (~PSP PRX or ELF32-MIPS)
0x24 4 u32le offset_data_psar Slot 7 offset: DATA.PSAR auxiliary data archive (or file_size when absent)
Canonical PBP Section Slots (Slots 0–7)
Slot Header Offset Type Canonical Name Payload Format & XMB Constraints
0 0x08 PSF Table PARAM.SFO Required on bootable packages. Little-endian \x00PSF metadata table.
1 0x0C PNG ICON0.PNG Optional XMB icon; standard dimensions 144x80 (24/32-bit PNG, max ~512 KiB).
2 0x10 PMF Video ICON1.PMF Optional animated XMB icon (PSMF MPEG-4 AVC stream, typically 144x80, looping).
3 0x14 PNG PIC0.PNG Optional XMB info overlay graphic (typically 310x180 PNG).
4 0x18 PNG PIC1.PNG Optional XMB full-screen background graphic (standard PSP screen size 480x272 PNG).
5 0x1C ATRAC3 RIFF SND0.AT3 Optional XMB background audio (RIFF/WAVE container with Sony ATRAC3/ATRAC3plus codec, capped ~500 KiB in XMB).
6 0x20 Executable DATA.PSP Main executable: Kirk-encrypted ~PSP wrapper or plain ELF32-MIPS/PRX binary.
7 0x24 PSAR Archive DATA.PSAR Optional large data payload (e.g., encrypted firmware updater archive PSAR or emulator disc image).

3. Flags, Slots & Decoding Formulas

The PBP header contains no bitflags; section presence and sizes are derived exclusively from the monotonic offset array offsets[0..7] and the total file size file_size:

PBP Section Size Derivation Formulas
Condition Size Type Formula Description
Slots 0..6 Derived u32 size[i] = offsets[i + 1] - offsets[i] Byte length of section i equals the difference to the next slot's start offset
Slot 7 (DATA.PSAR) Derived u64 size[7] = file_size - offsets[7] Byte length of DATA.PSAR runs from offsets[7] to end of file
Empty / Omitted Slot 0 bool size[i] == 0 A slot is absent when its offset equals the next slot's offset (or file_size for slot 7)

4. Edge Cases & Loader Rules

  • Zero-length empty sections: Most homebrew and utility PBPs omit ICON1.PMF, PIC0.PNG, SND0.AT3, and DATA.PSAR. When multiple consecutive sections are empty, several entries in offsets[0..7] share the exact same byte value (for example, offsets[2] == offsets[3] == offsets[4]). Parsers must emit or skip zero-byte slots cleanly without treating duplicate offsets as errors.
  • Monotonicity & bounds validation: Valid PBPs satisfy 0x28 <= offsets[0] <= offsets[1] <= ... <= offsets[7] <= file_size. Any violation indicates corruption, truncation, or a malformed header.
  • DATA.PSAR trailing bounds & alignment padding: Because slot 7 has no sentinel "end of PSAR" field in the 40-byte PBP header, file_size - offsets[7] includes any trailing padding or appended container signatures. Likewise, some official packers align DATA.PSP or DATA.PSAR to 16-byte or 4096-byte boundaries; padding bytes between a payload's inner end (such as PNG IEND or SFO end) and offsets[i + 1] fall inside the derived slice size[i].
  • 4 GiB offset ceiling: PBP offsets are unsigned 32-bit integers (u32le), capping section start offsets at 4 GiB - 1. Only DATA.PSAR (slot 7) can extend beyond 4 GiB if file_size is tracked as 64-bit, though standard PSP FAT32 Memory Stick files cannot exceed 4 GiB - 1.
  • DATA.PSP execution gate: Official PSP firmware routes DATA.PSP through sceKernelLoadModule / Kirk verification; retail firmware requires a valid ~PSP encrypted/signed header, whereas devkit or custom environments may also execute plain ELF32-MIPS binaries in slot 6.

5. Step-by-Step Parser Pseudocode

SLOT_NAMES = [
    "PARAM.SFO", "ICON0.PNG", "ICON1.PMF", "PIC0.PNG",
    "PIC1.PNG",  "SND0.AT3",  "DATA.PSP",  "DATA.PSAR"
]

function parse_pbp(stream, file_size):
    if file_size < 0x28:
        error("File smaller than 40-byte PBP header")

    seek(stream, 0x00)
    magic = read_bytes(stream, 4)
    if magic != b"\x00PBP":
        error("Invalid PBP magic")

    version = read_u32le(stream)
    offsets = [read_u32le(stream) for _ in range(8)]

    prev = 0x28
    for i in range(8):
        if offsets[i] < prev or offsets[i] > file_size:
            error("Non-monotonic or out-of-bounds PBP offset at slot " + str(i))
        prev = offsets[i]

    sections = []
    for i in range(8):
        start = offsets[i]
        end = offsets[i + 1] if i < 7 else file_size
        length = end - start
        sections.append({
            "slot": i,
            "name": SLOT_NAMES[i],
            "offset": start,
            "size": length,
            "present": length > 0
        })

    return {
        "version": version,
        "sections": sections
    }

6. Provenance & Confidence

The 40-byte PBP header layout, \x00PBP magic, slot ordering, and adjacent-offset size derivation are confirmed across all PSP retail firmware generations, official firmware updaters, and Sony/homebrew PBP tooling.

Revision & inner payload caveats: While the 8-slot PBP wrapper itself is invariant, the internal format of DATA.PSAR varies significantly by package role (encrypted PSAR firmware update archives vs. PS1 Classics disc containers) and is outside the outer PBP header specification. Likewise, XMB asset size and codec limits (such as ICON0.PNG, PIC1.PNG, and SND0.AT3 ATRAC3 bitrate/size caps) are enforced by VSH/XMB software and vary slightly across PSP firmware revisions.
