SYSTEM.CNF Boot Descriptor & PS2 Optical Disc Layout

PLAYSTATION 2 · BOOT CONFIGURATION & OPTICAL FILESYSTEM Platform-Inherited

SYSTEM.CNF is the mandatory ASCII boot configuration descriptor placed in the root directory of every bootable PlayStation 2 CD-ROM or DVD-ROM. It instructs the Boot ROM (OSDSYS / EELOAD) which Emotion Engine executable to launch, which video region mode to initialize, and whether HDD/network power hardware is requested, all resolved over an ISO-9660 (ECMA-119) filesystem—paired with a UDF 1.02 bridge on DVD media.

Canonical Filenames
SYSTEM.CNF (recorded in ISO-9660 root as SYSTEM.CNF;1)
Magic Bytes
SYSTEM.CNF: none (ASCII KEY = VALUE text starting with BOOT2). Disc Volume: 43 44 30 30 31 (CD001) at LBA 16 (0x8000); UDF bridge adds BEA01 / NSR02 / TEA01
Endianness
SYSTEM.CNF: ASCII text. ISO-9660: dual-endian (u16le+u16be / u32le+u32be) and single-byte fields. UDF: Little-Endian
Platform/OS Scope
PlayStation 2 Boot ROM (OSDSYS), CDVDMAN IOP optical filesystem driver
Role/MIME
Boot configuration descriptor (text/plain) & optical disc volume image (application/x-iso9660-image)

1. Identification & Scope

PlayStation 2 optical media exists in two physical families, both exposing an ISO-9660 directory hierarchy to the IOP cdrom0: filesystem driver:

  • PS2 CD-ROM: 2048-byte user sectors in Mode 2 Form 1 (or 2352-byte raw sectors in .bin dumps containing a 24-byte sync/header/subheader prefix and 280-byte EDC/ECC trailer). Formatted with ISO-9660 Level 1/2.
  • PS2 DVD-ROM (DVD-5 / DVD-9): 2048-byte sectors formatted as an ISO-9660 + UDF 1.02 Bridge. The ISO-9660 Primary Volume Descriptor sits at LBA 16 (0x8000), followed by the UDF Volume Recognition Sequence (BEA01, NSR02, TEA01) and a UDF Anchor Volume Descriptor Pointer (AVDP) at LBA 256 (0x80000). The PS2 Boot ROM and CDVDMAN mount the ISO-9660 tree directly.
  • PS1 vs. PS2 Distinction: Original PlayStation discs use BOOT = cdrom:\... inside SYSTEM.CNF, whereas PlayStation 2 discs use BOOT2 = cdrom0:\....

0x01 1 u8 len_ear Extended Attribute Record length in logical blocks (normally 0).
0x02 8 both32 extent_lba Starting Logical Block Address of file or directory data (u32le at 0x02, u32be at 0x06).

0x12 7 u8[7] recording_date Year-1900, Month, Day, Hour, Minute, Second, GMT offset (signed 15-min units).

0x1A 1 u8 file_unit_size Interleave file unit size (0 if non-interleaved).
0x1B 1 u8 interleave_gap Interleave gap size (0 if non-interleaved).
0x1C 4 both16 vol_seq_number Volume sequence number (typically 1).
0x20 1 u8 len_fi Byte length of file_identifier.

3. Keys, Flags & Naming Formulas

SYSTEM.CNF Key Semantics

SYSTEM.CNF Directives and Allowed Values
Key Required Syntax / Enum Values Notes
BOOT2 Yes cdrom0:\<PATH>;1 Device prefix cdrom0:, backslash directory separators, uppercase 8.3 path, mandatory ;1 ISO-9660 version suffix.
VER Yes <major>.<minor> (e.g. 1.00) Printed or inspected by OSDSYS / diagnostics; numeric dotted decimal string.
VMODE Yes NTSC | PAL Selects initial GS video timing (NTSC 60 Hz for North America/Japan; PAL 50 Hz for Europe/Oceania).
HDDUNITPOWER No NICHDD | NIC | HDD | NONE Controls whether Expansion Bay Network Adaptor / ATA HDD power rails stay enabled across boot.

Disc ID & Boot Executable Naming Convention

Retail PS2 boot executables follow an 8.3-compatible catalog identifier formatted as PPPP_NNN.NN (for example, SLUS_200.01 or SCES_500.01):

  • First character (S): Standard Sony PlayStation software prefix.
  • Second character (C / L / P): C = Sony first-party, L = third-party licensee, P = demo/promotional or special retail SKU.
  • Third & fourth characters (Region): US = North America, ES = Europe/PAL, PS / PM = Japan (NTSC-J), KA = Korea, AJ = Asia.
  • Numeric suffix (_NNN.NN): 5-digit catalog number split into 3 digits, a dot, and 2 digits to satisfy ISO-9660 8.3 filename rules (stored on disc with ;1 appended).

ISO-9660 Dual-Endian & File Flag Formulas

  • Dual-Endian Validation: For both32 fields, le_val = read_u32le(buf, off) and be_val = read_u32be(buf, off + 4); conforming discs satisfy le_val == be_val.
  • file_flags (offset 0x19): Bit 0x01 = Hidden/Existence, 0x02 = Directory, 0x04 = Associated File, 0x08 = Extended Attribute Record format, 0x10 = Permissions in EAR, 0x80 = Multi-extent (file continues in subsequent Directory Record).

4. Edge Cases & Loader Rules

  • ISO-9660 ;1 Version Suffix: ISO-9660 Directory Records store file identifiers with a trailing version number (;1). PS2 OSDSYS expects BOOT2 to include ;1 explicitly (e.g. cdrom0:\SLUS_200.01;1); a general parser should strip ;1 only when normalizing paths for host filesystems, while preserving exact matching for cdrom0: resolution.
  • Whitespace & Line Endings: Tools and SDKs emit either \r\n (CRLF) or \n (LF) and may place spaces around = (BOOT2 = ... or BOOT2=...). Parsers must trim whitespace around keys, values, and trailing line breaks, and ignore empty lines.
  • Raw 2352-byte CD Sectors vs. 2048-byte Cooked Images: DVD-ROM images always store 2048 bytes per sector. Raw CD-ROM Mode 2 Form 1 dumps store 2352 bytes per sector, where user data starts at byte +24 inside each raw frame (12B sync + 4B header + 8B subheader). Checking for CD001 at both 16 * 2048 + 1 (0x8001) and 16 * 2352 + 24 + 1 (0x9319) distinguishes cooked vs. raw Mode 2 Form 1 images cleanly.
  • Sector-Boundary Padding in ISO-9660 Directories: Directory Records never cross a 2048-byte sector boundary. When remaining space in a sector is smaller than the next record, the remaining bytes are zero-filled and len_dr == 0 signals the parser to advance to the start of the next 2048-byte sector until data_length bytes have been consumed.
  • DVD-9 Dual-Layer Discs: Dual-layer PS2 DVDs place the ISO-9660/UDF directory tree and SYSTEM.CNF;1 on Layer 0. Files located on Layer 1 may carry valid ISO-9660 LBAs beyond the Layer 0 boundary, or may be addressed through secondary layer metadata managed by CDVDMAN.

5. Step-by-Step Parser Pseudocode

function parse_ps2_system_cnf(disc_reader):
    # 1. Detect 2048-byte cooked vs 2352-byte Mode 2 Form 1 raw sector layout
    if disc_reader.read(0x8001, 5) == b"CD001":
        sector_stride = 2048
        data_offset   = 0
    elif disc_reader.read(16 * 2352 + 24 + 1, 5) == b"CD001":
        sector_stride = 2352
        data_offset   = 24
    else:
        error("ISO-9660 PVD signature CD001 not found at LBA 16")

    def read_sector(lba):
        return disc_reader.read(lba * sector_stride + data_offset, 2048)

    # 2. Scan Volume Descriptor Set starting at LBA 16 for PVD (type == 1)
    pvd = null
    for lba in 16 .. 64:
        sec = read_sector(lba)
        if sec[1..6] != b"CD001":
            break
        if sec[0] == 0x01:
            pvd = sec
            break
        if sec[0] == 0xFF:
            break
    if pvd is null:
        error("Primary Volume Descriptor missing")

    block_size = u16le(pvd[0x80..0x82])
    assert block_size == 2048
    root_dr = pvd[0x9C .. 0x9C + 34]
    root_lba = u32le(root_dr[0x02..0x06])
    root_len = u32le(root_dr[0x0A..0x0E])

    # 3. Traverse ISO-9660 directory extent
    function find_in_dir(dir_lba, dir_len, target_upper):
        bytes_read = 0
        cur_lba = dir_lba
        while bytes_read < dir_len:
            sec = read_sector(cur_lba)
            pos = 0
            while pos < 2048 and bytes_read + pos < dir_len:
                len_dr = sec[pos]
                if len_dr == 0:
                    break  # advance to next sector
                rec = sec[pos .. pos + len_dr]
                len_fi = rec[0x20]
                name = ascii(rec[0x21 .. 0x21 + len_fi]).upper()
                if name == target_upper or name.split(";")[0] == target_upper.split(";")[0]:
                    return {
                        "lba": u32le(rec[0x02..0x06]),
                        "size": u32le(rec[0x0A..0x0E]),
                        "flags": rec[0x19]
                    }
                pos += len_dr
            bytes_read += 2048
            cur_lba += 1
        return null

    # 4. Locate and parse SYSTEM.CNF;1
    cnf_entry = find_in_dir(root_lba, root_len, "SYSTEM.CNF;1")
    if cnf_entry is null:
        error("SYSTEM.CNF;1 not found in ISO-9660 root")

    cnf_bytes = read_file_extent(cnf_entry.lba, cnf_entry.size)
    config = {}
    for raw_line in ascii(cnf_bytes).splitlines():
        line = raw_line.strip()
        if line == "" or "=" not in line:
            continue
        key, val = line.split("=", 1)
        config[key.strip().upper()] = val.strip()

    if "BOOT2" not in config:
        error("Missing BOOT2 directive (not a PS2 SYSTEM.CNF)")

    # 5. Resolve cdrom0:\<PATH>;1 to target EE ELF extent
    boot_path = config["BOOT2"]
    assert boot_path.lower().startswith("cdrom0:\\")
    rel_parts = boot_path[8:].split("\\")
    cur_lba, cur_len = root_lba, root_len
    for i, part in enumerate(rel_parts):
        entry = find_in_dir(cur_lba, cur_len, part.upper())
        if entry is null:
            error("Boot executable not found: " + part)
        if i < len(rel_parts) - 1:
            assert (entry.flags & 0x02) != 0
            cur_lba, cur_len = entry.lba, entry.size
        else:
            config["boot_elf_extent"] = entry
    return config

6. Provenance & Confidence

Confirmed Spec SDK-Revision-Dependent

  • Confirmed Spec: ISO-9660 (ECMA-119) PVD and Directory Record layouts, UDF 1.02 VRS/AVDP descriptors (OSTA UDF 1.02 / ECMA-167), Mode 2 Form 1 2352-byte framing, and PS2 SYSTEM.CNF core keys (BOOT2, VER, VMODE) are standardized and verified across retail PS2 media and Boot ROM behavior.
  • SDK-Revision-Dependent: HDDUNITPOWER appears in later Sony PS2 SDK revisions supporting the Expansion Bay HDD/Network Adaptor; older titles omit it entirely.

Caveat on Dual-Layer & UDF Parsing: While retail PS2 DVD-ROMs carry a UDF 1.02 bridge alongside ISO-9660, the PS2 Boot ROM itself mounts ISO-9660. Do not assume files visible only in UDF structures are reachable through standard cdrom0: Boot ROM paths.
