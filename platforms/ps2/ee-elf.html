Emotion Engine ELF32-MIPS R5900 Executable

PLAYSTATION 2 · EMOTION ENGINE EXECUTABLE Platform-Inherited

The primary executable format for the PlayStation 2 Emotion Engine (EE) is a little-endian 32-bit Executable and Linkable Format (ELFCLASS32) binary targeting the MIPS R5900 processor (e_machine = 8). Although the R5900 provides 64-bit general-purpose registers and 128-bit multimedia extensions, EE executables use 32-bit virtual addresses (ILP32 pointer model with EABI64 register conventions) and are mapped statically by the EE kernel loader (EELOAD / LoadExecPS2).

1. Identification & Scope

An EE executable is identified by the standard 16-byte ELF identification array (7F 45 4C 46 01 01 01 ...) combined with e_type = 2 (ET_EXEC), e_machine = 8 (EM_MIPS), and R5900 machine bits in e_flags (specifically EF_MIPS_MACH_5900 = 0x00920000). Unlike PS2 IOP .irx modules, retail EE executables are linked at fixed virtual addresses (commonly starting at 0x00100000 above the 1 MiB EE kernel region) and contain no runtime relocations.

2. Binary Layout Tables

Elf32_Ehdr — ELF32 File Header (52 / 0x34 bytes at Offset 0x00)
Offset Size Type Field Description
0x00 4 u8[4] e_ident[EI_MAG0..3] Magic bytes 7F 45 4C 46 (\x7FELF).
0x04 1 u8 e_ident[EI_CLASS] 1 = ELFCLASS32 (32-bit ELF container).
0x05 1 u8 e_ident[EI_DATA] 1 = ELFDATA2LSB (Little-Endian).
0x06 1 u8 e_ident[EI_VERSION] 1 = EV_CURRENT.
0x07 1 u8 e_ident[EI_OSABI] 0 = ELFOSABI_NONE (System V / bare-metal ABI).
0x08 1 u8 e_ident[EI_ABIVERSION] 0.
0x09 7 u8[7] e_ident[EI_PAD] Zero padding.
0x10 2 u16le e_type 2 = ET_EXEC (static executable).
0x12 2 u16le e_machine 8 = EM_MIPS.
0x14 4 u32le e_version 1 = EV_CURRENT.
0x18 4 u32le e_entry EE virtual entry point address (commonly 0x00100000 or 0x00100008).
0x1C 4 u32le e_phoff File offset of Program Header Table (typically 0x00000034).
0x20 4 u32le e_shoff File offset of Section Header Table (0 when stripped).
0x24 4 u32le e_flags MIPS architecture, R5900 machine, and EABI flags (commonly 0x20924001).
0x28 2 u16le e_ehsize ELF header size in bytes (0x34 = 52).
0x2A 2 u16le e_phentsize Size of one Program Header entry (0x20 = 32 bytes).
0x2C 2 u16le e_phnum Number of Program Header entries.
0x2E 2 u16le e_shentsize Size of one Section Header entry (0x28 = 40 bytes, or 0 if stripped).
0x30 2 u16le e_shnum Number of Section Header entries (0 if stripped).
0x32 2 u16le e_shstrndx Index of .shstrtab section name string table (0 if stripped).
Elf32_Phdr — Program Header Entry (32 / 0x20 bytes at e_phoff + i * e_phentsize)
Offset Size Type Field Description
0x00 4 u32le p_type Segment type (1 = PT_LOAD, 0x70000000 = PT_MIPS_REGINFO).
0x04 4 u32le p_offset Byte offset of segment payload in the ELF file.
0x08 4 u32le p_vaddr Target virtual address in EE RAM.
0x0C 4 u32le p_paddr Physical address (typically identical to p_vaddr on EE).
0x10 4 u32le p_filesz Number of bytes to copy from file into memory.
0x14 4 u32le p_memsz Total memory footprint of segment; p_memsz - p_filesz is zero-filled (.bss).
0x18 4 u32le p_flags Permission bitmask: PF_X (1), PF_W (2), PF_R (4).
0x1C 4 u32le p_align Required alignment in file and memory (e.g. 0x10, 0x80, or 0x1000).
Elf32_Shdr — Section Header Entry (40 / 0x28 bytes, Present in Unstripped ELFs Only)
Offset Size Type Field Description
0x00 4 u32le sh_name Byte offset into .shstrtab for section name.
0x04 4 u32le sh_type Section type (SHT_PROGBITS=1, SHT_SYMTAB=2, SHT_STRTAB=3, SHT_NOBITS=8, SHT_MIPS_REGINFO=0x70000006).
0x08 4 u32le sh_flags Attribute bitmask (SHF_WRITE=1, SHF_ALLOC=2, SHF_EXECINSTR=4, SHF_MIPS_GPREL=0x10000000).
0x0C 4 u32le sh_addr Virtual address of section in EE RAM (0 if non-allocatable).
0x10 4 u32le sh_offset File offset of section data (unused for SHT_NOBITS).
0x14 4 u32le sh_size Section byte size.
0x18 4 u32le sh_link Associated section index (e.g. .strtab for .symtab).
0x1C 4 u32le sh_info Type-dependent auxiliary info (e.g. first non-local symbol index).
0x20 4 u32le sh_addralign Required virtual alignment (power of 2).
0x24 4 u32le sh_entsize Fixed record size in bytes for table sections (16 for Elf32_Sym), else 0.
Elf32_RegInfo — MIPS Register Info Block (24 / 0x18 bytes, Optional PT_MIPS_REGINFO / .reginfo)
Offset Size Type Field Description
0x00 4 u32le ri_gprmask Bitmask of general-purpose registers referenced by the binary.
0x04 16 u32le[4] ri_cprmask[4] Bitmasks for coprocessors CP0–CP3.
0x14 4 s32le ri_gp_value Initial global pointer ($gp) value for small-data (.sdata/.sbss) addressing.

3. Flags, Enums & Memory Map

ELF Header e_flags Bitfields (GNU MIPS / R5900)

EE ELF32 e_flags Masks and Constants
Mask / Value Symbol Meaning
0x00000001 EF_MIPS_NOREORDER At least one .noreorder directive was used during assembly.
0x00000002 EF_MIPS_PIC Contains position-independent code.
0x00000004 EF_MIPS_CPIC Follows standard MIPS calling conventions for PIC interoperability.
0x0000F000 EF_MIPS_ABI (mask) ABI field: 0x00003000 = E_MIPS_ABI_EABI32, 0x00004000 = E_MIPS_ABI_EABI64 (standard for EE R5900), 0x00001000 = O32.
0x00FF0000 EF_MIPS_MACH (mask) Machine variant: 0x00920000 = E_MIPS_MACH_5900 (Toshiba/Sony R5900 Emotion Engine).
0xF0000000 EF_MIPS_ARCH (mask) ISA level: 0x00000000 = MIPS I, 0x10000000 = MIPS II, 0x20000000 = MIPS III (typical EE setting), 0x30000000 = MIPS IV.

A typical ee-gcc EE executable carries e_flags = 0x20924001, decoded as EF_MIPS_ARCH_3 (0x20000000) | E_MIPS_MACH_5900 (0x00920000) | E_MIPS_ABI_EABI64 (0x00004000) | EF_MIPS_NOREORDER (0x00000001).

Program & Section Flags

  • p_type: 0 = PT_NULL, 1 = PT_LOAD, 4 = PT_NOTE, 6 = PT_PHDR, 0x70000000 = PT_MIPS_REGINFO.
  • p_flags: 0x1 = PF_X (executable), 0x2 = PF_W (writable), 0x4 = PF_R (readable).
  • sh_flags: 0x1 = SHF_WRITE, 0x2 = SHF_ALLOC, 0x4 = SHF_EXECINSTR, 0x10000000 = SHF_MIPS_GPREL ($gp-relative small data).

Emotion Engine Virtual Memory Regions

EE User-Space Virtual Address Layout
Virtual Range Size Description
0x00000000 – 0x000FFFFF 1 MiB EE Kernel / BIOS exception vectors and system state (protected from user PT_LOAD segments).
0x00100000 – 0x01FFFFFF 31 MiB Retail EE User RDRAM (standard load base 0x00100000, extending up to 32 MiB ceiling).

4. Edge Cases & Loader Rules

  • Stripped vs. Unstripped Section Headers: Retail EE executables frequently strip all section headers and symbol tables (e_shoff == 0, e_shnum == 0, e_shstrndx == 0). Sony's EELOAD / LoadExecPS2 loader uses only Elf32_Phdr entries and ignores section headers entirely. Tooling must never require e_shnum > 0 to load or analyze an EE ELF.
  • Non-PT_LOAD Program Headers: Some toolchains emit a PT_MIPS_REGINFO (0x70000000) or PT_NULL program header before or alongside PT_LOAD. Loaders must skip all entries where p_type != 1 rather than mapping them into EE RAM.
  • p_memsz > p_filesz BSS Expansion: When p_memsz > p_filesz, the loader copies p_filesz bytes from p_offset to p_vaddr and zeroes the remaining p_memsz - p_filesz bytes. Reject segments where p_memsz < p_filesz or p_offset + p_filesz > file_size.
  • Kernel Region Guard: User-space executables loaded by EELOAD must not overlap kernel memory below 0x00100000 (or exceed 0x02000000 on retail 32 MiB hardware).
  • Cache Coherency Before Entry: Because the R5900 has separate non-coherent instruction and data caches, LoadExecPS2 writes back the data cache (FlushCache(0)) and invalidates the instruction cache (FlushCache(2)) after copying PT_LOAD segments and before transferring control to e_entry.
  • VU Microcode Sections: In unstripped ELFs, sections such as .vutext or .vudata hold VU0/VU1 microprograms; they reside inside regular PT_LOAD EE RAM segments and are DMA-transferred to VU memory by user code at runtime.

5. Step-by-Step Loader Pseudocode

function load_ee_elf(buf, ee_ram_limit = 0x02000000):
    if len(buf) < 0x34:
        error("File smaller than Elf32_Ehdr")

    # 1. Validate ELF32 little-endian MIPS header
    if buf[0x00..0x04] != b"\x7FELF":
        error("Invalid ELF magic")
    if buf[0x04] != 1 or buf[0x05] != 1 or buf[0x06] != 1:
        error("Expected ELFCLASS32, ELFDATA2LSB, EV_CURRENT")

    e_type      = u16le(buf, 0x10)
    e_machine   = u16le(buf, 0x12)
    e_entry     = u32le(buf, 0x18)
    e_phoff     = u32le(buf, 0x1C)
    e_shoff     = u32le(buf, 0x20)
    e_flags     = u32le(buf, 0x24)
    e_phentsize = u16le(buf, 0x2A)
    e_phnum     = u16le(buf, 0x2C)

    if e_type != 2 or e_machine != 8:
        error("Expected ET_EXEC (2) and EM_MIPS (8)")
    if (e_flags & 0x00FF0000) != 0x00920000:
        warn("EF_MIPS_MACH_5900 (0x00920000) not set in e_flags")
    if e_phnum == 0 or e_phentsize < 0x20:
        error("Missing or invalid program header table")
    if e_phoff + e_phnum * e_phentsize > len(buf):
        error("Program header table out of bounds")

    # 2. Map all PT_LOAD segments into EE memory image
    segments = []
    for i in 0 .. e_phnum - 1:
        off = e_phoff + i * e_phentsize
        p_type   = u32le(buf, off + 0x00)
        p_offset = u32le(buf, off + 0x04)
        p_vaddr  = u32le(buf, off + 0x08)
        p_paddr  = u32le(buf, off + 0x0C)
        p_filesz = u32le(buf, off + 0x10)
        p_memsz  = u32le(buf, off + 0x14)
        p_flags  = u32le(buf, off + 0x18)
        p_align  = u32le(buf, off + 0x1C)

        if p_type != 1:  # skip PT_MIPS_REGINFO, PT_NULL, etc.
            continue
        if p_memsz < p_filesz or p_offset + p_filesz > len(buf):
            error("Invalid PT_LOAD segment bounds")
        if p_vaddr < 0x00100000 or p_vaddr + p_memsz > ee_ram_limit:
            error("Segment outside user EE RAM bounds")

        mem_copy(dst=p_vaddr, src=buf[p_offset .. p_offset + p_filesz])
        if p_memsz > p_filesz:
            mem_zero(dst=p_vaddr + p_filesz, size=p_memsz - p_filesz)
        segments.append({ "vaddr": p_vaddr, "memsz": p_memsz, "flags": p_flags })

    # 3. Flush EE data cache and invalidate instruction cache before jump
    flush_dcache()
    invalidate_icache()
    return { "entry": e_entry, "segments": segments, "stripped": (e_shoff == 0) }

6. Provenance & Confidence

Confirmed Spec SDK-Revision-Dependent

  • Confirmed Spec: ELF32 header, program header, and section header layouts are governed by the System V ELF specification; MIPS e_flags and Elf32_RegInfo constants match GNU binutils MIPS/R5900 definitions; EE user-space virtual memory bounds and LoadExecPS2/EELOAD segment mapping are confirmed across PS2 hardware and SDK binaries.
  • SDK-Revision-Dependent: Specific combinations of EF_MIPS_ARCH_*, E_MIPS_ABI_EABI64, PT_MIPS_REGINFO emission, and segment alignment vary slightly between ee-gcc versions and third-party commercial compilers.

Loader Note: Development executables built for 128 MiB TOOL kits may link debug symbols or heap tables above 0x02000000; parsers targeting retail discs should enforce the 32 MiB boundary while allowing an optional override for development dumps.
