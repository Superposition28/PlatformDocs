PlayStation 2 (PS2) Platform Formats

PLATFORM OVERVIEW · MIPS R5900 EE + MIPS R3000A IOP · LITTLE-ENDIAN

The Sony PlayStation 2 uses a heterogeneous dual-MIPS architecture pairing a 64-bit Emotion Engine (EE) main CPU with a 32-bit I/O Processor (IOP) derived from the original PlayStation CPU. All platform-inherited boot descriptors, executables, relocatable device drivers, firmware update images, and memory card system descriptors operate in little-endian byte order (aside from dual-endian ISO-9660 volume structures).

Primary CPU (EE)
MIPS R5900 (MIPS III/IV subset + 128-bit MMI SIMD), little-endian, 294.912 MHz, 32 MiB RDRAM, 16 KiB Scratchpad
I/O CPU (IOP)
MIPS R3000A (MIPS I), little-endian, 36.864 MHz (33.8688 MHz in PS1 mode), 2 MiB IOP RAM
Inter-Processor Bus
Serial Interface (SIF0 / SIF1 / SIF2 DMA channels, SIFCMD, and SIFRPC)
Media & Storage
CD-ROM (ISO-9660), DVD-5 / DVD-9 (ISO-9660 + UDF 1.02 Bridge), 8 MiB MagicGate Memory Card (MCFS), PS2 HDD

1. Dual-Processor Architecture

Every PS2 runtime environment cleanly separates high-throughput compute and rendering from peripheral I/O:

  • Emotion Engine (EE): Runs user applications compiled as ELFCLASS32 little-endian MIPS binaries (e_machine = 8) tagged with R5900 machine flags and 64-bit register ABI (EABI64) over a 32-bit virtual address space. The EE directly drives Vector Units (VU0/VU1) and the Graphics Synthesizer (GS).
  • I/O Processor (IOP): Manages optical media (CDVDMAN), memory cards (MCMAN), controllers (PADMAN), SPU2 audio, USB, and network/HDD interfaces. IOP drivers are distributed as relocatable .irx modules loaded dynamically into the 2 MiB IOP RAM and linked against resident kernel export tables.
  • ROM & Firmware Images: Boot ROM (rom0:) and disc-resident IOP replacement images (IOPRP*.IMG) package drivers and configuration files in flat 16-byte-aligned ROMDIR containers.

2. CD/DVD Boot & Module Loading Sequence

Cold boot from optical media follows a deterministic pipeline governed by the PS2 Boot ROM (OSDSYS / EELOAD):

  1. Disc Recognition & Mount: The optical drive identifies PS2 CD-ROM (Mode 2 Form 1) or DVD-ROM media and mounts the ISO-9660 filesystem via the IOP cdrom0: device driver.
  2. Boot Descriptor Lookup: OSDSYS opens cdrom0:\SYSTEM.CNF;1 and parses ASCII KEY = VALUE directives (BOOT2, VER, VMODE, and optional HDDUNITPOWER).
  3. EE Executable Load: EELOAD (invoked via LoadExecPS2) reads the ELF32 binary referenced by BOOT2 (typically named after the catalog disc ID, e.g. cdrom0:\SLUS_200.01;1), maps PT_LOAD segments into EE RAM, zeroes p_memsz - p_filesz tails, flushes instruction/data caches, and jumps to e_entry.
  4. IOP Reboot & IRX Loading: Early in initialization, the EE program calls SifIopReset—optionally passing a disc-bundled IOPRP*.IMG ROMDIR image to replace outdated ROM drivers—and then calls SifLoadModule over SIF RPC to relocate and start .irx drivers on the IOP.

4. Platform Boundary

These pages document only Sony PlayStation 2 hardware, boot ROM, IOP/EE kernel, and SDK-mandated formats. Title-specific archives, asset containers, audio banks, and middleware formats are intentionally excluded. Executable specifications cover container headers, ABI flags, relocation formulas, and generalized loader memory mapping without instruction-set emulation.
