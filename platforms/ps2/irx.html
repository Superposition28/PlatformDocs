.irx IOP Relocatable Module

PLAYSTATION 2 · I/O PROCESSOR MODULE Platform-Inherited

An .irx (IOP Relocatable eXecutable) file is a little-endian ELF32 MIPS R3000A module executed by the PlayStation 2 I/O Processor (IOP). Unlike statically linked EE executables, .irx binaries use Sony's processor-specific ELF type 0xFF80 (ET_IOP_EXEC), carry a mandatory SHT_IOPMOD (0x70000080) metadata descriptor, retain SHT_REL relocation tables so MODLOAD can place the module anywhere in 2 MiB IOP RAM, and perform dynamic library linking via 0x41E00000 import/export tables.

1. Identification & Scope

Every .irx begins with a standard 52-byte Elf32_Ehdr configured for little-endian MIPS (EI_CLASS = 1, EI_DATA = 1, e_machine = 8), distinguished from EE executables and standard relocatable .o objects by:

  • e_type = 0xFF80 (ET_IOP_EXEC / ET_SCE_IOPRELEXEC): Processor-specific relocatable IOP module linked at base address 0x00000000 (variant 0xFF81 ET_SCE_IOPRELEXEC2 also exists in later toolchains).
  • e_flags: Targets MIPS I / R3000A (no EF_MIPS_MACH_5900 and no EABI64; typically 0x00000000 or 0x00000001 EF_MIPS_NOREORDER).
  • .iopmod Section / Segment: Identified by SHT_IOPMOD = 0x70000080 (and usually a matching PT_IOPMOD = 0x70000080 program header) storing the irx_info descriptor.

2. Binary Layout Tables

0x04 2 u16le version Module version in BCD (high byte major, low byte minor).

Offset Size Type Field Description
0x00 4 u32le r_offset Byte offset (relative to module/section base) of the 32-bit word to patch.
0x04 4 u32le r_info Packed symbol index (r_info >> 8) and relocation type (r_info & 0xFF).
IOP Library Export & Import Table Headers (Embedded in .text, 20 / 0x14 bytes + entries)
Offset Size Type Field Description
0x00 4 u32le magic Constant 0x41E00000 marker identifying an IOP export or import header.
0x04 4 u32le next Runtime linked-list pointer used by LOADCORE (0x00000000 on disk).
0x08 2 u16le version Library BCD version (exported version or minimum required import version).
0x0A 2 u16le flags Library flags (typically 0 on disk; runtime flags set by LOADCORE).
0x0C 8 char[8] name 8-byte ASCII library identifier, NUL-padded (e.g. "sysmem\0\0", "loadcore").
0x14 Variable u32le[] / Stub[] entries For exports: array of u32le function pointers terminated by 0x00000000. For imports: array of 8-byte MIPS call stubs terminated by 8 zero bytes.

3. Flags, Relocations & Import/Export Formulas

MIPS Relocation Types (R_MIPS_*)

Let B be the allocated IOP RAM base address of the module, and *P be the existing 32-bit little-endian word at B + r_offset:

IRX Relocation Codes (r_type = r_info & 0xFF)
Code Name Relocation Formula
0 R_MIPS_NONE No operation.
2 R_MIPS_32 Direct 32-bit pointer: *P = *P + B.
4 R_MIPS_26 26-bit jump target (j / jal): A = (*P & 0x03FFFFFF) << 2; *P = (*P & 0xFC000000) | (((A + B) >> 2) & 0x03FFFFFF).
5 R_MIPS_HI16 Upper 16 bits (lui): queued until paired with the following R_MIPS_LO16; uses signed LO16 carry adjustment.
6 R_MIPS_LO16 Lower 16 bits (addiu / lw / sw): combined with all queued R_MIPS_HI16 entries: V = ((s16)(*HI16 & 0xFFFF) << 16) + (s16)(*LO16 & 0xFFFF) + B; write ((V + 0x8000) >> 16) & 0xFFFF to each HI16 and V & 0xFFFF to LO16.

IOP Import Stub & Export Table Mechanics

  • Import Call Stubs (8 bytes per imported function): On disk, each stub at 0x14 + k * 8 contains:
    • Word +0x00: 0x03E00008 (jr $ra)
    • Word +0x04: 0x24000000 | func_index (addiu $zero, $zero, func_index)
    When LOADCORE resolves the target library's export table, it patches word +0x00 to 0x08000000 | ((export_addr >> 2) & 0x03FFFFFF) (j export_addr) and word +0x04 to 0x00000000 (nop).
  • Export Table Differentiation: Both export and import tables begin with 0x41E00000. At runtime/analysis, import stubs are recognizable by the 0x03E00008 / 0x2400XXXX pattern and sit in .iop.import sections (without R_MIPS_32 relocations on entries), whereas export tables sit in .iop.export with R_MIPS_32 relocations on every non-zero function pointer.

4. Edge Cases & SifLoadModule Rules

  • Mandatory Relocations & Metadata: Stripping SHT_REL or SHT_IOPMOD renders an .irx unloadable on real hardware because every module is linked at base 0x00000000 and cannot execute without runtime relocation by MODLOAD.
  • Multiple R_MIPS_HI16 Before One R_MIPS_LO16: Optimizing MIPS compilers emit multiple lui instructions sharing one lower-half addiu/load/store. Relocators must maintain a FIFO/list of pending R_MIPS_HI16 locations and resolve all of them when the matching R_MIPS_LO16 is encountered.
  • r_offset Base Semantics: In linked ET_IOP_EXEC (0xFF80) files, r_offset is typically module-relative (relative to base 0 of the image, even though the SHT_REL section's sh_info names the target section). Unlinked ET_REL (1) objects before iop-ld use section-relative offsets plus symbol table lookups.
  • Generalized SifLoadModule / MODLOAD Lifecycle:
    1. EE calls SifLoadModule (via SIF RPC LOADFILE server on IOP).
    2. MODLOAD validates e_type == 0xFF80 and reads irx_info from PT_IOPMOD / SHT_IOPMOD.
    3. IOP kernel allocates text_size + data_size + bss_size bytes in IOP RAM at base B, copies PT_LOAD data, and zeroes the bss_size tail.
    4. MODLOAD applies all SHT_REL relocations using base B and flushes IOP instruction/data caches.
    5. LOADCORE resolves .iop.import stubs against registered export tables and registers any exported tables.
    6. MODLOAD invokes B + irx_info.entry with $gp = B + irx_info.gp_value; return value 0 (MODULE_RESIDENT_END) keeps the driver resident, while 1 (MODULE_NO_RESIDENT_END) unloads its memory after initialization.

5. Step-by-Step Relocator Pseudocode

function load_and_relocate_irx(buf, iop_base):
    if len(buf) < 0x34 or buf[0..4] != b"\x7FELF":
        error("Invalid ELF magic")
    if buf[4] != 1 or buf[5] != 1:
        error("Expected ELFCLASS32 little-endian")

    e_type    = u16le(buf, 0x10)
    e_machine = u16le(buf, 0x12)
    e_phoff   = u32le(buf, 0x1C)
    e_shoff   = u32le(buf, 0x20)
    e_phent   = u16le(buf, 0x2A)
    e_phnum   = u16le(buf, 0x2C)
    e_shent   = u16le(buf, 0x2E)
    e_shnum   = u16le(buf, 0x30)

    if e_type not in (0xFF80, 0xFF81) or e_machine != 8:
        error("Not a PS2 IOP IRX executable")
    if e_shoff == 0 or e_shnum == 0:
        error("Stripped IRX missing section headers")

    # 1. Locate SHT_IOPMOD (0x70000080) and SHT_REL (9) sections
    iopmod = null
    rel_sections = []
    for i in 0 .. e_shnum - 1:
        sh = e_shoff + i * e_shent
        sh_type   = u32le(buf, sh + 0x04)
        sh_offset = u32le(buf, sh + 0x10)
        sh_size   = u32le(buf, sh + 0x14)
        if sh_type == 0x70000080:
            iopmod = {
                "moduleinfo": u32le(buf, sh_offset + 0x00),
                "entry":      u32le(buf, sh_offset + 0x04),
                "gp_value":   u32le(buf, sh_offset + 0x08),
                "text_size":  u32le(buf, sh_offset + 0x0C),
                "data_size":  u32le(buf, sh_offset + 0x10),
                "bss_size":   u32le(buf, sh_offset + 0x14),
                "version":    u16le(buf, sh_offset + 0x18),
                "name":       read_cstr(buf, sh_offset + 0x1A, sh_size - 0x1A)
            }
        elif sh_type == 9:  # SHT_REL
            rel_sections.append((sh_offset, sh_size))

    if iopmod is null:
        error("Missing SHT_IOPMOD metadata")

    # 2. Allocate and map PT_LOAD segments into IOP RAM image
    total_mem = iopmod.text_size + iopmod.data_size + iopmod.bss_size
    image = bytearray(total_mem)  # zero-initialized (covers .bss)
    for i in 0 .. e_phnum - 1:
        ph = e_phoff + i * e_phent
        if u32le(buf, ph + 0x00) == 1:  # PT_LOAD
            p_offset = u32le(buf, ph + 0x04)
            p_vaddr  = u32le(buf, ph + 0x08)
            p_filesz = u32le(buf, ph + 0x10)
            image[p_vaddr .. p_vaddr + p_filesz] = buf[p_offset .. p_offset + p_filesz]

    # 3. Apply SHT_REL relocations relative to iop_base
    pending_hi16 = []
    for (rel_off, rel_sz) in rel_sections:
        for pos in range(rel_off, rel_off + rel_sz, 8):
            r_offset = u32le(buf, pos + 0x00)
            r_info   = u32le(buf, pos + 0x04)
            r_type   = r_info & 0xFF
            word     = u32le(image, r_offset)

            if r_type == 0:    # R_MIPS_NONE
                continue
            elif r_type == 2:  # R_MIPS_32
                write_u32le(image, r_offset, (word + iop_base) & 0xFFFFFFFF)
            elif r_type == 4:  # R_MIPS_26
                target = (((word & 0x03FFFFFF) << 2) + iop_base) >> 2
                write_u32le(image, r_offset, (word & 0xFC000000) | (target & 0x03FFFFFF))
            elif r_type == 5:  # R_MIPS_HI16
                pending_hi16.append(r_offset)
            elif r_type == 6:  # R_MIPS_LO16
                lo_addend = sign_extend_16(word & 0xFFFF)
                for hi_off in pending_hi16:
                    hi_word = u32le(image, hi_off)
                    hi_val  = sign_extend_16(hi_word & 0xFFFF) << 16
                    full    = hi_val + lo_addend + iop_base
                    new_hi  = ((full + 0x8000) >> 16) & 0xFFFF
                    write_u32le(image, hi_off, (hi_word & 0xFFFF0000) | new_hi)
                pending_hi16.clear()
                new_lo = (lo_addend + iop_base) & 0xFFFF
                write_u32le(image, r_offset, (word & 0xFFFF0000) | new_lo)

    return { "iopmod": iopmod, "image": image, "entry": iop_base + iopmod.entry }

6. Provenance & Confidence

Confirmed Spec SDK-Revision-Dependent

  • Confirmed Spec: ELF32 MIPS layout, e_type = 0xFF80, SHT_IOPMOD = 0x70000080, irx_info offsets, R_MIPS_32/26/HI16/LO16 arithmetic, and 0x41E00000 import/export stub structures are confirmed across official PS2 BIOS modules and open-source PS2SDK tools.
  • SDK-Revision-Dependent: ET_SCE_IOPRELEXEC2 (0xFF81) and moduleinfo = 0xFFFFFFFF occur in specific linker/SDK generations; some modules include additional .iopmod alignment padding or multiple PT_LOAD segments.

Relocation Note: Do not conflate standard MIPS ET_REL (e_type = 1) object files with linked ET_IOP_EXEC (0xFF80) .irx files; unlinked objects require symbol table (SHT_SYMTAB) resolution, whereas linked .irx relocations resolve directly against the module load base.
