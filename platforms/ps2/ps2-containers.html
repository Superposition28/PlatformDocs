Sony SDK System Formats: IOPRP ROMDIR & ICON.SYS

PLAYSTATION 2 · BIOS/IOPRP ARCHIVE & MEMORY CARD DESCRIPTOR Platform-Inherited

This specification documents two foundational Sony PlayStation 2 system formats: (1) the IOPRP ROMDIR Image (IOPRP*.IMG / rom0:), a flat 16-byte-aligned firmware archive used to update or replace IOP BIOS modules via SifIopReset, and (2) Memory Card ICON.SYS (PS2D), the fixed 964-byte save directory descriptor read by the PS2 OSDSYS Memory Card Browser to render save titles, gradient backgrounds, 3-light setups, and 3D .icn animations.

IOPRP*.IMG (e.g. IOPRP255.IMG, IOPRP300.IMG); icon.sys (lowercase inside mc0:/<SAVE_DIR>/)

Role/MIME

1. Identification & Scope

  • IOPRP ROMDIR Image (IOPRP*.IMG): Shipped on PS2 optical discs so applications can reboot the IOP with newer Sony SDK .irx drivers (such as updated CDVDMAN, MCMAN, PADMAN, and IOPBTCONF) than those burned into console mask ROM (rom0:). The container stores files sequentially in exact directory order with no explicit offset field.
  • Memory Card icon.sys (PS2D): Stored inside every PS2 save folder on an 8 MiB MagicGate Memory Card (mc0:/<DIR>/icon.sys). It defines the two-line Shift-JIS title, four-corner background gradient, three directional lights, ambient color, and filenames of the associated 3D .icn geometry files for idle, copy, and delete states.

2. Binary Layout Tables

ROMDIR Entry Record (16 bytes per entry, NUL-terminated table)
Offset Size Type Field Description
0x00 10 char[10] name ASCII filename, NUL-padded (max 10 chars; entry 0 is always "RESET\0\0\0\0\0", entry 1 is "ROMDIR\0\0\0\0", optional entry 2 is "EXTINFO\0\0\0"). Terminated by all-zero 16-byte entry (name[0] == 0).
0x0A 2 u16le extinfo_size Total byte length of this entry's metadata records inside the EXTINFO file (0 if none).
0x0C 4 u32le size Exact unaligned payload byte length of this file.
EXTINFO Sub-Record Header (4 bytes + ext_len payload bytes)
Offset Size Type Field Description
0x00 2 u16le value Tag-specific scalar (for type == 2, holds BCD module version).
0x02 1 u8 ext_len Payload byte length following this 4-byte header (4-byte aligned, e.g. 0 or 4+).
0x03 1 u8 type Metadata tag: 1 = BCD Date (YYYYMMDD u32le), 2 = Version, 3 = ASCII Comment, 0x7F = Null/Marker.
0x04 ext_len u8[] data Optional payload bytes (present when ext_len > 0).
Memory Card ICON.SYS Binary Layout (Fixed 964 / 0x3C4 bytes)
Offset Size Type Field Description
0x000 4 char[4] magic Constant ASCII signature "PS2D" (50 53 32 44).
0x004 2 u16le reserved1 Reserved / flags (normally 0x0000).
0x006 2 u16le nl_offset Byte offset within title (0x0C0) where line 2 begins (even Shift-JIS boundary).
0x008 4 u32le reserved2 Reserved (normally 0x00000000).
0x00C 4 u32le bg_alpha Background opacity: 0 (transparent) to 128 (0x80, fully opaque).
0x010 16 u32le[4] bg_col_tl Top-left background color (R, G, B, A), channels in 0x00..0x80.
0x020 16 u32le[4] bg_col_tr Top-right background color (R, G, B, A).
0x030 16 u32le[4] bg_col_bl Bottom-left background color (R, G, B, A).
0x040 16 u32le[4] bg_col_br Bottom-right background color (R, G, B, A).
0x050 48 f32le[3][4] light_dir[0..2] Three 4-component directional light vectors (X, Y, Z, W).
0x080 48 f32le[3][4] light_col[0..2] Three directional light RGB colors (R, G, B, 0.0) in 0.0–1.0.
0x0B0 16 f32le[4] ambient_col Ambient scene color (R, G, B, 0.0) in 0.0–1.0.
0x0C0 68 u8[68] title NUL-terminated Shift-JIS save title string (split across 2 lines at nl_offset).
0x104 64 char[64] icon_list_name NUL-terminated ASCII filename of normal/idle 3D icon (e.g. icon.icn).
0x144 64 char[64] icon_copy_name NUL-terminated ASCII filename of copy-operation 3D icon.
0x184 64 char[64] icon_delete_name NUL-terminated ASCII filename of delete-operation 3D icon.
0x1C4 512 u8[512] reserved Zero-filled reserved padding up to 0x3C4 (964 bytes).

3. Alignment, Offset & Encoding Formulas

ROMDIR Fixed-Order Offset Derivation

RomDirEntry records contain no file offset field. All payloads are laid out sequentially from byte 0x00000000 in exact directory order, each rounded up to a 16-byte boundary:

  • offset[0] = 0 (always RESET; in IOPRP*.IMG, RESET.size is commonly 0, placing ROMDIR directly at offset 0x00000000).
  • offset[i + 1] = offset[i] + ((entry[i].size + 15) & ~15).
  • entry[1] is always ROMDIR itself, and entry[1].size equals (num_entries + 1) * 16 (including the 16-byte zero terminator).
  • When EXTINFO is present (entry[2]), its total byte size equals sum(entry[i].extinfo_size) across all non-terminator entries, sliced sequentially in entry order.

ICON.SYS Shift-JIS Title & Color Scaling

  • Two-Line Shift-JIS Title: title[0 .. nl_offset) forms Line 1 and title[nl_offset .. NUL) forms Line 2. Both slices are encoded in Shift-JIS (code page 932), typically using full-width 2-byte characters, so nl_offset must align to a character boundary (or 0 / length of string when single-line).
  • Background Color Range: Unlike f32le light colors (0.0–1.0), bg_alpha and bg_col_* integer channels use GS fixed-point intensity 0x00..0x80 (128 = 100% / 1.0); convert to 8-bit sRGB via clamp(round(val * 255 / 128), 0, 255).

4. Edge Cases & Loader Rules

  • Locating ROMDIR When RESET.size > 0: Full console BIOS dumps store boot executable code inside RESET before ROMDIR. Scanners locate ROMDIR by probing every 16-byte boundary for "RESET\0\0\0\0\0" followed at +0x10 by "ROMDIR\0\0\0\0", and verifying ((entry[0].size + 15) & ~15) == romdir_offset.
  • IOPRP*.IMG RESET.size == 0: Disc-bundled IOPRP images omit bootstrap code, setting RESET.size = 0 so "RESET\0\0\0\0\0" sits at file offset 0x00.
  • EXTINFO Alignment & Presence: Minimal ROMDIR images can omit EXTINFO when all extinfo_size == 0. When present, every sub-record's ext_len is padded to a 4-byte multiple so sequential parsing never misaligns.
  • Case-Sensitive icon.sys & Filename Reuse: PS2 Memory Card Filesystem (MCFS) paths are case-sensitive; Sony system requirements mandate lowercase icon.sys. All three icon filename fields (icon_list_name, icon_copy_name, icon_delete_name) frequently point to the same .icn file to conserve 8 MiB card space.
  • ICON.SYS Exact Size Check: Conformant icon.sys files are always exactly 964 bytes (0x3C4); parsers should reject truncated files shorter than 0x1C4 bytes even if reserved trailing bytes are omitted in non-standard dumps.

5. Step-by-Step Parser Pseudocode

function parse_romdir_image(buf):
    # 1. Locate ROMDIR table on 16-byte boundaries
    romdir_off = -1
    for off in range(0, len(buf) - 32, 16):
        if buf[off .. off + 10] == b"RESET\x00\x00\x00\x00\x00" and \
           buf[off + 16 .. off + 26] == b"ROMDIR\x00\x00\x00\x00":
            reset_size = u32le(buf, off + 0x0C)
            if ((reset_size + 15) & ~15) == off:
                romdir_off = off
                break
    if romdir_off < 0:
        error("Valid ROMDIR header not found")

    # 2. Read 16-byte entries until null terminator and compute offsets
    entries = []
    cur_data_off = 0
    extinfo_cursor = 0
    pos = romdir_off
    while pos + 16 <= len(buf):
        raw_name = buf[pos .. pos + 10]
        if raw_name[0] == 0:
            break
        name         = raw_name.rstrip(b"\x00").decode("ascii")
        extinfo_size = u16le(buf, pos + 0x0A)
        file_size    = u32le(buf, pos + 0x0C)
        if cur_data_off + file_size > len(buf):
            error("ROMDIR entry out of bounds: " + name)
        entries.append({
            "name": name,
            "offset": cur_data_off,
            "size": file_size,
            "extinfo_offset": extinfo_cursor,
            "extinfo_size": extinfo_size
        })
        cur_data_off += (file_size + 15) & ~15
        extinfo_cursor += extinfo_size
        pos += 16

    return entries

function parse_icon_sys(buf):
    if len(buf) < 0x1C4 or buf[0..4] != b"PS2D":
        error("Invalid ICON.SYS header (expected PS2D)")

    nl_offset = u16le(buf, 0x06)
    bg_alpha  = u32le(buf, 0x0C)
    raw_title = buf[0x0C0 .. 0x104].split(b"\x00", 1)[0]
    split_at  = min(nl_offset, len(raw_title))
    line1     = raw_title[0 .. split_at].decode("shift_jis")
    line2     = raw_title[split_at ..].decode("shift_jis")

    return {
        "title_line1": line1,
        "title_line2": line2,
        "bg_alpha": bg_alpha,
        "bg_colors": [ [u32le(buf, 0x10 + c*16 + k*4) for k in 0..3] for c in 0..3 ],
        "light_dirs": [ [f32le(buf, 0x50 + l*16 + k*4) for k in 0..3] for l in 0..2 ],
        "light_cols": [ [f32le(buf, 0x80 + l*16 + k*4) for k in 0..3] for l in 0..2 ],
        "ambient":    [f32le(buf, 0xB0 + k*4) for k in 0..3],
        "icon_list":   read_cstr(buf, 0x104, 64),
        "icon_copy":   read_cstr(buf, 0x144, 64),
        "icon_delete": read_cstr(buf, 0x184, 64)
    }

6. Provenance & Confidence

Confirmed Spec Unverified / Reserved

  • Confirmed Spec: ROMDIR 16-byte entry layout, 16-byte alignment offset rules, PS2D 964-byte ICON.SYS field offsets, 0x00..0x80 GS background color scaling, Shift-JIS encoding, and nl_offset splitting are verified across retail PS2 BIOS ROMs, IOPRP*.IMG images, and OSDSYS behavior.
  • Unverified / Reserved: ICON.SYS offsets 0x004 (reserved1), 0x008 (reserved2), and 0x1C4..0x3C3 (512-byte tail) are zero in standard saves; certain EXTINFO tag values beyond Date (1), Version (2), Comment (3), and 0x7F are sparsely documented across SDK versions.

Shift-JIS Boundary Caution: Malformed save tools occasionally set nl_offset in the middle of a 2-byte Shift-JIS character or past the NUL terminator; decoders should clamp nl_offset to the NUL-terminated byte length and handle incomplete multibyte sequences gracefully.
